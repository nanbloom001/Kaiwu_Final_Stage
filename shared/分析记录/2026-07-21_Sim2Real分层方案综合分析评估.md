# Sim2Real 分层方案综合分析评估

> 评估日期：2026-07-21
> 代码基线：`main@c8826d9` 及截至该提交可读取的远程归档 Tag
> 评估对象：复赛 Standard 10288、现有 Track/LBC/D2 路线、Jetson 部署链路与最终高低层单模型方案

## 1. 结论摘要

推荐把最终系统设计为一个模型文件中的两个子网络：

```text
深度图 + 机器人坐标系 Goal + 导航记忆
                    │
                    ▼
        高层导航策略 π_nav（5～10 Hz）
                    │
          有界速度指令 vx / vy / wz
                    │
                    ▼
深度图 + proprio45（其中 [6:9] 为速度指令）+ 运控记忆
                    │
                    ▼
        低层视觉运控 π_loco（50 Hz）
                    │
                    ▼
                12 维关节动作
```

两个子网络最终打包到同一个 checkpoint 和同一个 ONNX 图中。真机外围 C++ 只负责传感器适配、UWB 滤波、时间戳与异常处理、速度/动作安全限制以及到点停车，不承担主要的深度避障或迷宫规划。这样既能保留模块化训练的工程优势，也比“真机额外运行一套导航器”更接近仿真与真机使用同一模型的要求。

复赛 Standard 的 `model.ckpt-10288.pkl` 值得复用，但不能直接作为现有视觉 LBC 的教师：

- 它是一个扁平 MLP，Actor 输入为 `proprio45 + height_scan256 = 301`，直接输出 12 维关节动作；
- 它没有独立地形编码器，也没有 `latent32`；
- 现有 LBC 要求教师 checkpoint 中存在可拆分的 `encoder.*` 和 `actor.*`；
- 因此必须先把 10288 的行为蒸馏到 `height_scan256 → latent32` 的 `ActorCriticEncoder`，再以这个新策略作为视觉蒸馏教师。

推荐训练主线为：

```text
复赛扁平 Standard 10288
    │ 行为蒸馏：动作监督
    ▼
带 latent32 的特权 Standard 运控
    │ PPO 恢复和速度覆盖训练
    ▼
成熟的特权低层教师
    │ D2 视觉蒸馏：latent + action + DAgger + TBPTT
    ▼
深度相机低层学生
    │ 视觉 PPO 后训练
    ▼
可独立运行的视觉低层运控
    │ 冻结低层，训练高层导航
    ▼
高层导航 + 低层运控的单模型
```

这一路线不是要求教师永久存在。教师只在前期提供监督和训练期特权信息；视觉学生完成蒸馏和 PPO 后训练后，可以脱离教师独立部署和继续训练。

## 2. 证据等级

本文用四种标签区分结论性质：

- **已确认事实**：可由当前代码、配置、checkpoint 结构或规则镜像直接验证。
- **代码推断**：由多处实现组合推断出的运行行为，仍应通过最小实验确认。
- **建议方案**：为完成比赛任务提出的设计，不代表仓库已经实现。
- **待确认规则**：本地规则未给出足够明确结论，需要向主办方书面确认。

## 3. 当前系统的真实结构

### 3.1 复赛 Standard 10288

**已确认事实：** [`archive/代码存档/复赛_standard`](../../archive/代码存档/复赛_standard/) 中的策略不是“地形理解器 + Actor”的模块化结构，而是一个扁平的 `ActorCritic`：

```text
Actor:
  proprio45 + height_scan256 = 301
  301 → 512 → 256 → 128 → action12

Critic:
  critic_proprio60 + height_scan256 = 316
  316 → 512 → 256 → 128 → value1
```

相关证据：

- [`agent_ppo/conf/conf.py`](../../archive/代码存档/复赛_standard/agent_ppo/conf/conf.py) 定义 `num_scan=256`、`model_class="ActorCritic"`；
- [`policy_observation_process.py`](../../archive/代码存档/复赛_standard/agent_ppo/feature/policy_observation_process.py) 明确观测为 `proprio45 + height_scan256`；
- [`actor_critic.py`](../../archive/代码存档/复赛_standard/agent_ppo/model/actor_critic.py) 是直接消费 301 维观测的 MLP；
- [`model.ckpt-10288.pkl`](../../archive/代码存档/复赛_standard/ckpt/model.ckpt-10288.pkl) 的首层权重与 301 维 Actor 输入一致，未发现独立 latent 参数。

这解释了为什么复赛代码中看不到 `latent32`：复赛模型并未显式构建 32 维地形表征，地形特征隐含在整个 MLP 的中间激活中。

### 3.2 当前主线的特权运控与视觉 LBC

当前 [`LocomotionConfig`](../../server/agent_ppo/conf/conf.py) 使用 `ActorCriticEncoder`，把网络显式拆成：

```text
height_scan256 → DmEncoder → latent32
proprio45 + latent32 = 77 → Actor → action12
```

当前视觉学生 [`VisionEncoder`](../../server/agent_ppo/model/vision_encoder.py) 则使用：

```text
depth[180,320,1] → CNN → visual_feature32
visual_feature32 + proprio45 = 77
→ 2 层 LSTM(hidden64) → latent32
```

因此 `latent32` 不是比赛规则规定的输入，也不是复赛 checkpoint 自带的参数；它是决赛路线为“可替换感知模块”而引入的中间接口。它的价值是让教师和学生共享同一个 Actor：训练时教师从 height scan 生成 latent，部署时学生从深度图生成近似 latent。

### 3.3 当前 D2 蒸馏究竟蒸馏什么

当前 [`algorithm_lbc.py`](../../server/agent_ppo/algorithm/algorithm_lbc.py) 与 [`lbc_workflow.py`](../../server/agent_ppo/workflow/lbc_workflow.py) 的 D2 路线包含三类监督：

1. 教师 latent 与学生 latent 的 Smooth L1 回归；
2. 教师 latent 与学生 latent 的余弦方向一致性；
3. 同一个冻结 Actor 分别消费教师/学生 latent 后，原始动作的 Smooth L1 一致性。

同时使用逐环境 DAgger 驱动比例和 16 帧 TBPTT，使训练后段的状态分布逐步来自学生自身，而不是永远只看教师走出来的理想状态。

**已确认事实：** D2 只优化视觉编码器，教师 encoder 和 Actor 均冻结。它是“视觉表征 + 行为一致性蒸馏”，不是学生 PPO。

**当前缺口：** 仓库没有一个已经接通的“视觉循环策略 PPO 后训练”阶段。也就是说，现有学生完成 D2 后可以独立推理，但还不能直接通过当前工作流脱离教师继续 RL；要实现用户期望的“蒸馏一次，之后在学生上继续 RL”，仍需新增视觉 recurrent PPO 阶段。

### 3.4 当前 Track 与 378413 并非真正的高低层结构

现有 Track 路线仍然让一个 Actor 直接输出 12 维关节动作。Track 的 `goal3` 拼接在 Actor 输入中，形成 `proprio45 + latent32 + goal3 = 80`。当前部署中的 378413 因而是 Actor80，而不是“导航器输出速度、Standard 运控执行速度”的层级策略。

部署侧虽然已经保留 `nav_h/nav_c`、`cmd` 等端口，但目前导航状态主要为透传，`cmd` 也未形成一个实际学习型高层导航闭环。现有接口更像为分层结构预留了外壳，而不是已经完成了高层网络。

## 4. 对关键争议的判断

### 4.1 “教师无法实机上楼，所以必须先修教师”是否成立

需要改写这个命题。

- 教师消费 `height_scan256`，本来就不应直接部署到真机；真机无法提供同语义的特权高度扫描，并不代表教师能力有缺陷。
- 已确认教师在仿真中能够上楼，则它可以为楼梯状态提供有效动作和 latent 监督。
- 真正需要验证的是：教师在足够广的仿真地形、速度和转向分布中是否稳定，而不是它能否直接实机运行。
- 若教师在仿真楼梯、坡地或速度跟踪上失败，才需要先修教师；否则应优先解决视觉学生的感知、闭环状态分布和 Sim2Real 泛化。

因此本项目对教师的准入标准应是“仿真能力和监督质量合格”，而不是“可直接真机部署”。

### 4.2 蒸馏是否只能做一次

蒸馏可以是一个阶段，也可以在后续 RL 中作为逐步退火的正则项：

- 第一次蒸馏解决网络结构变化：10288 扁平 MLP → 带 `latent32` 的特权运控；
- 第二次蒸馏解决传感器变化：height scan → 深度相机；
- 学生视觉策略合格后，可以不再依赖教师进行部署；
- 学生 PPO 初期仍可保留少量教师动作约束，防止突然遗忘上下楼和稳定步态，再逐渐退火到零。

这里做两次蒸馏并非重复绕路：第一次制造一个可拆分的感知接口，第二次才把这个接口从特权传感器迁移到合法传感器。如果直接从扁平 10288 蒸馏到视觉关节策略，也能作为快速对照实验，但会失去当前 LBC 的 latent 接口和教师/学生共享 Actor 的稳定性优势。

### 4.3 还需不需要复赛 Track 教师

不建议把复赛 Track 教师作为新高层导航的主要教师，原因是：

- 它直接输出关节动作，不能为新的高层 `[vx, vy, wz]` 提供天然动作标签；
- 已观察到它对仿真任务过拟合，速度跟踪、转弯、停车和真机稳定性较弱；
- 蒸馏它会把这些缺陷一并复制到学生；
- 其地形门控和部分指令逻辑依赖仿真特权信息，不应进入最终 Actor 观测闭环。

复赛 Track 和 ST7 历史代码仍可复用以下内容：Goal 编码、奖励设计、成功/碰撞/进度指标、UWB 噪声思路、迷宫课程以及 hard-start reset 机制。旧 Track checkpoint 最多作为离线轨迹或对照基线，不作为新架构的根模型。

## 6. 10288 迁移可行性

### 6.1 不可行：直接加载或切片权重

把 10288 的 `512×301` 首层权重切片或补零后加载到 Actor77，并不能得到语义正确的映射：

- 旧网络第一层把 proprio 和每个 scan 单元直接混合；
- 新网络先把 scan 压缩成 latent32，再与 proprio 拼接；
- 两者隐藏单元没有一一对应关系；
- “张量形状能够装入”不等于策略含义被迁移。

因此训练计划必须禁止把 partial-load 成功当作迁移成功，所有关键模型应使用严格结构检查。

### 6.2 可行：行为蒸馏到特权瓶颈模型

当前主线已经存在 [`algorithm_behavior_distill.py`](../../server/agent_ppo/algorithm/algorithm_behavior_distill.py) 和 [`behavior_distill_workflow.py`](../../server/agent_ppo/workflow/behavior_distill_workflow.py)，其设计目的正是：

```text
flat ActorCritic(obs301 → action12)
        ↓ action MSE
ActorCriticEncoder(proprio45 + scan256 → latent32 → action12)
```

但当前入口尚未完整接通：`Config.CURRENT` 没有可选择的 behavior-distill StageConfig，Agent 只分发 PPO/LBC，workflow 又要求 `agent.is_behavior_distill=True`。现有 workflow 也只有全局布尔值 `student_drive`，不具备本文计划的逐阶段或逐环境 DAgger 比例。当前 teacher loader 使用 `strict=False` 并忽略 unexpected keys，保存路径又仅写裸 `state_dict`，缺少结构 schema、checkpoint 格式元数据、optimizer 和严格恢复契约。因此这些文件目前只是可复用的实现骨架，不是可直接启动的训练入口。

历史归档 [`决赛_track蒸馏_162404/agent_ppo/agent.py`](../../archive/代码存档/决赛_track蒸馏_162404/agent_ppo/agent.py) 含有曾经接通过的行为蒸馏分发与 flat teacher 加载蓝图，可用来恢复入口，但应按当前主线接口重写和测试，不能整目录回拷。

### 6.3 必须增加闭环恢复

只在教师状态分布上做 action MSE 容易产生 covariate shift：学生一点误差就会进入教师数据中没出现过的姿态，误差继续放大。因此需要：

1. 教师驱动的监督预热；
2. 逐步增加学生驱动比例；
3. 在学生访问的状态上继续查询教师动作；
4. 蒸馏后使用 PPO 恢复任务回报和速度跟踪。

这也是为什么“训练 loss 很小”不能代替闭环地形成功率验收。

## 7. 总体架构方案比较

### 方案 A：继续单体 Track 端到端关节策略

```text
depth + proprio + goal → joint12
```

优点：单图、路径最短，和当前 378413 接近。
缺点：导航、避障、速度跟踪和落足控制互相耦合；旧 Track 过拟合明显；高层错误会直接变成关节动作；很难单独验证“不会上楼”究竟是视觉、导航还是运控问题。
判断：可保留为现有基线，不应继续作为主方案。

### 方案 B：外围 C++ 导航器 + Standard 视觉运控

```text
C++ 深度避障/迷宫规划/UWB → command3 → visual Standard → joint12
```

优点：低层容易训练，传统导航逻辑易调试，到点停车清晰。
缺点：仿真榜难以复刻同一外围导航闭环；主办方是否允许真机 C++ 承担深度避障和迷宫规划并不明确；“同一模型”可能名义相同但实际决策系统不同。
判断：适合作为低层真机验收工具和应急备选，不作为最终得分主线，除非主办方书面确认并能在仿真评测中运行同等导航器。

### 方案 C：单模型内的高层导航 + 低层视觉运控

```text
π_nav(depth, goal, memory) → command3
π_loco(depth, proprio, command, memory) → joint12
```

优点：低层能力可独立验收；高层输出受低层能力包络约束；仿真和真机可运行同一图；便于把 UWB 适配与学习决策分开；某一层失败时定位清晰。
缺点：需要新增真正的高层训练、双频调度和单图导出；两个视觉编码器会增加算力；必须确认一个提交模型内允许包含两个子网络。
判断：推荐主方案。

### 方案 D：从零开始直接视觉 RL

```text
depth + proprio (+ goal) → RL → joint12 或 command3
```

优点：不受教师 latent 限制，有机会超过教师。
缺点：像素输入样本效率低，早期探索极不稳定，容易先学会保守不动或绕开楼梯；在封闭平台上调试成本高；会放弃 10288 已有运动能力。
判断：作为方案 C 中“视觉 PPO 后训练”的补充，而不是从零取代蒸馏。

## 8. 推荐的模型边界

### 8.1 低层视觉运控

输入：

- D435i 深度图，统一为 `180×320×1`、固定裁剪与归一化；
- `proprio45`，其中 `[6:9]` 由高层给出的 `[vx, vy, wz]` 覆写；
- 低层 LSTM 状态。

输出：12 维关节动作。

职责：

- 平地稳定行走；
- 速度和角速度跟踪；
- 零速停车；
- 上下楼、上下坡；
- 在合法速度包络内保持真机稳定。

低层不接收 UWB Goal，也不额外拼接一份 command。速度指令沿用现有 `proprio45[6:9]` 契约，避免把“要去哪”与“怎样稳定迈步”重新耦合。

### 8.2 高层导航

输入：

- 深度图或独立的轻量深度特征；
- 机器人坐标系 `goal3`；
- 上一时刻 command；
- 高层 GRU/LSTM 状态；
- 必要的少量机体状态摘要。

输出：归一化后再映射到低层已验收包络内的 `[vx, vy, wz]`。

职责：

- 根据 Goal 选择前进、侧移和转向；
- 区分可通行楼梯/坡地与不可穿越障碍；
- 局部绕障；
- 依靠时序记忆走出迷宫；
- 在接近目标时给出减速趋势。

最终硬停车仍由外围带迟滞的安全状态机执行，防止 UWB 抖动导致反复启动。

### 8.3 是否共享视觉编码器

首版不建议强行共享：

- 低层需要台阶边缘、落足和近场几何；
- 高层需要通道、障碍、远场方向和记忆；
- 共享会使高层更新破坏已经验收的低层特征。

优先使用同一深度输入、两个独立轻量编码器。只有 Jetson 延迟或显存不满足时，再做共享 backbone、特征缓存或量化，并以不降低低层安全性为前提。

## 9. Goal 与 UWB 设计判断

### 9.1 继续使用 `goal3`，暂不升级 `goal_v2`

当前 [`goal_features.py`](../../server/agent_ppo/feature/goal_features.py) 的定义是：

```text
local_goal_xy = 世界目标位置转换到机器人机体坐标系，单位 m

goal3 = [
    clip(local_x / 10, -1, 1),
    clip(local_y / 10, -1, 1),
    clip(planar_distance, 0, 20) / 20
]
```

该表示保留左右、前后和距离信息，比只用 `cos(beta), sin(beta)` 更直接；UWB 的三维测距也不意味着导航模型必须使用三维 Goal，比赛任务的路径规划主要发生在地面平面，垂直分量可在传感器标定后投影掉。

不建议首版加入：

```text
[cos(beta), sin(beta), distance, valid, age]
```

原因不是该表示错误，而是 `valid` 与 `age` 更适合先由外围确定性逻辑处理：

- UWB 无效或过旧时保持短时间最后有效值，再降速/停车；
- 异常跳变在进入模型前拒绝；
- 到点停车用迟滞状态机实现；
- 模型只看到语义稳定的相对目标。

这可避免扩展模型输入、重新定义所有 checkpoint，并减少仿真构造完整 UWB 协议和故障状态的工作量。若后续实验证明“仅外部处理仍无法区分短暂丢包与真实静止”，再把 `valid/age` 作为高层网络的版本化输入，而不是预先增加复杂度。

### 9.2 推荐的外围 UWB 流程

```text
Unitree UWB 原始读数
    → 时间戳与字段合法性检查
    → 安装位姿/坐标系标定
    → 转为机器人坐标系 planar (x, y)
    → 中值/异常值拒绝
    → 低通或限速滤波
    → 短时丢失保持；超时进入安全减速/停车
    → GoalEncoder（与仿真同一数学定义）
    → goal3
```

用户实测最高约 5 Hz 且稳定性较差，应作为待测输入条件，而不是未经记录就写死为接口保证。训练时无需伪造完整 UWB 服务协议，只需在 `local_goal_xy` 语义层模拟：5 Hz 左右的采样保持、噪声、偏差、跳变、短时丢失和延迟。仿真与真机分别使用 `SimGoalProvider` 和 `RealUwbProvider`，二者最终都调用同一个 `GoalEncoder`。

### 9.3 S 型走位的主要来源

S 型走位通常不是 Goal 维数本身导致，而是多个闭环延迟叠加：

- 低频 UWB 更新；
- 坐标转换或 yaw 符号错误；
- 每次新测量都突然改变航向目标；
- 高层输出角速度过大；
- 低层并不准确跟踪 `wz`；
- 没有 command slew limit 和转向迟滞。

因此优先顺序应是：先验证坐标和符号，再滤波 Goal，再限制高层 command 变化率，最后才考虑改变网络 Goal 表示。

## 10. 台阶被当作障碍物的分层解决方式

分层后要把问题拆成两个可测试命题：

1. 给低层一个稳定向前速度时，它能否可靠上楼；
2. 高层看见台阶时，是否仍然输出足够的向前速度并保持对准。

若命题 1 失败，问题在低层视觉蒸馏、地形覆盖、相机视角、速度分布或运控奖励；若命题 1 成功而命题 2 失败，才是高层把台阶误判为障碍。

高层训练应同时提供：

- 可通行台阶、坡地的正样本；
- 外观相近但不可穿越的墙体/高障碍负样本；
- 台阶入口对准、登阶中段和出口状态；
- “绕障”与“沿目标方向穿越可通行地形”的奖励平衡；
- 楼梯场景的优先采样和失败重放；
- 深度噪声、遮挡和相机姿态随机化。

不能只靠“碰撞惩罚 + 目标进度奖励”期待模型自动理解楼梯语义。建议记录台阶接近时的高层 command、深度帧、Goal、低层速度误差和失败类型，建立明确的误判数据集。

## 12. Sim2Real 泛化重点

### 12.1 地形分布

低层训练不能只复现仿真榜固定路线，应覆盖：

- 楼梯高度、宽度、深度、边缘圆角和摩擦变化；
- 坡度、坡长、坡面粗糙度；
- 台阶前后平地长度与不同进入角度；
- 混合地形连接处；
- 可通行台阶与不可通行高障碍的近似外观。

基础课程通过后再使用 Opt5B 保守 hard-start，避免模型只会从标准入口姿态开始。

### 12.2 动力学与执行器

至少随机化质量、质心、摩擦、关节增益、动作延迟、控制周期抖动、初始姿态和外部推力。随机化范围必须来自真机测量或逐步扩展，不能为了“更随机”而使用会产生非物理步态的范围。

### 12.3 深度相机

训练和部署必须统一：

- 相机安装外参；
- 投影内参和重映射；
- 裁剪、resize、无效值、量程和归一化；
- 30 Hz 相机到 50 Hz 控制的帧保持语义；
- 空洞、飞点、遮挡、亮面/暗面失效和短时旧帧；
- 相机松动或数据过期时的 fail-safe。

不能用随机噪声代替真实深度日志回放。训练后期应使用真机录制的深度序列做离线推理和分布检查。

## 13. 需要主办方人工确认的规则

在投入高层单图实现前，应获得书面答复：

1. 一个最终模型文件/ONNX 图中包含高层导航和低层运控两个子网络，是否满足“同一个模型”；
2. 仿真评测是否允许模型内部以不同频率更新两个 recurrent 子网络；
3. 真机 C++ 是否允许进行 UWB 坐标转换、滤波、异常值拒绝、短时保持、速度限幅和到点停车；
4. 真机 C++ 是否允许基于深度做主动避障、局部规划或迷宫状态机；若允许，仿真榜如何运行同等逻辑；
5. 除 D435i 与 UWB 外，是否允许使用 Go2 自带雷达/点云；若允许，其数据协议在仿真评测中如何提供；
6. 最终提交对 ONNX 输入输出名、数量、网络结构和 recurrent state 是否有硬性约束。

在第 4、5 项未确认前，不应把外围深度规划或机载雷达高度图作为主路线。即便雷达点云能够投影为局部高度图，它也可能在规则上不可用、在仿真端没有等价输入，并且会重新引入传感器语义差距。

## 14. 最终判断

1. 复赛 Standard 10288 是有价值的运动能力起点，值得复用；
2. 它没有 `latent32`，不能直接成为现有 LBC 教师，必须通过行为蒸馏形成特权瓶颈模型；
3. 教师不需要也不应该直接实机部署，只需在仿真中提供可靠能力和监督；
4. 视觉蒸馏完成后，应新增学生 PPO 后训练，使学生最终脱离教师；
5. 复赛 Track 过拟合且直接输出关节动作，不适合作为新高层的主要教师；
6. 最终推荐单模型内两层：视觉 Standard 运控负责稳定运动，高层导航负责 Goal、避障和迷宫；
7. 首版保留现有机器人坐标系 `goal3`，UWB 有效性、年龄、滤波和停车放在外围处理；
8. 当前归档 Tag 主要复用机制、测试和失败经验，不应默认复用其模型制品；
9. 真正开训前必须先接通 behavior-distill、建立可量化基线，并确认双子网络单模型与外围处理的比赛许可。
