## 1. 这段工作的最终落点

这段工作的主要成果不是“已经训练出最终模型”，而是逐步确认并修通了第一段
迁移链路：

```text
原始复赛 Standard 10288
proprio45 + height_scan256 → flat Actor301 → action12

                ↓ 行为蒸馏 + DAgger

模块化特权学生
height_scan256 → latent32
proprio45 + latent32 → Actor77 → action12
```

当前已经完成：

1. 确认 10288 是 301 维 flat 模型，不自带 `latent32`；
2. 确认必须先完成 301→77 的结构桥接，之后才能复用现有 depth→latent 视觉 LBC；
3. 找到并修复训练无法启动的关键环境/同步问题；
4. 让 minimal bridge 在开悟平台出现持续的 BehaviorDistill iteration/loss 日志；
5. 恢复开悟平台的 `train_global_step` 和模型池保存生命周期；
6. 在可启动 minimal 代码之上设计并实现 R2 自适应 DAgger；
7. 将 checkpoint 统一为可继续扩展视觉模块和高层模块的
   `kaiwu_train_v1`。

当前没有完成：

- R2 在腾讯平台的 6000-iteration 三小时长跑；
- `kaiwu_train_v1` 在平台 PyTorch 环境中的真实保存—恢复 round-trip；
- R2 学生相对 10288 教师的三个固定 seed 闭环评估；
- 上楼、下楼、转向和摔倒视频验收；
- 深度相机视觉蒸馏；
- 可部署 `lbc_loco`/ONNX/Jetson 制品。

因此当前结论是“训练管线和下一轮方案已经准备”，不能写成“R2 模型已经训练
成功”。

## 2. 证据分类

本文使用四类证据：

| 标记 | 含义 |
|---|---|
| Git 事实 | 已进入提交历史，可由 commit 与 diff 复核 |
| 当前实现 | 当前 R2 工作树内容，尚未提交、未推送 |
| 平台观察 | 操作者在开悟页面看到的日志、曲线、评估分数或文件 |
| 待验证 | 代码设计合理，但尚未在开悟真实运行或视频中确认 |

必须避免把“代码已经写好”写成“平台已经跑通”，也不能把“总分接近”代替
上下楼视频和失败原因分析。

## 3. 前置背景：为什么重新从 10288 开始

昨天白天对 D2、D3、D4、D5 的比较暴露出三个问题：

1. D2/D3/D5 的楼梯能力差异明显，尤其学生上楼不稳定；
2. D4 直接关闭教师后效果极差，说明当时的视觉学生还不能无锚点地独立优化；
3. D5 即使继续从 D3 蒸馏，也没有证明学生真正理解上楼状态，而可能只对部分
   教师轨迹做了动作近似。

由此决定不继续在 D3/D4/D5 上叠加补丁，而是重新建立清晰血缘：

```text
10288 flat 教师
→ 模块化 height-scan 特权学生
→ depth 视觉学生
→ 可选学生 RL
→ 高层导航 + 低层运控单模型
```

第一轮只解决 flat301→Actor77，不同时加入深度图、PPO、Goal、UWB 或部署修改。

### 4.3 预训练模型与启动门禁简化

平台最早的症状是日志长期只有：

```text
learner_proxy send sample stat, succ_cnt is 0, error_cnt is 0
```

当时一度把问题集中在：

- 预训练 checkpoint 是否加载；
- 模型 ID 是否应由代码指定；
- SHA/key/shape 门禁是否阻止 rollout；
- `sample succ_cnt=0` 是否等于训练没开始。

处理过程：

1. 明确预训练模型由平台任务页选择；
2. `configure_app.toml` 启用 `/data/pre_model/ckpt`；
3. 操作者负责确认源模型是原始 10288；
4. 保留必要的 key/shape/冻结校验，不再使用额外字节级 SHA 启动门禁；
5. 认识到自定义 BehaviorDistill workflow 直接调用 `env.step` 和优化器，
   `learner_proxy sample succ_cnt` 可以继续为 0。

踩坑结论：

> `sample succ_cnt=0` 不是这个训练流的健康指标。真正应看
> `BehaviorDistill/StandardDAgger iter`、loss、cosine、`train_global_step`
> 和实际 checkpoint 文件。

### 4.6 同步空响应：HTTP 200 不等于文件已经正确落盘

提交：

```text
d2bf115 fix(server): verify sync uploads after empty proxy response
```

同步过程中出现：

```text
failed to upload ... {'ok': True, 'empty_response': True, 'status': 200}
```

旧逻辑无法判断这是：

- 写入成功但代理没有返回 body；
- 写入未完成；
- 连接中断；
- 容器端文件没有落盘。

修复方式：

1. 空响应后调用远端读取接口；
2. 对比本地数据与远端文件 SHA256；
3. 只有 SHA 一致才标记上传成功；
4. 同步范围继续保持四个目录，不做全仓库覆盖；
5. 不删除远端任务范围外文件。

踩坑结论：

> 同步工具必须验证“远端最终状态”，不能把 HTTP 状态码当作文件存在的证明。

### 4.8 开悟 lifecycle 修复

提交：

```text
7d48cba fix(server): restore Kaiwu lifecycle for bridge smoke
```

BehaviorDistill 在自定义 workflow 内直接完成梯度更新，没有走普通 PPO 的
`Agent.learn()`。但开悟框架的：

- `train_global_step`；
- 模型池当前 ID；
- 定时保存调用上下文；

仍依赖平台 lifecycle。

最终保留的做法：

```text
每个 outer iteration：
  workflow 内完成 24 次蒸馏更新
  → 调用一次 agent.learn(None) 作为平台 lifecycle callback
  → 每 100 iterations 调用 agent.save_model()
  → 不手工传模型数字 ID
```

代码中的 `Agent.learn()` 对 behavior distill 是 no-op；它不重复更新参数，作用是
让开悟外层包装看到一次标准学习回调。模型数字 ID 由平台注入，业务代码不再用
`10288 + iteration` 人工计算。

该提交成为 R2 的起点：

```text
codex/standard-bridge-r1-minimal@7d48cba
```

### 4.9 smoke test 的评价边界

平台观察：

- minimal 学生评估总分相比教师只下降约 1 分；
- 使用的是无头评估；
- 尚未取得逐地形视频证据。

这说明学生可能已经迁移了相当部分行为，但不能推出：

- 上楼能力已保留；
- 下楼能力已保留；

- 教师与学生失败类型相同；
- 可以进入视觉蒸馏。

正确结论：

> smoke test 证明结构迁移和学生推理路径可工作；能力验收仍需要同 seed、同地形、
> 分项指标和视频。

### 4.10 R2：在可启动 minimal 上重新加入受控 DAgger

当前分支：

```text
codex/standard-dagger-r2
```

R2 不整体 cherry-pick 复杂 R1，而是在 `7d48cba` 上重新实现：

- 6000 iterations、3 小时任务；
- 0/25/50/75/100% 逐环境学生驱动；
- 前四阶段最少/最多预算；
- 连续两个 50-iteration 质量窗口；
- 正常晋升和 forced 晋升；
- 阶段 entry/best/exit；
- 安全接管；
- 1.0/0.25/0 样本权重；
- 8192 条 FP16 reservoir；
- 75% 当前状态 + 25% 回放；
- 教师冻结与学生非有限检查；
- 统一 `kaiwu_train_v1`；
- 阶段英文文件 + 同 ID `locomotion` 别名。

阶段预算：

| 阶段 | 学生比例 | 最少 | 最多 |
|---|---:|---:|---:|
| `daggerzero` | 0% | 900 | 1500 |
| `daggerquarter` | 25% | 600 | 900 |
| `daggerhalf` | 50% | 600 | 900 |
| `daggerthreequarter` | 75% | 600 | 900 |
| `daggerfull` | 100% | 1800 | 训练至 6000 |

最早在 iteration 2700 进入 full，可训练 3300 iterations；最晚在 4200 进入
full，仍保留 1800 iterations。

当前实现经过多轮独立只读审查，期间发现并修复：

- `daggerfull` 满足质量条件后错误尝试晋升到不存在的第六阶段；
- iteration=0 的异常 checkpoint 可能携带错误 phase 状态；
- replay 恢复后缺少容量/比例合法性校验；
- Standard eval 对新格式可能落入 legacy partial-load；
- 每步全参数有限性扫描开销过大，调整为每 outer iteration 检查一次；
- full 最终状态必须无条件重新保存，确保 `training_status` 和最佳点回退落盘。

这些是本地代码审查结果，不是平台运行结果。

## 5. 本轮主要踩坑清单

### 5.1 把 HJC 指令范围误当成原始教师范围

错误范围：

```text
vx=[0.3,0.6]
vy=[-0.2,0.2]
wz=[-0.5,0.5]
resampling=[2,4]
```

这是 `hjcnew蒸馏1_10288` 的桥接配置，不是原始 10288 的可靠来源。

经重新审计 `archive/代码存档/复赛_standard`：

```text
Config.CURRENT = StairInvFineTuneConfig
实际 TOML = train_env_conf_standard_stair_inv_finetune.toml

vx=[0.3,1.3]
vy=[-0.2,0.2]
wz=[-0.3,0.3]
resampling=[6,10]
```

该 TOML 的 initial ranges、hard limits 和四个 velocity curriculum stages
全部相同。

证据边界：

- `kaiwu.json` 只记录 `train_step=10288`、约三小时训练和模型文件；
- checkpoint 不包含历史命令配置；
- 当前采用的是 `复赛_standard` 归档代码实际选中的入口；
- 不能仅凭 checkpoint 二进制证明历史任务当时一定使用同一份代码。

### 5.2 一次性加入太多安全门禁

完整 R1 同时改训练算法、加载、阶段推进、保存、同步和文档，导致平台不启动时
排查面过大。

改进：

- 先回到 minimal；
- 证明环境、前向、梯度和 lifecycle；
- 再逐项恢复必要保护；
- 只把会污染教师、产生 NaN 或写盘失败的情况作为硬停止；
- 质量阈值用于晋升/警告，不使用未经验证的姿态阈值增加隐藏门禁。

### 5.3 把 `sample succ_cnt=0` 当成训练没有发生

BehaviorDistill 不通过普通 sample pipeline，sample 计数可以保持 0。

以后判断训练状态必须同时看：

- `[StandardDAgger] iter=...`；
- action MSE/cosine；
- optimizer grad；
- `train_global_step`；
- checkpoint 文件；
- 模型 payload 的 `current_iteration`。

### 5.4 训练代码完整，但环境代码缺失

缺少 `isaac_env/base_env.py` 使训练包不完整。以后从历史目录复现时必须按项目
边界比较，而不是只比较 `agent_ppo`。

最低目录清单：

```text
agent_diy/
agent_ppo/
conf/
isaac_env/
train_test.py
kaiwu.json
```

### 5.5 同步成功判断不可靠

HTTP 200 + empty body 不等于远端写入成功。必须回读 SHA。同步脚本也不是
“自动删除远端旧文件”的镜像工具，容器残留文件需要单独审计。

### 5.6 混淆三套保存频率

曾混淆：

1. `configure_app.toml` 的框架 `dump_model_freq`；
2. StageConfig 的 `model_save_interval`；
3. 自定义 workflow 的 `save_interval`。

R2 的可控保存依据是：

```text
[standard_ref_distill]
save_interval = 100

workflow:
if current_iteration % save_interval == 0:
    agent.save_model()
```

框架参数不能自动替代自定义 workflow 的保存调用。

### 5.7 人工计算平台模型 ID

旧 R1 曾设计：

```text
platform_id = 10288 + current_iteration
```

这会把平台模型池 ID、父 checkpoint ID 和业务 iteration 混为一谈。

R2 改为：

- `agent.save_model()` 不传数字 ID；
- 使用开悟框架注入的 ID；
- iteration 只保存在 payload；
- 文件阶段标签只用小写英文。

### 5.8 阶段标签中使用数字

平台探活正则的阶段部分只接受 `[a-z]*`。因此不使用：

```text
dagger25
dagger-25
```

而使用：

```text
daggerzero
daggerquarter
daggerhalf
daggerthreequarter
daggerfull
```

### 5.9 模型格式与部署格式混淆

训练恢复需要 optimizer、RNG、reservoir、教师和阶段状态；Jetson 只需要部署
推理图。不能让一个文件同时假装完成两种职责。

当前边界：

```text
kaiwu_train_v1  = 训练包，不可部署
lbc_loco        = 视觉策略候选，可进入导出审查
ONNX            = Jetson 推理制品
```

### 5.10 修改代码后直接评估旧模型

开悟评估使用已保存模型包内的代码。修改开发容器中的：

- loader；
- 纯学生评估路径；
- checkpoint 解包；
- 网络结构；
- inference；

不会自动改变旧模型包。必须续训到保存出一个包含新代码的新模型，再评估它。

### 5.11 只看总分，不看楼梯视频

总分接近教师不能证明上楼能力。之后所有阶段放行至少需要：

- `pyramid_stairs` 与 `pyramid_stairs_inv` 分项；
- 三个固定 seed；
- 上楼入口、登阶中段和楼梯出口视频；
- 下楼、转向、停止和摔倒原因；
- teacher/student 同条件对照。

## 6. 当前最终冻结的技术决策

1. 源教师只认原始复赛 Standard 10288，不使用 HJC 10 分钟产物作源教师；
2. R2 从 `minimal@7d48cba` 开始，不从复杂 R1 整体 cherry-pick；
3. R2 仍使用 `height_scan256`，只是新的特权学生，不是视觉模型；
4. 学生网络固定为 `scan256→latent32 + proprio45→Actor77→action12`；
5. 教师全程冻结，optimizer 只含学生 encoder/actor；
6. 指令域按 `复赛_standard` 当前实际入口固定；
