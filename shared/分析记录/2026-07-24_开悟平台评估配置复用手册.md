# 开悟平台评估配置复用手册

> 日期：2026-07-24
> 适用平台版本：腾讯开悟 `V27.0.21`
> 当前验证对象：Standard 深度视觉模型 `model.ckpt-visionfull-28401.pkl`
> 用途：统一后续评估任务配置、测试口径和结果登记方式

## 1. 使用范围

本文用于创建腾讯开悟模型评估任务时复用环境 TOML，重点说明：

- 哪些字段可以在创建评估任务时调整；
- Standard 视觉模型必须保持不变的字段；
- 如何分别测试上楼、下楼、坡面和完整地形组合；
- 如何保证不同 checkpoint 的评估结果可以比较；
- 哪些改动不能通过评估配置完成，必须重新生成模型包。

本文不是训练 TOML 说明。训练参数、网络结构、checkpoint loader 和模型包内部
Python 不属于评估页面的普通覆盖范围。

## 2. 先记住评估配置的作用边界

开悟平台评估使用已经保存的模型包。任务页环境配置只负责覆盖模型包明确读取的
环境参数：

```text
评估任务页 TOML
      ↓
tools/eval/conf/eval_env_conf.toml
      ↓
与 tools/conf/base/eval_env_base.toml 合并
      ↓
模型包内 Config 和 base_env 读取并应用
```

只有同时满足以下两个条件，字段才会真正生效：

1. 平台接受并下发该字段；
2. 当前模型包代码读取并应用该字段。

平台编辑器显示“代码已通过校验”，不等于模型一定使用了该字段。

相关实现：

- `server/agent_ppo/conf/conf.py:272-315`
- `server/agent_ppo/conf/conf.py:348-422`
- `server/isaac_env/base_env.py:2243-2332`

## 3. 当前 Standard 视觉模型的固定合同

评估 `visionfull-28401` 以及同结构后续模型时，以下字段必须保持：

```toml
[env_conf]
task_name = "Unitree-Go2-Velocity-Camera"

[terrain]
mode = "standard"

[camera.depth_camera]
offset_pos = [0.339871, 0.034697, 0.075010]
offset_rot = [0.982631, -0.007085, 0.184337, -0.020153]
```

含义：

- `Unitree-Go2-Velocity-Camera` 创建深度相机场景；
- `mode="standard"` 选择 Standard 地形、评分和视觉 LBC 加载路径；
- 相机外参必须与训练时的 21.22° 标定保持一致。

当前阶段推断只完整支持：

```text
Unitree-Go2-Velocity        + standard → LocomotionConfig
Unitree-Go2-Velocity-Camera + standard → LBCLocoConfig
```

因此不能通过把 `terrain.mode` 改成 `track`，将 Standard 模型变成 Track 模型。

## 4. 推荐的通用评估基线

下面这份配置用于比较不同 Standard 视觉 checkpoint。除非实验明确要求，否则不要
修改相机、地形集合和指令范围。

```toml
[env]
# num_envs <= 16 时平台默认生成 MP4
num_envs = 16
episode_length_s = 20.0

[env_conf]
task_name = "Unitree-Go2-Velocity-Camera"

[terrain]
mode = "standard"
level = [6, 7, 8, 9]

[terrain.standard]
sub_terrains = [
    "pyramid_slope",
    "pyramid_slope_inv",
    "pyramid_stairs",
    "pyramid_stairs_inv",
]

[commands]
[commands.limit]
lin_vel_x = [0.0, 1.0]
lin_vel_y = [0.0, 0.0]
ang_vel_z = [0.0, 0.0]

[camera.depth_camera]
offset_pos = [
    0.339871,
    0.034697,
    0.075010,
]
offset_rot = [
    0.982631,
    -0.007085,
    0.184337,
    -0.020153,
]
```

这份配置形成：

```text
4 个难度 × 4 种地形 = 16 个并行环境
```

适合做 checkpoint 总体横向对比，但不替代单地形视频诊断。

## 5. 后续最常用的可修改字段

| 字段 | 是否建议修改 | 用途 |
|---|---:|---|
| `env.num_envs` | 是 | 控制并行环境数和 MP4；需要视频时保持 `<=16` |
| `env.episode_length_s` | 是 | 调整单局时长；不同模型对比时必须一致 |
| `terrain.level` | 是 | 指定难度 0–9 |
| `terrain.standard.sub_terrains` | 是 | 选择上坡、下坡、上楼或下楼 |
| `commands.limit.lin_vel_x` | 是 | 测试不同前进速度或速度范围 |
| `commands.limit.lin_vel_y` | 谨慎 | 当前主要测试前进运动，默认固定为 0 |
| `commands.limit.ang_vel_z` | 谨慎 | 只在转向能力专项测试时修改 |
| `env_conf.task_name` | 否 | 当前视觉模型必须使用 Camera 任务 |
| `terrain.mode` | 否 | 当前 Standard 模型必须使用 `standard` |
| `camera.offset_pos/offset_rot` | 否 | 普通能力评估必须与训练标定一致 |

## 6. 可直接复制的专项评估配置

以下配方都建立在同一个视觉模型、同一相机外参和 Standard 模式上。

### 6.1 上楼梯

```toml
[env]
num_envs = 4
episode_length_s = 20.0

[env_conf]
task_name = "Unitree-Go2-Velocity-Camera"

[terrain]
mode = "standard"
level = [6, 7, 8, 9]

[terrain.standard]
sub_terrains = ["pyramid_stairs"]

[commands]
[commands.limit]
lin_vel_x = [0.3, 0.3]
lin_vel_y = [0.0, 0.0]
ang_vel_z = [0.0, 0.0]

[camera.depth_camera]
offset_pos = [0.339871, 0.034697, 0.075010]
offset_rot = [0.982631, -0.007085, 0.184337, -0.020153]
```

评估重点：

- 是否主动接近台阶；
- 前腿是否能抬上第一级；
- 登阶过程中是否持续前进；
- 是否在楼梯中段趴倒或横向偏移；
- 到达顶部后是否恢复稳定步态。

### 6.2 下楼梯

将上楼配置中的子地形替换为：

```toml
[terrain.standard]
sub_terrains = ["pyramid_stairs_inv"]
```

评估重点：

- 是否在下沿前过度停顿；
- 前腿落点是否稳定；
- 是否发生连续踏空；
- 是否因俯冲导致机身触地；
- 下楼后是否恢复姿态。

### 6.3 上坡

```toml
[terrain.standard]
sub_terrains = ["pyramid_slope"]
```

评估重点：

- 前进速度是否明显衰减；
- 机身 pitch 是否持续增大；
- 是否在坡中段打滑；
- 坡顶过渡是否稳定。

### 6.4 下坡

```toml
[terrain.standard]
sub_terrains = ["pyramid_slope_inv"]
```

评估重点：

- 是否因速度过快失稳；
- 是否出现前腿支撑不足；
- 是否能在坡底恢复稳定步态。

## 7. 速度跟踪专项配方

不同速度应创建独立评估任务，保持地形、难度、episode 时长和评估局数一致。

推荐固定速度点：

```text
0.0 m/s：停止能力
0.2 m/s：低速稳定性
0.3 m/s：当前保守工作点
0.5 m/s：中速能力
0.8 m/s：较高速能力
1.0 m/s：评估上限
```

例如固定 `0.3 m/s`：

```toml
[commands.limit]
lin_vel_x = [0.3, 0.3]
lin_vel_y = [0.0, 0.0]
ang_vel_z = [0.0, 0.0]
```

使用 `[0.0, 1.0]` 测的是一个随机速度范围，不能代替固定速度点的可控对比。

停止能力测试仍应保留足够 episode 时长，并观察机器人是否真正停止，而不是只看最终
得分。

## 8. 评估任务命名建议

任务名应短、可检索，并包含模型阶段和测试目的：

```text
vis-all-l689
vis-up-l689
vis-down-l689
vis-slope-l689
vis-invslope-l689
vis-v03-up
vis-v05-up
```

同一组对比只改变一个变量。例如：

```text
vis28401-v03-up
vis28401-v05-up
```

不要同时更换模型、速度、地形、难度和 episode 时长，否则无法判断差异来源。

## 10. 公平比较规则

对比两个模型时，以下内容必须一致：

- 评估 TOML；
- 平台实验版本；
- 评估局数；
- 地形和难度；
- 速度指令；
- episode 时长；
- 相机外参；
- 视频开关；
- 结果统计口径。

若只需要确认某项能力，应使用专项评估；若需要判断总体回归，应使用第 4 节通用
基线。最终模型至少同时通过：

1. 通用基线；
2. 上楼专项；
3. 下楼专项；
4. 视频人工检查。

## 11. 当前代码支持但不建议作为普通覆盖项的字段

当前模型包还读取一些未列入平台默认模板的参数。

### 11.1 地形内部参数

代码支持 `num_rows`、`num_cols`、`difficulty_range`、`curriculum`、
`max_init_terrain_level` 以及子地形对象已有参数。

评估配置存在 `terrain.level` 时，代码会重新计算网格并关闭训练期课程升降级，所以
普通评估不应同时设置这些字段。

### 11.2 相机内部参数

代码支持 `max_depth`、焦距、孔径、裁剪范围、分辨率和更新周期。

普通评估不应修改：

- `width/height`：模型固定期待 `180×320×1`；
- `max_depth`：会改变归一化和有效量程；
- `update_period`：会改变视觉时序；
- 焦距、孔径和外参：会改变训练时视觉分布。

这些字段只适合独立的相机敏感性实验。

### 11.3 域随机化和观测噪声

代码支持 `[domain_rand]` 和 `[noise]`，但官方说明评估默认关闭这些训练扰动。
正式能力比较应保持关闭。

### 11.4 原始环境覆盖

`[isaaclab_override]` 和 `[env_cfg_override]` 可以尝试递归设置已有 Isaac Lab 属性，
但未出现在官方评估模板中，不应作为常规评估接口使用。

## 12. 评估任务配置不能覆盖的内容

以下内容固定在模型包中：

- Python 推理代码；
- 网络结构和输入维度；
- checkpoint loader；
- VisionEncoder、LSTM 和 Actor 权重；
- Standard Actor77 与 Track Actor80 的结构差异；
- 评估时是否加载特权 Encoder；
- 深度预处理中新增加的逻辑；
- LSTM reset 语义；
- 动作缩放和关节顺序；
- 将 LBC 路径改成 PPO 或高低层联合推理。

修改这些内容后，必须：

```text
同步新代码
→ 从旧 checkpoint 续训或执行最短有效训练
→ 保存新模型包
→ 使用新模型创建评估任务
```

只同步开发容器，不会改变已经保存的旧模型包。

## 13. 深度消融只作为评估边界示例

当前模型包没有 `constant`、`shuffle` 或 `permute_env` 深度模式，评估任务 TOML
不能直接完成恒定深度或打乱深度测试。

同样：

- 修改相机外参测试的是标定敏感性；
- 修改 `max_depth` 测试的是量程和归一化敏感性；
- 两者都不是“模型是否真正使用视觉”的严格消融。

如果以后需要该能力，应先在模型包代码中实现可配置入口，再保存新模型。该问题只是
评估覆盖边界的一个例子，不是本文的主要用途。
