# Standard 深度视觉蒸馏 10 小时长训计划

> 功能阶段：Standard 深度视觉能力蒸馏
> 建议分支：`codex/depth-vision-distillation`
> 平台任务名：`std-vision-long`（15 个字符）
> 平台任务时长：10 小时
> 状态：方案冻结，尚未修改视觉训练代码
> 父模型：`standard-dag_16288`
> 规范父文件：`model.ckpt-daggerfull-16288.pkl`
> 父文件 SHA256：`5bfd5d7c75162ba82f0e7d9514713747ef5d7c360d336fc50546088f5a3fc67c`

## 1. 本轮训练解决什么问题

上一阶段已经把复赛 Standard 10288 的扁平策略：

```text
proprio45 + height_scan256
    → Flat Actor301
    → action12
```

迁移成带 `latent32` 的模块化特权低层策略：

```text
height_scan256
    → PrivilegedEncoder
    → latent32

proprio45 + latent32
    → Actor77
    → action12
```

上一阶段的最终学生仍然依赖仿真专有的 `height_scan256`，不能直接部署到真机。
本轮唯一目标是用 D435i 深度图替换这条特权输入，得到第一个能够进入
Standard Sim-to-Real 评估的视觉低层策略：

```text
depth[180,320,1] + proprio45 + recurrent_state
    → VisionEncoder(CNN + LSTM)
    → student_latent32

proprio45 + student_latent32
    → frozen Actor77
    → action12
```

本轮不训练 Goal/UWB、不训练高层导航、不处理迷宫、不修改部署 C++，也不进行
无教师约束的视觉 PPO。这里的“学生驱动”仍然属于视觉 DAgger：环境逐步由视觉
学生闭环访问，但每个有效状态继续向冻结教师查询 latent 和 action 标签。

父模型 `standard-dag_16288` 完成了 6000 iterations、约 3 小时训练，最终
`daggerfull` 阶段持续 1800 iterations。最终日志记录：

```text

safety_takeover_rate ≈ 0.002
normalized_action_mse ≈ 0.000939

```

平台评估证据：

- 最终模型三组无头评估平均分约为 `62.62`、`58.84`，均完成上下楼任务；
- 开启视频的评估为 4/4 完成，0 timeout，0 abnormal；
- 视频评估平均分 `64.19`；
- `pyramid_stairs` 平均分 `66.76`；
- `pyramid_stairs_inv` 平均分 `61.63`；
- 人工查看视频后确认基本行走、上楼和下楼表现没有明显异常。

`forced`，并从 `phase_entry` 恢复后再晋升。最终模型能力已经由平台评估支持，
但这套“失败后仍强制升档”的状态机不能直接复制到视觉阶段。


视觉教师只使用：

- `modules.low_level.encoder_state_dict`：`height_scan256 → teacher_latent32`；

## 4. 训练与评估观测契约

### 4.1 训练期

训练环境可以同时提供：

```text
proprio45
height_scan256      # 只给冻结教师
depth[180,320,1]    # 给视觉学生
episode reset mask
```

Teacher：

```text
height_scan256 → teacher_latent32
proprio45 + teacher_latent32 → teacher_action12
```

Student：

```text
depth + proprio45 + recurrent_state → student_latent32
proprio45 + student_latent32 → student_action12
```

### 4.2 评估与部署期

视觉学生评估不得读取 `height_scan256`。推理输入只能包含：

```text
proprio45
depth[180,320,1]
LSTM hidden/cell state
episode reset mask
```

固定 Actor77 仍属于模型的一部分。`height_scan256` 只允许留在训练时的教师
标签链路，不能出现在视觉评估的 observation adapter、ONNX 输入或部署配置中。

## 5. 网络与优化边界

本轮不修改已经验收的低层 Actor77，只训练视觉 Encoder：

```text
depth[180,320,1]
→ CNN
→ visual feature32
→ concat proprio45
→ 2-layer LSTM(hidden64)
→ Linear64→32
→ L2-normalized student_latent32
```

冻结项：

- 特权 `PrivilegedEncoder`；
- 低层 `Actor77`；
- 原始 flat301 教师；
- 任何 Critic、探索标准差和高层模块。

可训练项：

- `VisionEncoder` 的 CNN；
- `VisionEncoder` 的 LSTM；
- `VisionEncoder` 的 latent projection。

首轮建议固定：

```text
num_envs = 128
num_steps_per_env = 24
learning_rate = 2e-4
max_grad_norm = 1.0
depth_shape = [180, 320, 1]
```

历史视觉配置使用 128 个环境；不能把上一阶段只处理 301 维观测时的
`num_envs=1024` 直接搬到深度训练。仅单帧深度在 128 个环境下就约有
737 万个像素，CNN/LSTM activation 和反向图还会额外占用显存。

如果启动后显存持续超过 90%、出现 OOM 或单轮耗时不稳定，终止该次启动并将
环境数降为 64；不能在同一 checkpoint 血缘中静默改变环境数而不记录。

## 6. 损失函数

第一轮固定为：

```text
latent_loss =
    SmoothL1(student_latent32, teacher_latent32)

cosine_loss =
    1 - cosine(student_latent32, teacher_latent32)

action_loss =
    SmoothL1(
        FrozenActor77(proprio45, student_latent32),
        FrozenActor77(proprio45, teacher_latent32)
    )

total_loss =
    0.5 * latent_loss
  + 0.1 * cosine_loss
  + 1.0 * action_loss
```

`action_loss` 的梯度允许穿过冻结 Actor 回传到视觉 Encoder，但 Actor 自身不能
进入 optimizer。

任务开始后的前 20 分钟只用于量级校验，不自动修改权重。必须记录三项原始
loss、加权后贡献和 VisionEncoder 梯度范数。如果任一项出现 NaN/Inf，或者单项
长期占总梯度 95% 以上，则该次任务定义为预检失败，不继续消耗 10 小时。

## 7. 数据域保持不变

为了只验证 `height_scan → depth` 的感知迁移，本轮沿用已确认的原始
`复赛_standard` 当前入口 `StairInvFineTuneConfig` 训练域：

```text
vx = [0.3, 1.3]
vy = [-0.2, 0.2]
wz = [-0.3, 0.3]
command resampling = [6, 10] s
```

地形比例：

```text
pyramid_slope       = 20%
pyramid_slope_inv   = 20%
pyramid_stairs      = 20%
pyramid_stairs_inv  = 40%
maze                = 0%
```

本轮不扩展零速、低速、倒退和更大转向范围；也不同时修改奖励。速度跟随能力和
零速停车将在视觉基线通过后作为独立的受约束 RL/微调目标。

本轮先关闭：

- 动力学随机化；
- 外力推动；
- proprio 噪声；
- 大幅相机外参扰动；
- 强深度 dropout、大片遮挡和旧帧模拟。

允许保留与训练相机渲染本身一致的确定性裁剪、尺寸变换、无效值处理和归一化。
Sim-to-Real 深度增强在本轮视觉基线通过后单独加入，避免把“视觉没有学会”和
“增强过强”混成一个问题。

## 8. 单次 10 小时的阶段调度

平台任务时长在任务页设置为 10 小时。业务代码不使用人工计算的模型 ID，也
不把某个固定 iteration 当成平台任务时长。内部最大 iteration 只作为远高于
10 小时可达量的保险上限；实际升档依据为有效训练时长和质量窗口。

| 时间区间 | 标签 | 请求学生驱动 | 最短目标 | 主要目的 |
|---|---|---:|---:|---|
| 00:00–00:20 | `visionteacher` | 0% | 20 分钟 | 启动、加载、loss/显存/相机检查 |
| 00:20–02:20 | `visionteacher` | 0% | 2 小时 | 在干净教师轨迹上建立视觉 latent/action 对齐 |
| 02:20–03:00 | `visioncanary` | 10% | 40 分钟 | 小比例闭环探测视觉学生是否制造异常状态 |
| 03:00–04:00 | `visionquarter` | 25% | 1 小时 | 开始覆盖学生访问状态 |
| 04:00–05:15 | `visionhalf` | 50% | 1 小时 15 分 | 形成稳定混合闭环 |
| 05:15–06:30 | `visionthreequarter` | 75% | 1 小时 15 分 | 检查高学生占比的楼梯稳定性 |
| 06:30–09:30 | `visionfull` | 100% | 3 小时 | 纯视觉闭环收敛和防遗忘训练 |
| 09:30–10:00 | `visionfull` | 100% | 30 分钟 | 最终窗口、checkpoint 和退出缓冲 |

时间表表示“最早可进入下一阶段”的目标，不表示到点强制晋升。上一阶段提前通过
时，节省时间全部转给 `visionfull`；上一阶段未通过时，继续停留在当前比例，
不得恢复入口后强制升档。

如果任一阶段达到其计划最晚时间仍未通过：

1. 保存当前阶段最佳有效 checkpoint；
2. 标记 `training_status="blocked"`；
3. 停止提高学生比例；
4. 剩余时间用于维持当前比例、收集失败诊断；
5. 任务结束后从失败阶段修复，不能把未到 `visionfull` 的产物描述成完整视觉模型。

## 9. 晋升条件

每 50 iterations 形成一个窗口，连续两个窗口同时满足才允许晋升：

```text
teacher_parameter_diff == 0
student_nonfinite_rate == 0
valid_teacher_ood_rate == 0
latent_cosine >= 0.95
normalized_latent_mse <= 0.10
action_cosine >= 0.98
normalized_action_mse <= 0.05
safety_takeover_rate <= 0.10
hard_termination_rate 相对上一阶段增加 <= 0.01
effective_student_ratio >= requested_student_ratio - 0.05
```

其中 `teacher_ood` 只在非 reset、观测有效的帧上计算；episode reset 期间的零
命令不得被误判为教师 OOD。这一点用于避免上一阶段“可见指标很好但一直不能
正常晋升”的假阻断。

在线 loss 只决定是否继续升档，不替代固定 seed 的平台能力评估。

## 10. 防污染措施

### 10.1 动作安全接管

在 `visionteacher` 阶段结束时，用有效样本固定：

```text
safety_threshold = max(0.25, 2 × P95(student_action - teacher_action 的 L2))
```

仅在以下情况由教师临时接管该环境：

- 学生 action 含 NaN/Inf；
- 学生与教师 action 的 L2 超过固定阈值。

必须同时记录：

```text
requested_student_ratio
effective_student_ratio
safety_takeover_rate
```

请求 100% 不等于实际 100%；最终有效学生比例低于 95% 时不能通过。

### 10.2 样本权重

```text
1.0：正常、域内、未硬终止样本
0.25：发生安全接管但状态仍可恢复
0：非有限值、reset 错位、有效命令域外、硬终止后的无效帧
```

正常的学生偏离状态不能过滤，因为它们正是视觉 DAgger 需要覆盖的数据。

### 10.3 有界回放

深度帧远大于 301 维观测，不能复制上一阶段的 8192 条全量 reservoir。首轮使用：

```text
capacity = 2048 frames
storage = CPU FP16 preprocessed depth
current/replay loss = 75% / 25%
```

同时保存对应的 proprio、reset mask、teacher latent 和 teacher action。回放只
接收权重 1.0 的有效样本。checkpoint 写盘前记录实际字节数；若单个 checkpoint
明显超过平台允许范围，则只保存可恢复的近期分层样本索引，不静默丢弃 replay
状态。

### 10.4 阶段最佳点

每个阶段保留：

- `phase_entry`；
- `phase_best`；
- `phase_exit`。

`phase_best` 依次按以下条件选择：

1. 无非有限值、教师未变化；
2. 最低硬终止率；
3. 最低安全接管率；
4. 最低 action normalized MSE；
5. 最高 latent/action cosine。

阶段末恶化时可以回到 `phase_best`，但回退之后必须重新满足晋升窗口；禁止
“回退后立即强制晋升”。

## 11. LSTM 时序约束

- 每个环境维护独立 hidden/cell state；
- episode reset 必须在同一环境索引上清零 hidden/cell；
- 教师驱动切换到学生驱动时不能清空仍在同一 episode 的状态；
- 训练、平台评估、Python 导出 wrapper 和 ONNX 必须使用相同 reset mask 语义；
- 日志至少记录 hidden norm、reset 数量和 nonfinite 数量；
- 固定序列重复推理必须确定，eval 模式关闭随机增强。

首轮不同时引入新的 recurrent PPO。若后续需要 TBPTT，应作为独立消融，不能在
本次 10 小时任务中静默改变序列训练方式。

## 13. 运行中的观察点

### 前 20 分钟

- 正确加载 `daggerfull-16288`；
- 教师 Encoder/Actor shape 严格匹配；
- 深度 shape、范围、无效值比例正确；
- GPU 无 OOM，单 iteration 耗时稳定；
- 三项 loss 和梯度均有限；
- `train_global_step` 增长；
- 首个 `visionteacher` checkpoint 可下载并重新加载。

### 每次升档

- 当前/下一 phase；
- 连续两个质量窗口明细；
- requested/effective ratio；
- takeover、hard termination、reset、teacher OOD；
- latent/action loss 与 cosine；
- 各地形 episode 数，尤其上下楼不能长期无样本；
- checkpoint 使用的真实平台 ID。

### 最后 30 分钟

- 保持 `visionfull`，不再改变损失、地形和增强；
- 保存最终 checkpoint；
- 立即做一次 checkpoint round-trip；
- 最终文件记录父 SHA、配置 SHA、代码 commit 和实际训练时长；
- 任务退出前确认状态不是“写盘中”或缺失 payload。

## 14. 10 小时任务后的固定评估

至少使用 3 个固定 seed，每个 seed 同时评估教师和视觉学生。

### 能力门槛

- 100% 视觉学生闭环；
- clean 综合完成率达到特权教师的至少 90%；
- `pyramid_stairs` 完成率相对教师下降不超过 10 个百分点；
- `pyramid_stairs_inv` 完成率相对教师下降不超过 10 个百分点；
- 坡地两项相对教师下降不超过 10 个百分点；
- 摔倒率相对教师增加不超过 1 个百分点；
- 有效学生比例至少 95%，安全接管率不超过 5%。

### 视觉真实性门槛

对同一 checkpoint 做三组对照：

1. 正常深度；
2. 全常量深度；
3. 打乱环境之间的深度帧。

常量/错配深度应显著破坏楼梯和坡地表现；否则说明模型可能主要依赖 proprio
时序而没有真正使用视觉。

### 时序门槛

- episode reset 前后的 hidden state 行为可复现；
- 连续长序列无 NaN/Inf；
- 相同输入、相同 hidden、eval 模式下输出一致；
- 不同环境 reset 不得污染其他环境的 LSTM 状态。

### 视频门槛

必须下载并人工查看：

- 上楼入口、连续登阶、楼梯出口；
- 下楼入口、中段姿态、落地恢复；
- 斜向接近楼梯；
- 坡地上行和下行；
- 转向过程中接近地形边缘；
- 摔倒或拒绝前进的失败样本。

只看总分不能放行。

## 15. 结果分流

### 通过

冻结 `visionfull` 为第一个 Standard 视觉基线，随后进入：

1. 深度噪声、空洞、旧帧和相机小扰动的 Sim-to-Real 强化；
2. 真实 D435i 日志离线回放；
3. 可选、受约束的纯学生 RL；
4. `lbc_loco` 导出、ONNX 多帧一致性和真机渐进测试。

### 教师驱动很好、学生闭环差

说明视觉表示能拟合教师，但闭环状态分布覆盖不足。下一轮只调整 DAgger
升档、回放和安全接管，不先做 PPO，也不改网络。

### 教师驱动阶段就差

优先检查：

- 相机外参和深度预处理；
- teacher/student observation 对齐；
- latent/action loss 的梯度量级；
- 楼梯样本覆盖；
- LSTM reset。

不能通过延长 100% 学生阶段掩盖前端感知未学会。

### 视觉学生达到教师，但速度/停车能力仍差

这是父教师能力边界，不属于视觉蒸馏失败。先冻结视觉基线，再设计带动作锚定和
回滚条件的视觉学生 RL，专门训练零速、低速、转向和速度跟随。

## 16. 正式启动前必须完成的代码验收

本文件只冻结方案，不代表代码已经实现。启动 10 小时任务前必须完成：

1. 在不删除 Track、D1–D5 和现有部署契约的前提下，把 R2 的
   `kaiwu_train_v1` low-level loader 移入最新主线；
2. 视觉 LBC loader 严格加载 `daggerfull-16288` 的 Encoder/Actor；
3. 实现同一任务内的视觉 teacher→canary→quarter→half→threequarter→full；
4. 取消“失败仍强制晋升”，输出具体未通过原因；
5. 评估入口明确运行视觉学生，不读取 height scan；
6. checkpoint 单文件保存、恢复、阶段状态和 LSTM 状态契约通过；
7. 1 环境 forward、少量更新 smoke、短闭环评估通过；
8. 新代码保存出的模型包完成一次平台短训后再评估，不能用旧模型包验证新 loader。
