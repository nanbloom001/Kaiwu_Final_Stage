## 1. 文档目标与证据边界

本文档不是为了宣称“P4 已经解决导航”，而是提供一份可以核验的工程地图：

1. 相对最初的低层 PPO，项目为什么引入 P2、P3、P4 分层结构。
2. P4 各轮实验分别改了什么，哪些改动应保留，哪些已暴露风险。
3. 当前代码、checkpoint、评估和平台运行合同。
4. 尚未解决的核心问题，以及不应再次重复的失败路径。
5. 两人并行开发时的文件所有权、合并顺序和验证责任。

后续 PR、issue 和实验报告必须区分以下证据层级。

| 标记 | 含义 | 可以宣称的内容 |
|---|---|---|
| 代码事实 | 从指定 commit 的代码、配置和测试直接核验 | 模块、shape、公式、配置、保存字段确实存在 |
| 本地已验证 | pytest、编译、TOML 和静态检查通过 | 纯 Python/合同逻辑在测试覆盖内正常 |
| 容器已验证 | 通过 Isaac/Kaiwu 正式启动环境完成 reset、rollout、update、save/resume | 指定容器和配置下可以运行 |
| 平台已验证 | 实际创建训练任务并产出有效曲线和 checkpoint | 该任务的训练链路工作 |
| 评估已验证 | 新模型包通过固定条件的 Standard/Track 评估 | 可以报告该次评估的分数和失败类型 |
| 真机已验证 | 相同合同在实际 Go2 上运行 | 可以讨论真实 Sim2Real 表现 |
| 实验观察 | 单次视频、面板或用户现场观察 | 可以形成待验证假设，不能单独确定模块根因 |
| 设计假设 | 根据现象提出的可能解释 | 必须通过 A/B、固定种子或新训练确认 |

重要平台边界：腾讯开悟评估使用已保存模型包中冻结的代码。只修改 Git 工作区或评估页配置，不会自动修复旧模型包。需要代码修复的评估问题，必须产生新的可核验模型包。

## 3. 从原始低层到 P4 的架构演进

### 3.1 原始低层 recurrent PPO

原始主要能力：

    depth 180x320 + proprio/scan
    -> low-level VisionEncoder
    -> low-level recurrent Actor
    -> 12 joint actions @ 50Hz

低层负责：

- 将速度命令转换为关节动作。
- 维持姿态、步态、足端接触和地形通过性。
- 在已训练命令域内跟踪 vx、vy、wz。

低层不应被单独期待解决：

- 全局终点和岔路选择。
- Maze 长程路线规划。
- 记忆已访问通道。
- UWB/goal 失联、跳变和远距离方位误差下的高层推理。

### 3.2 P2：引入分层导航

P2 将任务拆成：

    high-level policy @ 5Hz/10Hz
        outputs target_cmd3 = [vx, vy, wz]
                      |
                      v
    low-level locomotion @ 50Hz
        outputs 12 joint actions

经典高层观察合同为 85 维：

    nav_feat32
    + nav_nonvisual36
    + response_profile16
    + adapter_confidence1
    = Actor85

主要新增：

- 独立 NavigationEncoder，不与低层 CNN 共享参数或 storage。
- 两层 LSTM64 的高层 Actor 和独立 Critic。
- 高层 rollout、TBPTT 和 variable-duration GAE。
- ResponseAdapter，用命令和响应历史概括低层动力学。
- 低层冻结，高层 PPO 不反传到低层或 Adapter。
- 分模块 checkpoint，使 Standard 只取低层、Track 加载完整层级。

P2 同时暴露了后续长期存在的接口难点：

- 高层只通过 cmd 与低层交互，看不到全部低层闭环状态。
- target、limited、exec、measured、true velocity 间有时延和非线性。
- 运行时动作改写若没有回到观察和 rollout，会造成 PPO credit 错位。
- 前向深度看不到侧后方柱子和后腿挂住。
- 局部安全方向不等于全局正确路线。

### 3.3 P3：Standard 联合恢复与 Sim2Real

P3 尝试在 Standard + Camera 中修复低层 Sim2Real，同时保留 P2 高层。重要工程结果：

- Standard 低层评估与 Track 完整层级评估的双入口。
- compact low-level PPO storage，避免完整 float32 深度 rollout。
- 低层力矩、action rate/jerk、步态和域随机化实验。
- Adapter 低层版本边界和 worker bridge 修复。

P3 的步态和 Sim2Real 结果必须按证据层级描述。训练项和面板存在，不等于真机步态已经改善。P4 默认路线后来重新冻结低层，把问题聚焦到 Maze 高层导航。

### 3.4 P4：目标鲁棒、感知诊断、Maze 策略和闭环信用

P4 的主要模块：

| 文件 | 职责 |
|---|---|
| server/agent_ppo/algorithm/algorithm_p4_nav_ppo.py | P4 算法、阶段、辅助 loss、监控、checkpoint |
| server/agent_ppo/feature/p4_camera.py | 相机故障、延迟、hole、near clip、clean/live 诊断 |
| server/agent_ppo/feature/p4_goal_belief.py | goal 丢帧、跳变、传播、重捕获和置信度 |
| server/agent_ppo/feature/p4_contract.py | 动作、奖励、教师、速度、方向合同 |
| server/agent_ppo/feature/p4_stuck.py | 卡滞、墙面证据、reason4 和恢复窗口 |
| server/agent_ppo/feature/p4_spawn.py | 全赛道出生和分段实验 |
| server/agent_ppo/workflow/p2_nav_ppo_workflow.py | P2/P4 共用 rollout 闭环 |
| server/agent_ppo/feature/p2_worker_bridge.py | terminal-safe、contact、scanner、goal 和 worker tail |
| server/agent_ppo/conf/monitor_builder.py | 面板和指标路由 |
| server/agent_ppo/checkpoint_io.py | P4 标签、兼容加载和评估选择 |

P4 的核心意图：

1. 保持 Actor85 和部署接口，先修复 goal/depth 鲁棒性。
2. 使用训练期 nav_scanner + height_scan 作为特权教师，但不进入部署观察。
3. 区分“没看见”“看见但决策错”“命令正确但执行慢”“记忆不足”。
4. 记录 target -> limited -> exec -> measured/true 因果链。
5. 减少隐藏 limiter/controller 对 PPO 动作语义的污染。

## 4. P4 实验时间线与结论

### 4.1 初始 P4 导航诊断

关键 commit：

    4bd3250 feat(server): add P4 maze diagnostic training

新增 P4 算法、camera、GoalBelief、stuck、配置、测试和 smoke 工具。

后续确认并修复的正确性问题：

1. near clip 曾把“米”直接与归一化深度比较，额外制造大量 hole。
2. GoalBelief 曾从被正负 10m 裁剪的 Critic goal 重建米制目标，远目标测量会被错误拒绝。
3. warm-up 曾只把 LR 设为 0，但 Adam moments 仍变化；后续改为真正冻结参数和 optimizer state。

这些属于数据合同修复，不应回退。

### 4.2 10Hz Maze 进攻训练

关键 commit：

    244667b feat(server): train P4 maze policy at 10Hz

主要变化：

- 高层由 5Hz 提高到 10Hz，低层保持 50Hz。
- 同步调整 tick reward、duration、slew 和墙钟。
- success impulse 提高到 +200。
- 增加安全教师、软巡航、卡滞和近终点诊断。
- 加密 target/exec/true 动作链监控。

用户提供的某次 p4maze8h10hz 平台评估截图显示总完成系数约 0.75。这是一次用户提供的评估证据，不是可由本地代码重复推出的稳定统计。

重要制品：

    p4nav2h_1256446
    p4maze8h10hz_1416926

视频仍显示：

- 前腿或后腿卡柱后缺少可靠脱困。
- 目标在侧前方时有时用 vy 代替建立正确符号的 wz。
- target wz 已很大，但 exec/true 转向建立慢。
- 碰撞后连续碰撞或长期无效旋转。
- 近终点斜向经过，没有进入成功半径。
- SafetyHead 正确不等于 Actor 会选择通往终点的安全通道。

### 4.3 Track 评估 SafetyHead 缺失修复

关键 commit：

    c93dd11 fix(server): guard absent P4 eval safety head

Track 评估包可能不包含 training-only SafetyHead，旧代码首帧仍调用它而崩溃。修复是在 Head 缺失时将诊断 risk 清零，不改变模型能力。后续 eval 路径必须保留此边界。

### 4.4 五段全赛道实验和 Maze 遗忘

关键大改：

    e629c50 feat(server): repair P4 maze credit assignment

该阶段引入五段赛道、大范围出生、分段监控、恢复辅助、credit 修复和部署 UWB 方向修正。

实验观察：

- 前段坡面/楼梯能力改善。
- 训练早期 Maze 能力仍存在。
- 最终模型 Maze 条件成功率明显退化。

不能简单归因成“学习率太大”。更合理的联合风险：

- 出生、终止和奖励信用同时改变。
- 前段大量易获得进度样本稀释 Maze 决策样本。
- frontier clawback、route shaping、reason4 和分段 goal 同时变化。
- 模型可以在更容易的路段取得高回报而遗忘 Maze 岔路能力。

p4full8h-r2 最终模型应作为负面实验依据，不应默认作为新的 Maze 父包。

### 4.5 Maze credit repair

该轮从 p4maze8h10hz_1416926 回到单 Maze，尝试：

- 去掉 terminal frontier clawback。
- 改用不可重复 new-best。
- 减少 limiter 干预。
- 冻结低层、NavigationEncoder、SafetyHead、Adapter。
- 保留 Actor 权重并重置 Actor optimizer；一度重建 Critic/return stats。
- 新增 StuckHead 轻量监督。

明确实现 Bug：Actor 冻结且辅助 loss 为空时，loss 没有 grad graph，仍无条件 backward，导致：

    RuntimeError: element 0 of tensors does not require grad
    and does not have a grad_fn

长期防线：只有 loss 需要梯度且至少有可训练参数参与时，才能 backward/step。

该实验没有稳定证明“重建 Critic”有益。除非 reward/value/observation 合同不兼容，否则应优先保留 Critic、optimizer moments 和 return stats，并用较小学习率适配。

### 4.6 恢复辅助和隐藏控制问题

后续实验尝试过：

- 更快的三轴 slew 和轻量 wz 消抖。
- 卡滞条件探索或辅助 Head。
- 高层镜像一致性。
- 近终点捕获。
- 安全出口内 goal tie-break。
- translation limiter 和 yaw cancellation。

最重要的发现不是“某个奖励不够大”，而是多个运行时机制可能在 Actor 采样后改写命令：

    policy target
    -> hidden limiter/controller
    -> limited target
    -> slew
    -> exec
    -> low-level/physics

如果 log-prob 对应 policy target，奖励由 exec 产生，而 Actor 看不到改写状态，PPO 会学习错误动作-结果关系。可能表现为：

- 高估 vx/wz 响应。
- 大半径、拐早或拐晚。
- 用碰撞帮助转向。
- 向目标反方向狂奔后折返。
- vy 替代 yaw，身体转过去但平移方向仍不对。

因此 closed-loop r3 将多个改写机制改成 shadow，更多使用低权重 Actor mean 教师，而不是运行时覆盖动作。

### 4.7 closed-loop r3：当前建议基线

关键 commit：

    ea2ba0d feat(server): train P4 maze closed-loop policy

设计文档：

    server/docs/p4-maze8h-closed-loop-v3.md

当前代码合同：

    task:                  p4maze8h-closedloop-r3
    parent:                p4maze8h10hz_1416926-mazefinal
    effective training:    28800s
    task wall:             8.25h
    envs:                  128
    terrain:               open_entry_maze
    columns:               20, curriculum=false
    episode:               120s
    high-level:            10Hz
    low-level:             50Hz
    rollout:               32 high-level ticks
    TBPTT:                 16
    PPO epochs:            4

训练职责：

    frozen:
      low-level
      NavigationEncoder
      SafetyHead
      ResponseAdapter
      StuckHead

    trainable:
      high-level Actor LSTM/action head
      high-level Critic

动作范围：

    vx: [0.0, 1.0]
    vy: [-0.30, 0.30]
    wz: [-0.90, 0.90]

slew：

    increase: [0.60, 0.60, 2.00]
    release:  [1.20, 1.20, 4.00]

r3 的原则：

- near-goal capture 为 shadow。
- translation limiter 为 shadow。
- yaw-cancellation、missed-safe、goal-safe、yaw-exit 等多项 PPO reward 为 0 或仅诊断。
- stale Goal 速度 cap 保留，因为 freshness/age 对策略可见。
- slew 是确定性执行层，必须记录 policy、limited、exec 和 true。
- 不用“两次反转确认”或全局 wz 硬限制覆盖策略。

五方向 teacher：

    far-left / left / center / right / far-right

它来自 nav_scanner + height_scan，只用于训练期局部安全和 Actor mean 软引导：

- 不进入部署观察。
- 不在运行时覆盖动作。
- goal 只在安全性接近的出口间 tie-break。
- 梯度相对 PPO 有小比例和硬上限。
- 它不等于全局路线规划。

核心 reward：

    new-best:       +1.0/m, episode cap +6, no clawback
    success:        +200
    hard failure:   -60
    timeout:        -40
    reason4:        -75
    time:           -0.02 / 10Hz tick
    collision:      onset -0.12 - 0.18*severity
    persistent:     -0.05/tick
    stuck:          from 0.8s, reaches -0.03/tick after 2s

这些是当前代码合同，不等于已通过对照实验证明为最优权重。

reason4 语义：

- 必须由真实环境 reset 完成，不能只改计数。
- 属于 failure/truncated，绝不计 completion。
- bootstrap 和 continuation mask 均为 0。
- 必须使用 reset 前 terminal-safe 快照。
- contact mapping 或 termination term 不可信时 fail closed。
- reset 是样本回收，不是脱困能力。

训练阶段：

| 有效时间 | Actor | Critic | Teacher | Entropy | reason4 |
|---|---:|---:|---:|---:|---|
| 0-30m | 冻结 | 6e-5 | shadow | 0.004 | shadow/12s |
| 30m-2h | 3e-5 | 6e-5 | 0 -> 1% | 0.004 | active/12s |
| 2-6h | 5e-5 | 5e-5 | 2% | 0.003 | active/10s |
| 6-8h | 2.5e-5 | 3e-5 | 1% | 0.002 | active/10s |

checkpoint：

    contract: p4_maze_closed_loop_v3
    priority:
      loopstable > looptrain > loopadapt > loopwarm
      > historical labels

Standard eval 只加载低层；Track eval 加载完整层级；training-only teacher/heads 不应成为部署必需模块。

### 4.8 r3 的实验观察

用户观察：

- 约 2h checkpoint 相对父模型几乎无明显退化。
- 约 4h50 开始出现一定退化。
- 8h 最终模型退化较严重。
- 视频出现“碰撞作为转向”、延迟避障、大半径转弯和时机误差。

这些观察支持但没有单独证明以下假设：

- 长时间 Actor 训练偏离父模型已有 Maze 行为。
- 教师/碰撞梯度改变行为，却不足以提供全局正确路线。
- 局部安全教师可能降低立即碰撞，也可能在多个安全出口间造成摆动。
- LSTM 不一定真正使用路径历史。
- ResponseAdapter 可能给出错误先验，也可能只是与 Actor 错误共现。

后续必须使用固定父包、相同种子、阶段 checkpoint 和失败类型统计区分这些假设，不能只看总 reward。

## 5. 当前高低层网络和数据闭环

### 5.1 高层网络

当前高层是速度命令策略，不是端到端关节策略：

    depth57600
    -> independent NavigationEncoder
    -> nav_feat32

    nav_feat32
    + nav_nonvisual36
    + response_profile16
    + adapter_confidence1
    -> two-layer LSTM64
    -> three-axis squashed Gaussian
    -> policy_target_cmd3 [vx, vy, wz]

三轴 Actor 由旧二维结构增量扩展：

- 保留旧 vx/wz head 和迁移权重。
- 新增 vy mean/log-std 路径。
- 动作顺序始终是 vx、vy、wz。
- tanh Jacobian、rollout action、old log-prob 和 ratio 必须使用相同三维分布。

任何运行时动作处理都必须回答：

1. PPO log-prob 对应哪个动作？
2. 环境真正执行哪个动作？
3. Actor 下一时刻能否看到二者差异及产生差异的 gate？

无法回答的 limiter、filter、recovery controller 不应进入正式训练。

### 5.2 ResponseAdapter 的能力和限制

ResponseAdapter 为 GRU64，输出 response_profile16，大致布局：

    velocity response @ 0.2/0.6/1.0s: 9
    pose response:                        3
    stuck estimate:                       1
    log sigma:                            3

设计目的：让高层了解命令发布后低层通常如何响应。

限制：

- 它是统计预测摘要，不是真实闭环历史。
- 命令域外、碰撞、卡滞或低层版本变化时可能失准。
- confidence 只是 Actor 输入，不能保证 Actor 会正确降权 profile。
- stuck head 曾长期 precision/recall/F1 为 0，不能视为可靠脱困信号。
- 过度依赖 profile 可能使高层高估低层加速和转向能力。

### 5.3 感知、决策、执行和记忆必须分开归因

| 现象 | 更合理的一级归因 |
|---|---|
| teacher 显示有墙，SafetyHead/视觉预测错误 | 深度或 NavigationEncoder 感知问题 |
| 感知正确，Actor 仍选危险方向 | Actor、reward 或 teacher 梯度问题 |
| policy target 正确，limited/exec/true 没建立 | limiter、slew、低层或 Adapter 闭环问题 |
| 局部总选安全方向，但反复走回原路 | 路径记忆或全局路线问题 |
| clean depth 好，fault depth 差 | 相机增强或视觉鲁棒训练问题 |
| normal hidden 与每 tick 清零 hidden 几乎一致 | Actor 实际未使用时序记忆 |
| 后腿侧后方卡柱，前向深度无障碍 | 部分不可观测，不是单纯 CNN 漏检 |

建议持续维护四条因果链：

    teacher risk -> visual/head risk
    visual/head risk -> policy target
    policy target -> limited target -> exec
    exec -> measured/true motion -> collision/progress

没有这些数据，不应仅凭视频直接调大某项奖励。

## 6. 当前已确认的高风险问题

### 6.1 隐式动作改写和信用错位

最重要的风险不是“奖励不够大”，而是动作在采样后被修改。

允许的执行层至少满足一项：

1. 改写结果和 gate 进入 Actor 观察。
2. rollout 保存 policy、limited、exec 和 gate，训练显式建模差异。
3. 机制仅作为 shadow，不改变动作。
4. 机制是明确的最终安全层，并且训练时完整复现。

否则它可能暂时改善视频，却破坏 PPO 因果关系。

### 6.2 局部安全不等于到达终点

SafetyHead/teacher 能回答“哪里可通行”，不能单独回答：

- 岔路选左还是右。
- 某通道是否走过。
- 安全选择是否导致全局绕行。
- goal 跳变后继续原路线还是重规划。

持续增加局部避障惩罚可能得到“更保守、更慢、仍选错通道”的局部最优。

### 6.3 LSTM 不等于空间记忆

两层 LSTM64 可以建模短时响应和失联，但没有显式地图、访问记忆或拓扑状态。必须先进行 normal-hidden 对 zero-hidden 的固定 checkpoint 对照。如果两者几乎相同，应先承认当前策略没有使用时序信息，再决定是否增加最小路线记忆。

### 6.4 后腿和侧后方卡滞的可观测性

前腿已绕过柱子而后腿/机身侧后方被卡住时，前向深度可能看不到障碍。部署可得补充证据应优先来自：

- exec 与 measured motion residual。
- IMU yaw/roll/pitch 响应。
- joint velocity、action saturation、足端接触摘要。
- 有运动命令但空间位移不足。
- 短时事件历史。

训练期 privileged contact 可生成标签，但不可无声加入部署观察。

### 6.5 监控统计不等于 lifetime 真值

曾反复出现以下口径问题：

- EnvMonitor 常按 60 秒窗口 flush；窗口完成数不是 lifetime 完成率。
- 20 列 Track 的旧面板可能只显示 L0-L9。
- terrain_levels 在 Track 中通常是出生段，不是当前物理段。
- terminal outcome 必须按 reset 前 row/column 归因。
- completion coefficient、episode count、window count 和 lifetime count 不可混用。
- reward 分解必须互不重叠，逐 tick 之和必须等于 PPO storage reward。

## 7. 禁止无证据重复引入的旧方案

1. **依赖 server/isaac_env/base_env.py 的正式方案**
   平台会覆盖该文件。本地改动可调试，但不能成为训练或评估必要条件。

2. **用模型 ID、请求 ID、标签或 lineage 作单点硬门禁**
   ID 只用于选择和告警。文件、反序列化、module/spec/shape 和有限值才是结构硬检查。

3. **用全局 wz 限制或“两次反转确认”掩盖 S 型**
   会损害连续转弯和紧急避障，并覆盖策略本身问题。

4. **只训练 SafetyHead，不让 Actor 获得低权重行为引导**
   Head 指标可变好，Actor 行为不一定变化。

5. **让安全教师直接决定目标方向**
   安全教师不知道全局路线。goal 只能在安全性接近的出口中 tie-break。

6. **对成熟 Critic 无条件重建**
   只有 reward/value/observation 合同不兼容时才应重建。

7. **提供碰撞后恢复正奖励**
   容易学习“先碰撞再恢复”。恢复宜作为辅助标签或诊断。

8. **持续绝对 goal-distance 正奖励**
   会导致静止在终点外刷分。应使用不可重复 potential/new-best 和一次 success。

9. **硬映射统一 vx=0.7**
   会改变旧 Actor 输出的物理语义。巡航偏好应通过可关闭的软约束实现。

10. **用 reset 代替脱困学习**
    reset 只回收无效样本，必须算失败，不能当作学会恢复。

11. **一轮同时改变地形、出生、goal、reset、reward 和网络**
    五段训练已经证明这会破坏归因。

## 8. 建议的下一代高层结构

如果 Adapter 和 hidden 消融确认瓶颈在高层表示，建议构建兼容 HighLevel V2，而不是继续堆叠 reward。

### 8.1 零初始化 residual，保留旧 Actor85

    legacy Actor85 mean
            +
    alpha * residual_mean(context)
            =
    new mean3

alpha 从 0 开始，保证 warm start 时旧动作逐值不变。

这是网络合同变化，必须同一 PR 原子更新：

- server 训练端。
- deploy 推理端。
- shared/interfaces/server-deploy-contract.md。
- checkpoint spec、migration、exporter。
- Standard/Track eval。
- old checkpoint warm-start 回归测试。

### 8.2 建议新增上下文

#### A. 因果响应历史编码器

输入过去约 1 秒：

    policy target
    limited target
    exec command
    measured velocity
    IMU yaw/roll/pitch rate
    valid/age/source
    target-exec residual
    exec-measured residual

它比 response_profile16 更适合表达“刚才的转向是否真正建立”。Adapter 可以保留为慢先验，但 Actor 应同时看到真实闭环历史。

#### B. 部署可得的五方向安全表示

训练时 scanner/height 作 teacher，部署时用深度预测五方向 risk/clearance。不要只保留 training-only Head 而让 Actor 靠 latent 隐式解码。

#### C. goal-conditioned waypoint head

将两个问题分开：

    safe direction distribution
    short-horizon waypoint direction/distance

训练期可用 privileged geometry 生成 waypoint 标签，部署只使用视觉预测。它比把 goal heading 混入 safety label 更容易学习和归因。

#### D. 最小路线记忆

候选：

- route GRU：输入过去的出口选择和 egomotion。
- 小型 egocentric occupancy/visit memory。
- 岔路 token：记录已选左右和后续进展。

不要一开始构建庞大全局地图。先用 hidden 消融确认需求，再实现最小可验证记忆。

#### E. 部署可得的 stuck/recovery context

使用 command、motion residual、IMU、joint/contact summary 和近期 collision proxy。privileged tracker 只用于标签。

#### F. 有界 state-dependent exploration

可在旧 log-std 上增加零初始化、严格限幅的 delta_log_std(context)，但必须：

- rollout 保存 effective log-std。
- PPO update 重建相同分布。
- 不使用 privileged stuck 作为部署输入。
- 近终点不能因方差过大错过成功半径。

### 8.3 不建议的结构升级

- 只把 LSTM64 改成 LSTM128。
- 直接把 scanner/height 加入部署 Actor。
- 用硬规则完全替代 Actor 的 vy/wz。
- 一次改变 observation、mapper、reward、terrain 和 reset。
- 没有旧输出逐值一致测试的 checkpoint migration。

## 10. 验证和实验流程

### 10.1 本地定向测试

优先运行与改动直接相关的最小测试：

- old checkpoint 到新模型的权重迁移。
- 固定输入下 legacy mean/log-std 逐值一致。

- PPO log-prob 与 policy action 合同一致。
- terminal-safe snapshot 不读取 reset 后新 episode。
- timeout/reason4 GAE masks。
- Standard 低层 eval 和 Track 完整 eval 加载。

### 10.2 容器最小测试

- 源码、配置、命令优先使用仓库已有 RPC。

测试期间约每 5 分钟与 WebIDE 交互一次，避免容器回收。

    1 env reset/step
    8 env one complete 32-tick rollout
    one PPO update

## 11. 监控面板合同

### 11.1 平台限制

- line 面板最多 20 个指标。
- 标题字符集和长度也可能被校验。
- phase 标签建议使用纯小写英文字母。
- 空面板需要先区分“未上报”与“路由错误”，再决定删除。

### 11.2 必须保留的因果指标

目标信号：

    raw goal distance
    goal freshness / age
    accept / reject / reacquisition
    jump magnitude and angle
    innovation d2
    stale low-speed share

感知：

    teacher validity
    teacher risk per direction
    visual/head risk per direction
    wall miss / false positive
    clean-live latent cosine
    corridor / junction / dead-end

决策：

    policy target vx/vy/wz
    teacher-correct Actor-wrong
    goal-safe tie-break
    near-goal yaw response
    normal-hidden vs zero-hidden action difference

执行：

    policy -> limited
    limited -> exec
    exec -> measured
    measured -> true
    positive/negative vy and wz separately
    slew saturation and release delay

结果：

    success / timeout / hard failure / reason4
    window count and lifetime count separately
    collision onset / persistent contact
    wall-stuck candidate / duration / saved seconds
    near-goal miss
    episode return
    non-overlapping reward decomposition

正负速度必须分开。仅记录带符号均值会因左右抵消接近 0，无法反映方向偏置。

### 11.3 性能边界

监控会消耗训练吞吐，尤其是：

- 每 rollout 构造大量 Python tensor list。
- 逐环境 logger。
- 大张量频繁从 GPU 拷贝到 CPU。
- 过量 quantile/histogram 和原始 trace。

建议：

- GPU 上用 bincount/scatter_add 聚合。
- 每 60 秒 flush 标量。
- 每窗口最多保留 12 条代表性事件 trace。
- zero-hidden 只抽样约 5% 环境。
- 线性 probe 只在训练前或独立诊断执行。
- 删除无法支持决策的高维分桶。

## 12. 平台、容器和制品运维经验

### 12.1 任务创建失败时的安全清理

容器文件过多曾导致任务创建失败。可安全清理的典型内容：

    .ide-sync-*.tar.gz
    旧同步分片和上传中间包
    __pycache__ / .pytest_cache
    本任务生成的 test_artifacts
    过期日志
    不再需要的父包解压副本

禁止清理：

    .env / Token / Cookie / credentials
    测试未完成时仍需要的父模型
    当前任务需要的 checkpoint
    用户文件

清理必须先列清单、限定目录，再删除。不要使用不受控的递归删除。

### 12.2 同步和模型上传

历史问题：

- 同步工具曾上传 test_artifacts/p3_parent/extracted。
- 残留多个 .ide-sync-*.tar.gz。
- 上传耗时长且占满容器磁盘。

长期要求：

- source sync 使用 allowlist/exclude。
- 排除 archive、logs、extracted test artifacts、cache、model 副本。
- 上传前打印文件数和总字节数。
- 上传后验证 SHA256。
- 成功或失败后都清理本次中间 tar。
- 不打印 Token、Cookie 或 .env。

### 12.3 模型包体积

P3/P4 包比早期包大，可能来自：

- 高层 Actor/Critic/NavigationEncoder/Adapter。
- optimizer/scheduler/RNG。
- return/value statistics。
- completed Adapter records。
- training-only Safety/Stuck heads。
- 低层 anchor 或兼容别名。
- 训练合同和诊断状态。

包变大不等于一定有 Bug，但必须检查成员清单，确认没有源代码树副本、日志、cache、父 ZIP 或未完成 rollout。

### 12.4 WebIDE VSCode 传输能力

VSCode Remote 文件能力来自浏览器/IDE 会话，不是本地仓库中必然可 import 的 Python 模块。本地搜索不到“模型专用传输模块”，不等于已登录 WebIDE 没有 Remote FS 能力。应先检查浏览器会话、Remote FS 请求和 RPC，再使用分片 fallback。

## 15. 建议的下一阶段路线

### 阶段 A：无训练归因

1. 同一 checkpoint 运行 Adapter normal/neutral/empirical。
2. 同一 checkpoint 运行 normal-hidden/zero-hidden。
3. 使用相同固定种子和地形列。
4. 记录感知、决策、执行、结果四条链。
5. 将失败 episode 分为感知、Actor、执行、记忆、不可观测五类。

此阶段不改权重，先决定是否真的需要 HighLevel V2。

### 阶段 B：合同骨架 PR

1. 定义 response history 字段、归一化、窗口和 valid/age。
2. 定义 deployable five-direction safety。
3. 定义 residual Actor 零初始化和 checkpoint spec。
4. 定义 Standard/Track/export 兼容行为。
5. 定义新指标命名和最小面板。

该 PR 不改变正式策略行为。

### 阶段 C：并行实现

- A 实现 response-context residual。
- B 实现 deployable safety、waypoint 和诊断。
- 两人各自负责定向测试。
- 集成负责人合并后统一运行公共测试。

### 阶段 D：逐级训练

    5-10 min container smoke
    15-30 min platform smoke
    30-60 min targeted training
    fixed-seed multi-checkpoint evaluation
    2-3 h attribution training
    only after no regression, consider 8 h

## 17. 最终交接结论

P4 已形成较完整的工程骨架：

- 独立高层视觉。
- 三轴 recurrent Actor/Critic。
- ResponseAdapter。
- GoalBelief 和相机鲁棒合同。
- 特权安全教师。
- 卡滞诊断和 reason4。
- Standard/Track 双评估。
- 可恢复 checkpoint。
- 因果链监控。

尚未解决的核心问题：

1. 高层对低层真实响应的表示仍过度依赖压缩后的 Adapter profile。
2. 局部安全感知与全局正确路线没有充分解耦。
3. 当前 LSTM 是否实际利用时序记忆尚需消融。
4. 后腿/侧后方卡滞部分不可由前向深度直接观察。
5. 长训可能在 2-8 小时之间破坏父模型已有 Maze 能力。
6. 隐式动作改写可能破坏 PPO 数据闭环，这比继续增加奖励项更优先。

下一阶段应以“可观察、可归因、可兼容”为原则：

- 先完成 Adapter 和 hidden 消融。
- 再以零初始化 residual 增加因果响应历史。
- 将安全表示和短程 waypoint 分离。
- 只有诊断确认后才加入最小路线记忆。
- 不再把强 limiter、新 reset、新 reward、新地形和新网络同时放入一轮长训。
