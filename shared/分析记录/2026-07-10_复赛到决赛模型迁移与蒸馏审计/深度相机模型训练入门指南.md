## 1. 先看全局：项目中实际存在三种模型

```text
模型 A：复赛 flat Track

proprio45 + raw height_scan256 + goal3 = obs304
                         |
                         v
              MLP Actor 304→512→256→128→12
                         |
                         v
                    action12


模型 B：决赛 Encoder Teacher

raw height_scan256 → Scan Encoder 256→512→256→32 → latent32
proprio45 + latent32 + goal3 = actor_input80
                         |
                         v
              MLP Actor 80→512→256→128→12
                         |
                         v
                    action12


模型 C：决赛 Vision Student

depth[180,320,1] → CNN → image_feature32
image_feature32 + proprio45 → 2层LSTM64 → latent32
proprio45 + latent32 + goal3 = actor_input80
                         |
                         v
                同一个冻结 Actor
                         |
                         v
                    action12
```

最重要的理解是：决赛并不是让旧 Actor 直接读取一张图片，而是让视觉学生输出一个与教师 `scan encoder` 相同语义、相同维度的 `latent32`。Actor 只认这个 32 维接口，不需要理解 latent 来自高度扫描还是深度相机。

官方规则规定，训练时可以使用 `height_scan`，部署和评测时不能使用它，只能依赖深度相机与机器人自身状态：[项目简介](../../规则说明/开发指南/项目简介.md)。

## 2. 阅读模型代码前必须理解的基础概念

### 2.1 Tensor 和 shape

Tensor 可以先理解为多维数组。Shape 表示每个维度的长度。

本项目常见张量：

| 张量 | Shape | 含义 |
| --- | --- | --- |
| `proprio` | `[B,45]` | B 台机器人各自的 45 维自身状态 |
| `height_scan` | `[B,256]` | B 台机器人各自的 16×16 高度扫描 |
| `goal3` | `[B,3]` | 局部目标 x、y 和目标距离 |
| `depth` | `[B,180,320,1]` | B 张单通道深度图 |
| `latent` | `[B,32]` | 压缩后的地形表示 |
| `action` | `[B,12]` | 12 个 Go2 关节动作 |

`B` 是 batch size。在并行仿真中，一次可能同时运行 128 或 2048 台虚拟机器狗，因此网络第一维不是固定的 1。

例如：

```python
proprio = obs[:, 0:45]       # [B,45]
scan = obs[:, 45:301]        # [B,256]
goal = obs[:, 301:304]       # [B,3]
actor_input = torch.cat([proprio, latent, goal], dim=-1)
                                # [B,45+32+3] = [B,80]
```

两个 checkpoint 能否直接加载，首先取决于参数名和每个参数的 shape 是否一致；即使 shape 一致，还必须继续检查输入语义是否一致。

### 2.2 参数、前向传播和损失

神经网络中的权重和 bias 是可学习参数。一次训练更新可以简化为：

```text
输入数据
→ forward 前向计算
→ 得到模型输出
→ 与目标计算 loss
→ backward 计算每个参数的梯度
→ optimizer 根据梯度更新参数
```

如果一个模块被冻结：

```python
parameter.requires_grad = False
```

它仍然可以参与前向计算，但不会在 `optimizer.step()` 时更新。

### 2.3 Linear 和 MLP

一个全连接层 `Linear(in_dim, out_dim)` 可以理解为：

```text
y = W x + b
W.shape = [out_dim, in_dim]
```

例如旧 Track Actor 的第一层是：

```text
Linear(304,512)
weight.shape = [512,304]
```

MLP 是多层 Linear 加激活函数组成的网络：

```text
304 → 512 → 256 → 128 → 12
```

它适合处理已经整理成一维向量的特征，但不会自动知道 256 个连续数字原本排列成 16×16 网格。

### 2.4 CNN

CNN 使用局部卷积核处理图像。它会同时利用相邻像素和空间位置关系，适合识别台阶边缘、斜坡、墙面、空洞等局部结构。

当前 `SimpleCNN`：

```text
depth 180×320×1
→ Conv(1→32, kernel5, stride2) + Pool
→ Conv(32→64, kernel3, stride2) + Pool
→ Conv(64→128, kernel3)
→ Flatten
→ Linear
→ image_feature32
```

代码见 [simple_cnn.py](../../代码存档/决赛_track蒸馏_162404/agent_ppo/model/simple_cnn.py)。

### 2.5 LSTM

普通 MLP/CNN 每一帧都独立处理输入。LSTM 还保存上一帧留下的 hidden state 和 cell state，因此可以利用短时间历史。

深度相机需要时间信息，因为：

- 某一帧可能有深度空洞；
- 台阶可能被机器人自身或前景遮挡；
- 相机随身体上下和俯仰运动；
- 连续几帧更容易判断地形变化趋势。

当前结构为：

```text
LSTM input  = image_feature32 + proprio45 = 77
hidden size = 64
layers      = 2
output      = Linear(64,32) → latent32
```

LSTM 的 `h/c` 必须逐帧保留，并在序列边界清零。当前 Python 训练 workflow 已经在 episode `terminated|truncated` 后按环境清零；但仓库缺少实际 Jetson runtime，因此急停、控制器重启、相机断流以及 `Passive/FixStand/VisionLoco` 状态切换时的 reset 仍是待实现、待验证项。模型的 reset 接口见 [vision_encoder.py](../../代码存档/决赛_track蒸馏_162404/agent_ppo/model/vision_encoder.py)。

### 2.6 Latent

Latent 是模型内部压缩后的表示。这里 `latent32` 可以理解为“对控制有用的 32 个地形特征”，它不要求每一维都有人工可读的含义。

它的作用是建立稳定接口：

```text
height_scan → Teacher Encoder ─┐
                              ├→ latent32 → Actor
depth+proprio → Vision Student ┘
```

两种传感器只要能产生语义一致的 latent，后面的 Actor 就可以复用。

教师和学生的 latent 都经过 L2Norm，使每个 latent 的长度接近 1。训练重点变成让二者方向一致，便于使用 MSE、cosine 和夹角评价。

### 2.7 Actor、Critic 和 PPO

Actor 根据观测产生动作：

```text
Actor(observation) → 12 维关节动作
```

Critic 估计当前状态有多好：

```text
Critic(state) → value
```

PPO 是训练 Actor-Critic 的强化学习算法。它大致执行：

```text
Actor 与环境交互
→ 收集 observation、action、reward、done
→ Critic 估计价值
→ 根据实际回报计算 advantage
→ 更新 Actor，让高 advantage 动作更可能出现
→ 更新 Critic，让 value 估计更准确
```

不对称 Actor-Critic 表示 Critic 在训练时可以看到额外特权信息，而部署时只保留 Actor。Critic、reward 和探索噪声都不会进入真机推理。

本项目只需要先记住：PPO 用来学会走路和导航；LBC 不使用 reward，而是监督学习。

## 3. 一帧观测中到底有什么

### 3.1 Proprio 45

| 区间 | 维度 | 内容 |
| --- | ---: | --- |
| `[0:3]` | 3 | 机体角速度 |
| `[3:6]` | 3 | 重力方向投影 |
| `[6:9]` | 3 | 速度命令 `vx,vy,wz` |
| `[9:21]` | 12 | 关节相对位置 |
| `[21:33]` | 12 | 关节速度 |
| `[33:45]` | 12 | 上一帧动作 |

完整协议见 [数据协议](../../规则说明/开发指南/数据协议.md)。

### 3.2 Height scan 256

`height_scan` 是 16×16 前方高度扫描，共 256 个值。它是仿真 RayCaster 提供的特权观测，具有规则网格和干净几何信息。

旧 flat Actor 直接读取这 256 个值；决赛 Teacher 则先把它们压缩成 32 维 latent。

### 3.3 Depth 57600

深度图 shape 为 `180×320×1`，共 57600 个值。训练和部署需要保持：

```text
有效量程：(0,5m)
有效值：depth_in_meter / 5.0
最终值域：[0,1]
无效、非有限、<=0 或 >=5m：0
```

深度图不是普通灰度图。每个像素表示沿相机光线到可见表面的距离。

以上是目标协议和真机部署要求。当前仿真预处理只显式处理 `depth>=5m` 和数值 clamp，没有使用 `torch.isfinite` 清理 NaN；NaN 经过 `torch.clamp` 仍可能是 NaN。因此训练侧还需要补充非有限值和 `<=0` 的显式置零，不能假定现有代码已经完整兑现目标协议。

### 3.4 Goal3

当前 Track 扩展使用：

```text
[local_goal_x / 10, local_goal_y / 10, distance / 20]
```

代码见 [goal_features.py](../../代码存档/决赛_track蒸馏_162404/agent_ppo/feature/goal_features.py)。训练侧通过仿真世界坐标计算，真机必须由定位、UWB 或导航系统生成同义输入。

### 3.5 各阶段 shape 台账

| 阶段 | 外部观测/容器 | 真正进入 Actor 的输入 |
| --- | --- | --- |
| 复赛 Standard | `45+256=301` | 301 |
| 复赛 flat Track | `45+256+3=304` | 304 |
| 决赛 Standard Teacher | `45+256=301` | `45+32=77` |
| 决赛 Track Teacher | `45+256+3=304` | `45+32+3=80` |
| Standard LBC 训练 | `45+256+57600=57901` | Teacher 77 / Student 77 |
| Track LBC 训练 | `45+256+3+57600=57904` | Teacher 80 / Student 80 |
| 官方真机 loco | depth、proprio 分开输入 | 77 |
| 当前 goal3 真机方案 | depth、proprio、goal3 分开输入 | 80 |

`57901/57904` 只是训练时把配对信息装在一起的容器，不代表要建立一个 57904 维全连接 Actor。

## 4. 为什么旧模型不能直接换成深度输入

旧复赛 Track 首层：

```text
weight.shape = [512,304]
输入 0:45    = proprio
输入 45:301  = raw height_scan256
输入 301:304 = goal3
```

决赛 Track Teacher 首层：

```text
weight.shape = [512,80]
输入 0:45   = proprio
输入 45:77  = encoded latent32
输入 77:80  = goal3
```

如果简单复制旧权重的前 80 列，旧 `45:77` 仍是 raw scan 的前 32 个采样点，而新 `45:77` 应是经过多层非线性编码和归一化的 latent。Shape 看起来能放进去，语义却完全错误。

把深度图 resize 成 16×16 同样不成立：resize 只减少像素数量，不会把“相机射线距离”转换成“局部地面高度”。

可选路线比较：

| 路线 | 是否可行 | 说明 |
| --- | --- | --- |
| depth 直接替换 scan | 否 | Shape 和物理语义都不同 |
| depth resize 成 16×16 | 不推荐 | 没有完成几何坐标和高度语义转换 |
| depth→点云→高程栅格→旧策略 | 理论可行 | 依赖精确标定、姿态、遮挡处理和空洞填充，当前仓库未实现 |
| flat 策略→Encoder Teacher→LBC | 推荐 | 保留旧能力并进入官方视觉 latent 接口 |
| 新 Encoder Teacher 重新 PPO→LBC | 推荐备选 | 不继承旧权重，但链路更直接、可复现 |

## 5. 教师、学生和蒸馏

### 5.1 教师并不一定更大

教师的关键不是参数更多，而是训练时拥有更可靠的信息。

在 LBC 中：

- 教师能读取仿真中准确的 `height_scan`；
- 学生只能读取真机可获得的 `depth+proprio`；
- 教师相当于在仿真中“作弊”；
- 学生学习在不作弊的条件下复现教师的判断。

这就是 `Learning by Cheating`。

### 5.2 蒸馏不是复制权重

蒸馏是用教师输出作为监督标签训练学生。教师与学生可以有不同输入、不同网络结构和不同参数 shape。

```text
教师输出 target
学生输出 prediction
loss(target, prediction)
只更新学生
```

### 5.3 本项目有两种蒸馏

| 蒸馏 | 教师 | 学生 | 对齐目标 | 解决的问题 |
| --- | --- | --- | --- | --- |
| 行为蒸馏 | 旧 flat Track | 新 Encoder Track | action12 | flat→encoder 架构迁移 |
| LBC 蒸馏 | Encoder Teacher | VisionEncoder | latent32 | height scan→深度相机迁移 |

不要把这两次蒸馏混成一次。第一段解决网络接口变化，第二段解决传感器变化。

## 6. 第一段：如何得到合格的 Encoder Teacher

### 6.1 路线 A：复用旧 Track，做行为蒸馏

同一帧 `obs304` 同时送给两个模型：

```text
flat_teacher(obs304)    → teacher_action12
encoder_student(obs304) → student_action12

loss = MSE(student_action, teacher_action)
```

训练时：

| 模块 | 状态 |
| --- | --- |
| 旧 flat Track Teacher | 冻结 |
| 新 Scan Encoder | 更新 |
| 新 Actor | 更新 |
| 新 Critic | 行为蒸馏阶段可以不使用或后续 PPO 再训练 |

代码草稿见 [algorithm_behavior_distill.py](../../代码存档/决赛_track蒸馏_162404/agent_ppo/algorithm/algorithm_behavior_distill.py)。

建议先让 flat Teacher 驱动环境，保证样本处于成熟策略熟悉的状态；当 action MSE 足够低后，再让 Encoder Student 驱动并继续使用 Teacher 标注，减少闭环分布偏移。必要时最后用小学习率 PPO 微调。

当前仓库已经有行为蒸馏算法和 workflow 草稿，但 StageConfig 和主 workflow 分发尚未接通，因此这一步目前不能从现有快照稳定重跑。

### 6.2 路线 B：重新 PPO 训练 Encoder Teacher

也可以直接使用 `ActorCriticEncoder(goal3)` 从头训练：

```text
scan256 → Encoder → latent32
proprio45 + latent32 + goal3 → Actor → action12
Critic 估计 value
PPO 根据 reward 更新 Encoder、Actor、Critic
```

优点是训练链完整、结构天然符合 LBC；缺点是不直接继承 `42399` 已经学到的 Track 导航能力，可能需要更多平台训练时间。

### 6.3 Encoder Teacher 的通过标准

进入 LBC 前至少确认：

- checkpoint 包含 `encoder.*` 和 `actor.*`；
- Actor 第一层输入为 80（goal3 路线）或 77（官方 loco 路线）；
- height-scan Teacher 能独立闭环完成 Track；
- 完成率、摔倒率、用时、姿态和能耗都有固定种子基线；
- checkpoint 来源、配置和 hash 已归档；
- 教师加载缺失或 shape 不匹配时立即终止，而不是 warning 后继续。

## 7. 第二段：LBC 视觉蒸馏如何训练

### 7.1 同一时刻必须有配对数据

Track LBC 训练容器：

```text
[proprio45 | height_scan256 | goal3 | depth57600] = 57904
```

同一个环境、同一台机器人、同一时刻同时产生 scan 和 depth，才能建立有效监督关系。

### 7.2 一次 LBC 更新

```python
# 1. 教师根据特权扫描生成监督目标
with torch.no_grad():
    teacher_latent = teacher_encoder(height_scan)

# 2. 学生根据可部署观测预测同一表示
student_latent = vision_encoder(depth, proprio)

# 3. 比较两者
loss = ((student_latent - teacher_latent) ** 2).sum(dim=-1).mean()

# 4. 只更新学生
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

实际实现见 [algorithm_lbc.py](../../代码存档/决赛_track蒸馏_162404/agent_ppo/algorithm/algorithm_lbc.py)。

### 7.3 谁驱动环境

标准训练使用 Teacher Actor 驱动环境：

```text
height_scan → teacher_encoder → teacher_latent
proprio + teacher_latent + goal → frozen Actor → action
```

这样采样轨迹稳定，学生在教师真正会访问的状态上学习。

训练后必须切换到 Student 驱动：

```text
depth+proprio → VisionEncoder → student_latent
proprio + student_latent + goal → frozen Actor → action
```

当前 `student_drive=true` 的设计意图是纯评估，不做反向传播。但当前实现还存在一个阻断性问题：`_lbc_step()` 先调用 `act_student(obs)` 生成动作，随后又对同一帧调用 `compute_latent_loss(obs)` 计算指标；两个函数都会前向有状态的 VisionEncoder，导致同一相机帧让 LSTM `h/c` 推进两次。修复为“单次视觉前向同时复用 action 和指标”，或在第二次指标计算前保存/恢复状态之前，当前 student-drive 结果不能作为真实 50Hz 闭环基线。

修复单帧双前向后，如果 Student 闭环进入教师很少访问的新状态，再考虑实现 DAgger 式采样：让 Student 驱动，但仍用 Teacher 为这些状态生成监督目标。

### 7.4 LBC 中谁更新、谁冻结

| 模块 | 是否更新 | 作用 |
| --- | --- | --- |
| Teacher Scan Encoder | 否 | 产生 teacher latent |
| Teacher Actor | 否 | 驱动环境、将 latent 解码成动作 |
| Vision CNN | 是 | 从深度图提取空间特征 |
| Vision LSTM | 是 | 融合历史和 proprio |
| Vision Head | 是 | 输出 student latent32 |
| Critic | 不参与 | LBC 是监督学习，不是 PPO |

### 7.5 为什么主要蒸馏 latent，而不是直接蒸馏动作

蒸馏 latent 可以把感知学习和控制学习分开：

- 教师 Actor 已经会走，不需要视觉训练时反复重学；
- 32 维目标比 57600 维图像更紧凑；
- latent 只保留对控制有用的信息；
- 同一个 Actor 可以公平比较 Teacher 和 Student。

如果 latent 指标很好但动作仍偏差，可以额外增加 action consistency loss：

```text
teacher_action = Actor(proprio, teacher_latent, goal)
student_action = Actor(proprio, student_latent, goal)
action_loss = MSE(student_action, teacher_action)
```

这应作为辅助损失，而不是替代 latent 对齐。

## 8. 完整训练流程：每个阶段训练谁、产出什么

### 阶段 0：先决定最终模型契约

当前必须先在两种路线中选择：

| 路线 | Actor 输入 | 导航方式 | 部署工作量 |
| --- | ---: | --- | --- |
| 官方分层 loco | `45+32=77` | 高层导航/UWB 产生 `vx,vy,wz` | 较低，可复用官方 exporter/runtime |
| 当前端到端 Track | `45+32+goal3=80` | goal3 直接进入关节 Actor | 较高，需要自定义 exporter、runtime 和真机 goal3 |

官方 stock loco ONNX 中的 `goal[1,4]` 不参与动作计算，只记录诊断；速度由 fixed command 或 UWB 提供。当前 checkpoint 的 Actor80 则真实依赖 goal3。这个选择必须在继续训练前确定，不能等到导出时临时处理。

### 阶段 1：建立旧模型基线

| 项目 | 内容 |
| --- | --- |
| 输入 | `proprio45+scan256+goal3` |
| 模型 | flat Track `42399` |
| 是否训练 | 否，只评估 |
| 产物 | 固定种子基线报告 |
| 必看指标 | 完成率、摔倒率、用时、姿态、能耗、动作平滑度 |

这一阶段回答：“我们希望迁移后至少保留什么能力？”没有基线就无法判断蒸馏是否成功。

### 阶段 2：获得 Encoder Teacher

可以选择行为蒸馏或重新 PPO。

| 项目 | 行为蒸馏 | 重新 PPO |
| --- | --- | --- |
| 监督来源 | flat Teacher action | 环境 reward |
| 更新模块 | Encoder + Actor；Critic/std 不参与 action loss | Encoder、Actor、Critic |
| 优点 | 复用 `42399` | 链路干净、原生 Encoder |
| 风险 | 入口尚未接通，闭环分布偏移 | 训练成本高、可能重新学导航 |
| 产物 | `encoder.* + actor.*` checkpoint | 同左 |

只有当 Encoder Teacher 的 height-scan 闭环表现合格，才能进入下一阶段。

### 阶段 3：LBC 视觉蒸馏

| 项目 | 内容 |
| --- | --- |
| 环境 | Camera 变体，同步产生 scan 和 depth |
| 驱动者 | 冻结 Teacher |
| 训练者 | VisionEncoder |
| 优化损失 | latent squared distance |
| 监控指标 | cosine、angle、distance、latent std |
| reward | 不使用 |
| 产物 | `format=lbc_loco` 视觉 checkpoint |

当前 Track LBC 配置使用 128 个环境，低于规则建议的 `≤256`，这是合理的显存配置。最终一轮 LBC 开始前，应先固定目标真机的相机和支架、完成安装外参测量，并把实际 `offset_pos/offset_rot` 写回训练配置；否则后续标定改变视角后可能需要重新训练。

### 阶段 4：Student 闭环评估

先修复第 7.3 节所述的 Student 单帧双前向问题，并确保评估关闭随机视觉增强，再把环境动作来源切换为：

```text
depth → VisionEncoder → student latent → frozen Actor
```

固定与 Teacher 相同的种子、地形和命令分布，比较：

- Teacher 与 Student 的完成率；
- 摔倒率和失败位置；
- 每段地形的用时；
- roll/pitch 和能耗；
- latent、action 和 LSTM 状态是否异常；
- 深度视频中相机是否看到正确区域。

### 阶段 5：ONNX 导出与数值对拍

导出图只保留真机需要的推理路径。对于官方 actor77，stock ONNX 的输入是彼此独立的 `depth`、`proprio`、诊断用 `goal4`、`cmd_override`、`loco_h/c` 和透传的 `nav_h/c`：

```text
depth、proprio、goal4、cmd_override、loco_h/c、nav_h/c
→ CNN+LSTM+head
→ latent
→ Actor
→ joint action、下一帧 h/c
```

其中 stock `goal4` 在 loco 图内被忽略，真正速度命令进入 `proprio[6:9]`。actor80 路线不能把自定义 goal3 直接塞进 stock goal4；必须新增明确的 `goal3[1,3]` 输入，定义其缩放和拼接位置，并同步修改 wrapper、ONNX 和 C++ runtime。

至少验证：

1. 训练侧 PyTorch 模型与导出 wrapper 一致；
2. wrapper 与 ONNX 一致；
3. 连续多帧逐帧回灌 LSTM `h/c`；
4. episode reset 后两边状态同时清零；
5. action、hidden 和 cell 均在容差内。

ONNX 通过后还必须检查与 checkpoint 同源的 `deploy.yaml`：`joint_ids_map`、默认关节位置、`action.scale`、KP/KD、proprio scale、clip 和 `step_dt=0.02` 必须与训练一致。ONNX 数值正确但关节映射或动作 scale 错误，真机仍会产生危险动作。

官方部署要求见 [部署指南](../../规则说明/开发指南/部署指南.md)。

### 阶段 6：Jetson 与真机测试

任何真机操作前必须完整阅读 [安全规范](../../规则说明/开发指南/安全规范.md)，确认封闭测试区域、专业人员、人员安全距离、持续人工监控和物理急停。具体急停按键和固件行为还要以现场部署包和机器人版本为准。

```text
悬空/吊架检查关节方向与限幅
→ 低速平地
→ 单坡道、单楼梯
→ 单障碍与目标变化
→ 完整 Track
```

每一级都要有急停、姿态阈值、动作限幅和回退条件，不能直接从仿真跳到完整赛道。

## 9. 深度相机适配不是只改模型

### 9.1 仿真侧深度预处理

当前代码执行：

```text
读取 TiledCamera depth
→ 超过 5m 置 0
→ clamp 到 0~5m
→ 除以 5，归一化到 [0,1]
→ 训练时做像素 dropout
→ 加深度比例高斯噪声
→ roll 旋转抖动
→ pitch 像素平移
→ flatten 为 57600
```

实现见 [nav_observation_utils.py](../../代码存档/决赛_track蒸馏_162404/agent_ppo/feature/nav_observation_utils.py)。

这些增强的目的不是让图像“更好看”，而是扩大训练输入分布，使学生不要依赖仿真中特别干净的深度图。

视觉增强由 `getattr(env, "_is_training", True)` 控制，但当前仓库没有其他代码明确把 `_is_training` 在评估时设为 `False`。如果外部运行时也没有设置，评估仍会随机执行 dropout、噪声和图像抖动。正式评估前必须把训练/评估开关改成显式配置，并验证同一输入在评估模式下得到确定性的 depth tensor。

### 9.2 相机外参

相机安装位置和姿态决定每个像素看到哪里：

```text
offset_pos = [x前, y左, z上]
offset_rot = quaternion(w,x,y,z)
```

每台真机安装都可能存在毫米和角度误差。首次部署、移动相机或更换支架后必须重新测量。最终训练应使用目标机器狗的实际安装参数，而不是一直使用示例值。

### 9.3 内参重投影，不是 resize

真机 RealSense 与仿真相机的焦距、主点和视场角不同。直接 resize 只改变像素数量，不会对齐每个像素对应的光线方向。

正确流程是：

```text
目标仿真像素
→ 根据仿真内参反算相机光线
→ 用真实相机内参投影到 RealSense 原图
→ 采样真实深度
→ 处理无效值
→ 输出 180×320×1、[0,1]
```

规则中的具体内参和重投影要求见 [部署指南 A.6](../../规则说明/开发指南/部署指南.md)。

### 9.4 训练和真机命令分布

`proprio[6:9]` 是速度命令。Teacher 训练、LBC 采样和真机运行如果使用完全不同的速度范围，Student 会进入训练中没见过的状态。

需要固定或覆盖式随机化：

- 前进速度范围；
- 转向速度范围；
- 速度变化频率；
- UWB/高层导航的命令平滑；
- 真机安全速度上限。

### 9.5 控制周期与延迟

官方运行频率为 50Hz，即每 20ms 产生一次关节目标。深度重投影、ONNX 推理和控制代码的总耗时必须小于一个周期，并预留抖动余量。

## 10. 如何阅读训练指标

### 10.1 行为蒸馏指标

| 指标 | 含义 | 理想方向 |
| --- | --- | --- |
| `action_mse` | Student 与 Teacher 12 维动作平方误差 | 越小越好 |
| `action_l2` | 动作向量平均距离 | 越小越好 |
| `action_cos` | 动作方向相似度 | 越接近 1 越好 |
| `grad_norm` | 本次参数更新梯度大小 | 不能长期为 0 或爆炸 |

低 action MSE 仍不能代替闭环评估，因为很小的连续偏差也可能让机器人逐步走出 Teacher 的状态分布。

### 10.2 LBC 指标

| 指标 | 含义 | 理想方向 |
| --- | --- | --- |
| `mse_loss` | Student/Teacher latent 平方距离 | 越小越好 |
| `cos_sim` | 两个 latent 的方向相似度 | 越接近 1 越好 |
| `angle_deg` | 两个单位 latent 的夹角 | 越接近 0 越好 |
| `student_std` | Student latent 在 batch 内的变化 | 不能塌缩到常量 |
| `teacher_std` | Teacher latent 的变化基线 | 用于对比 |

两侧 latent 都经过 L2Norm，因此平方距离与 cosine 强相关：

```text
||z_s-z_t||² = 2(1-cos(z_s,z_t))
```

### 10.3 闭环指标比 loss 更重要

最终必须看：

```text
Track 完成率
摔倒率
完成时间
姿态稳定性
能耗
失败所在子地形
动作平滑度
```

“训练 loss 很低”只能证明网络在采样数据上拟合得好，不能证明机器狗能依靠自己的动作持续走完整条赛道。

可以先使用以下工程建议作为阶段门槛，它们不是官方评分线：

| 阶段 | 建议门槛 |
| --- | --- |
| 行为蒸馏 | action MSE `≤1e-3`，cosine `≥0.99` |
| Encoder Teacher 闭环 | 完成率不低于 flat Teacher 的 95%，绝对下降不超过 5 个百分点 |
| LBC latent | cosine `≥0.985`，平均夹角约 `≤10°` |
| Vision Student 闭环 | 完成率相对 Encoder Teacher 下降不超过 5 个百分点 |
| ONNX 多帧对拍 | action 最大绝对误差 `≤1e-4` |
| Jetson | 深度预处理加推理 p99 `<20ms`，建议目标 `<15ms` |

## 11. Checkpoint 是什么，三个阶段分别保存什么

Checkpoint 是某个训练时刻的模型参数和可选训练状态。

### 11.1 复赛 flat checkpoint

主要保存：

```text
actor.*
critic.*
std/log_std
```

它没有 `encoder.*`，因此不能直接作为官方 LBC Teacher。

### 11.2 Encoder Teacher checkpoint

应该包含：

```text
encoder.*
actor.*
critic.*
```

LBC 加载时会拆出 `encoder.*` 作为 Teacher Encoder，拆出 `actor.*` 作为 Teacher Actor；Critic 和探索标准差不参与视觉蒸馏。

### 11.3 LBC checkpoint

应该至少包含：

```text
format = "lbc_loco"
vision_encoder_state_dict
teacher_actor_state_dict
```

训练续跑通常还会保存：

```text
teacher_encoder_state_dict
optimizer_state_dict
current_iteration
total_steps
learning_rate
goal_dim
```

真机部署只需要 VisionEncoder 和 Teacher Actor，但 exporter 会检查 checkpoint 格式和 key 前缀。

## 12. 当前模型结构是否需要优化

### 12.1 当前基线并不大

按代码静态计算：

```text
SimpleCNN              ≈ 650,272 参数
完整 VisionEncoder     ≈ 722,240 参数
Standard Actor77       ≈ 205,708 参数
Track Actor80          ≈ 207,244 参数
Track 部署模型总计     ≈ 929,484 参数
```

这不是一个需要立即压缩的大模型。是否满足 50Hz 必须在 Jetson 上测量，而不是仅凭参数量判断。

### 12.2 优化顺序

正确顺序应当是：

1. 先确认相机几何和深度值域正确；
2. 再确认 Encoder Teacher 可靠；
3. 再确认 LBC latent 和 action 对齐；
4. 再确认 Student 闭环成功；
5. 最后根据明确瓶颈改网络。

### 12.3 什么情况下才改网络

| 现象 | 优先尝试 |
| --- | --- |
| loss 高、深度图明显错位 | 修标定/预处理，不先加网络 |
| latent 好但动作偏差大 | 加 action consistency loss |
| Teacher-drive 好、Student-drive 差 | DAgger 式 Student 状态采样 |
| 深度空洞/遮挡时不稳定 | 短序列 TBPTT 或更明确的时序训练 |
| 视觉表达确实不足 | 再评估 ResNetEncoder |
| Jetson 延迟超标 | 轻量卷积、自适应池化、减少大 FC |

当前 LSTM 每次 forward 后都会立即 detach hidden。这意味着 hidden/cell 的数值会跨帧保留，但梯度不会跨越任何相邻帧边界，实际是长度 1 的截断训练。如果闭环测试证明跨帧遮挡是主要问题，可以使用短序列 TBPTT；不要仅仅增加 LSTM 层数。

当前 SimpleCNN 使用固定分辨率 Flatten+Linear。如果未来改变图像分辨率或需要更强空间鲁棒性，可考虑自适应池化或轻量残差结构；这会改变 checkpoint 和 exporter，必须重训和重新对拍。

## 17. 递进式动手练习

### 练习 1：建立 shape 台账

在纸上重新写出 Standard、flat Track、Encoder Track、Track LBC 和真机五条路径。验收条件：所有拼接维度能手算正确。

### 练习 2：手算权重 shape

回答：

```text
Linear(304,512) 的 weight shape 是什么？
Track 比 Standard 多多少个首层参数？
Linear(80,512) 为什么不能直接复制旧权重前 80 列？
```

答案：`[512,304]`；新增 `512×3=1536` 个 Actor 首层权重；因为旧 scan 列和新 latent 列语义不同。

### 练习 3：跟踪一帧数据

从 `obs304` 开始，在代码中标出 proprio、scan、goal 的 slice，然后跟到 `action12`。再对 Track LBC 的 57904 维容器重复一次。

### 练习 4：最小教师学生实验

安装 PyTorch 后，用一个固定小 MLP 当 Teacher、另一个 MLP 当 Student，最小化二者输出 MSE。确认 Teacher 梯度始终为空，Student loss 持续下降。

### 练习 5：Dummy latent forward

构造随机 `scan[B,256]` 和 `depth[B,180,320,1]`，分别运行 DmEncoder 和 VisionEncoder。确认都输出 `[B,32]`，且每个输出的 L2 norm 接近 1。

### 练习 6：深度扰动可视化

对同一深度图分别添加 dropout、比例噪声、roll 和 pitch 偏移，观察输入如何变化。理解 domain randomization 改的是 Student 输入分布，不是 Actor。

### 练习 7：Teacher/Student 动作对比

让 teacher latent 和 student latent 经过同一个 Actor，记录 action MSE。理解 latent 指标与真实控制误差之间的关系。

### 练习 8：设计闭环实验表

先不运行仿真，建立包含 seed、地形、命令、完成率、摔倒率、用时、姿态、能耗和失败位置的实验表。

### 练习 9：多帧 LSTM 对拍

连续输入至少 8 帧，逐帧回灌 `h/c`，比较 PyTorch wrapper 与 ONNX。单帧一致不能作为验收。

## 21. 最后记住的五句话

1. 深度图不是更大的 height scan，不能直接换输入。
2. 决赛的 32 维 latent 是 Teacher 和 Student 之间的共同接口。
3. 先得到可靠 Encoder Teacher，再训练 Vision Student。
4. 蒸馏只证明 Student 在模仿 Teacher，闭环评估才证明机器人能走。
5. 相机标定、重投影、LSTM 状态、ONNX 对拍和真机安全都是模型的一部分，而不是训练结束后的附属工作。
