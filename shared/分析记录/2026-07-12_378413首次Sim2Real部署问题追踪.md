## 3. 首次发现的问题：goal 格式错误

远端原配置为：

```yaml
goal: [0.0, 0.0, 10.0, 0.0]
```

但训练 goal3 的定义是：

```text
[local_x / 10, local_y / 10, planar_distance / 20]
```

第三维训练范围为 `[0,1]`，原值 `10` 严重越界。ONNX 数值对照也证明 goal 会显著改变关节动作，因此不能把它当成占位输入。

本次改为“当前机体正前方 1m”的合法固定观测：

```yaml
goal: [0.1, 0.0, 0.05, 0.0]
```

计算：

```text
1 / 10 = 0.1
0 / 10 = 0
1 / 20 = 0.05
```

远端旧配置备份：

```text
config/config.yaml.before_goal_1m_20260712_150745
```

本地部署源配置也已同步修改。

## 5. 相机断连问题与恢复

首次测试时 D435i 连接松动，RealSense pipeline 停止，日志重复出现：

```text
try_wait_for_frames cannot be called before start()
```

约产生 517 万条相同错误和约 584MB `console.log`。

重新插紧后已确认：

```text
设备：Intel RealSense D435I
序列号：338622073957
固件：5.13.0.55
```

部署预检恢复通过：

```text
Preflight: network=eth0, source=fixed, depth=realsense
Fixed command: [0.15, 0.0, 0.0]
Preflight passed. No controller was started.
```

当前代码不能可靠地在运行中恢复相机热插拔。相机断连后的操作应是：

```text
LT+B进入Passive
Ctrl+C退出控制器
重新插紧D435i
rs-enumerate-devices -s
重新执行--check
重新启动控制器
```

## 7. 尚未关闭的部署 Gap

1. RealSense 没有首帧 readiness、帧时间戳和陈旧帧 watchdog。
2. 相机断流后不会自动进入 Passive，且异常日志没有限频。
3. 训练 `ang_vel` scale 是 `0.2`，远端活动 `deploy.yaml` 当前是 `0.25`。
4. 动作 clip 为 `[-100,100]`，不是真实 Go2 逐关节软限位。
5. 没有动作目标变化率和关节跟踪误差实时联锁。
6. 真机相机安装外参仍需与训练外参做现场确认。
7. 本地导出器/ONNX 尚未完整同步为 Jetson 当前 Actor80 版本，重新整包同步可能覆盖远端正确产物。
8. UWB 原始 goal 尚未转换成训练使用的归一化 goal3。

## 8. 阶段结论

> `378413` 的固定速度视觉运控链路已在真机初步跑通，但当前成果是“能正常行走”的部署基线，不等于相机断流安全、精确目标跟踪和正式 Track 闭环已经完成。
