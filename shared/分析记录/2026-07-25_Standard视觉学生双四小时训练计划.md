## 1. 决策

原 `standard-visual-r3` 单次八小时方案由本卡取代。训练拆成两个互相验收的四小时
任务：

1. `standard-anchor-r2` 只完成视觉学生的 anchor 退火和稳定训练；
2. 只有任务一通过固定评估后，才从其最佳 checkpoint 启动
   `standard-command-r1`，只完成 command 域泛化。

拆分的主要原因不是总训练时长，而是避免把以下变化放进同一个不可中途评估的任务：

- Actor/LSTM 解冻与 anchor 权重下降；
- 零速、低速、转向和横移 command 的引入；
- 平台会恢复自身 `isaac_env/base_env.py`，因此本地对 reset 生命周期和地形难度的
  修改不能作为可靠训练前提。

两个任务合计仍为八小时，但任务二是否启动由任务一的实际模型评估决定。任何任务都
不默认采用最后一个 checkpoint。

**新增最高优先级流程约束**：评估入口选择必须先闭环验证。`597491` 日志显示 Camera
任务实际回退到 `lbc_loco`，主进程和环境子进程均未使用视觉学生入口；因此该轮结果不
能用于判断模型、timeout、地形或 command 训练效果。入口修复、容器源码/配置回读和两条
进程链日志核验完成前，任务一与任务二都只保留为计划，不得创建正式长训任务。

## 3. 平台 `base_env.py` 边界

本方案不修改、不上传且不依赖本地 `server/isaac_env/base_env.py`。平台启动时会恢复
自己的该文件，本地副本只能作为阅读和兼容参考，不能承载本轮必须生效的功能。

这带来以下明确边界：

- 不承诺在每次 reset 前严格均匀重分配 0--9 难度；
- 不在 auto-reset 后强行改写 `terrain_levels`、`env_origins` 或机器人根状态；
- 不用本地 `base_env.py` 修改来消除平台自身的 `reached max length` 日志；
- episode timeout 仍按 PPO truncation 处理并做 value bootstrap，不计为 hard
  termination；
- command scheduler、checkpoint 调度、模块冻结和训练时钟全部放在不会被平台覆盖的
  `agent_ppo` 路径；
- 只在 worker 侧记录 level histogram 和 terrain × level 样本数，不借日志宣称分布
  已被主动控制。

严格均匀难度 reset 若再次成为硬要求，必须先取得平台保留的 pre-reset hook。拆成两个
任务本身不能解决这个生命周期限制。

## 5. 任务一：`standard-anchor-r2`

详细的逐文件实施、历史配置清理、测试和平台短启动要求见
[Standard Anchor R2 四小时实施计划](./2026-07-25_StandardAnchorR2四小时实施计划.md)。

### 5.1 唯一目标

从 `model.ckpt-visionfull-28401.pkl` 重新开始，在完全保持 S0 地形和 command 域的
条件下，完成视觉学生的分段解冻和 anchor 退火。视觉学生始终独立执行动作；冻结 S0
只计算 action/latent anchor，不参与环境动作选择。

不得继承 `29611` 及其后续 checkpoint 的 Critic、optimizer、训练时钟或安全状态。
首次加载精确优先 `visionfull-28401`，不使用 `latest`。

### 5.2 四小时时程

| 墙钟时间 | 可训练模块 | Action anchor | Latent anchor | 标签 |
|---|---|---:|---:|---|
| 0--45 分钟 | Critic | `1.00` | `0.25` | `anchorcritic` |
| 45--90 分钟 | Actor + Critic，LSTM 冻结 | `1.00 → 0.75` | `0.25` | `anchoractor` |
| 90--180 分钟 | Actor + LSTM + Critic | `0.75 → 0.35` | `0.25 → 0.10` | `anchoranneal` |
| 180--240 分钟 | Actor + LSTM + Critic | `0.35` | `0.10` | `anchorfinal` |

学习率：

```text
Critic：0--45 分钟 3e-4，之后 1e-4
Actor：1e-5
LSTM：5e-6
```

四小时内全程使用 S0 原始 command 域，不启用 zero/low/yaw/lateral bucket，也不修改
地形比例、课程、侧墙或奖励。独立保存 `anchor_session_elapsed_hours`；中断恢复时只有
同一 `schedule_mode=visual_anchor_anneal_v2` 的 bundle 才能续接该时钟。

## 6. 任务二：`standard-command-r1`

### 6.1 启动条件与恢复语义

任务二只从任务一固定评估选出的最佳 checkpoint 启动，不能默认读取
`anchorfinal` 或目录中的 `latest`。

跨任务使用 `transition_resume`：恢复 VisionEncoder 的 LSTM、Actor、Critic、动作
标准差、optimizer 和 RNG；保留 action/latent anchor `0.35/0.10`，但重置 command
session clock、command bucket 计时、安全窗口和 live LSTM hidden。任务二使用独立：

```text
schedule_mode = visual_command_generalization_v1
command_session_elapsed_hours
```

### 6.2 四小时 command 混合

地形、课程、侧墙、奖励、相机和可训练模块保持任务一不变。每个环境只在当前 command
到期时独立决定 source 或 target profile，不在保持期间强制改写。

| 墙钟时间 | Target 概率 | Source 概率 |
|---|---:|---:|
| 0--30 分钟 | `0%` | `100%` |
| 30--180 分钟 | 线性 `0% → 100%` | 线性 `100% → 0%` |
| 180--240 分钟 | `100%` | `0%` |

线性段的核对点：

```text
30 min: 0%
60 min: 20%
90 min: 40%
120 min: 60%
150 min: 80%
180 min: 100%
```

`source profile` 完全等于 S0 原始 command 域。`target profile` 为：

| Bucket | 权重 | 采样与保持 |
|---|---:|---|
| zero | 15% | `vx=vy=wz=0`，保持 `U(1.5,3.0)` 秒 |
| low forward | 20% | `vx=U(0.10,0.30)`，保持 `U(3.0,6.0)` 秒 |
| normal forward | 35% | `vx=U(0.30,0.80)`，保持 `U(3.0,6.0)` 秒 |
| forward + yaw | 20% | `vx=U(0.15,0.55)`，`wz=±U(0.15,0.30)`，保持 `U(3.0,6.0)` 秒 |
| lateral | 10% | `vy=±U(0.10,0.20)`，保持 `U(3.0,6.0)` 秒 |

全局 command limit 使用两套 profile 的并集：

```text
vx = [0.0, 1.3]
vy = [-0.2, 0.2]
wz = [-0.3, 0.3]
```

S0 anchor 只按样本调整监督权重，不改变 PPO 执行：

```text
source 或 target 中 vx >= 0.3：1.0
low-forward：0.25
zero / pure-lateral：0.0
```

### 6.3 保存与验收

每约 10 分钟保存，并在 30、90、180、240 分钟额外保存：

```text
model.ckpt-commandbase-<平台ID>.pkl
model.ckpt-commandblend-<平台ID>.pkl
model.ckpt-commandfull-<平台ID>.pkl
```

checkpoint 至少增加并恢复：

```text

command_target_probability
command_profile_mix_history
transition_parent_platform_model_id
```

评估 90、150、180、210 和 240 分钟附近候选，不默认选最后一个。最终放行条件：

```text

上楼总分和前进距离相对 28401 各下降 <= 3 分，且前进距离 >= 90
下楼与坡面总分相对 28401 各下降 <= 3 分
hard termination 相对 28401 增加 <= 1 个百分点
16 环境、20 秒零指令：平均平面速度 < 0.08 m/s，且无摔倒
```

没有候选同时通过楼梯和零速验收时，正式候选回退到任务一最佳点；不得进入步态
纠正、随机化或真机部署。

## 7. 必须实现的代码边界

### 7.0 P0 入口闭环（优先于所有训练改动）

任务一和任务二共用同一评估入口验收：

- 最终评估配置显式指定 `env_conf.policy_entry = "visual_policy_optimization"`；
- 主进程与平台环境子进程都必须打印显式入口选择和
  `Stage: visual_policy_optimization`；
- 容器回读 `conf.py`、`agent.py` 和最终生效 TOML 的 SHA256；
- 出现 `inferred from TOML task_name`、`Stage: lbc_loco` 或 `[LBC-Loco]` 时，结果只
  标为无效诊断数据，不得用于晋级或宣称训练成功；
- 不修改或依赖平台覆盖的 `base_env.py`，入口兼容函数留在 `agent_ppo.conf.conf`。

同步客户端的成功响应不构成入口生效证据；必须以容器回读和启动日志为准。

启动任务一前必须完成并静态核验：

1. 任务一只启用 `visual_anchor_anneal_v2`；
2. `anchor_session_elapsed_hours` 与累计训练时钟分离，保存和恢复不串线；
3. S0、同 mode resume 和其他 schedule migration 的恢复语义明确；
4. 原生 command 由活动 TOML 固定，不在任务一实现 progressive scheduler；
5. `base_env.py` 与操作者提供的平台版本 SHA256 一致，活动代码不依赖其自定义修改；
6. 启动日志打印实际 checkpoint 路径、平台 ID、SHA256、command 配置、depth 开关和
   Anchor 状态；
7. 10 分钟墙钟保存和中断恢复通过 round-trip 测试。

`visual_command_generalization_v1`、command 独立时钟、source/target telemetry 与
`transition_resume` 属于任务二，在任务一通过评估后另行实现，不能为了复用而提前耦合。

当前 `codex/anchor-r2` 已完成任务一的本地静态改造；在 Torch 张量测试和一次短平台启动
完成前，仍不得把本卡状态改为“可开始四小时长训”。
