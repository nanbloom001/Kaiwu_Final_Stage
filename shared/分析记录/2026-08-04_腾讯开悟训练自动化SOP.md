# 腾讯开悟训练自动化 SOP

> 来源：P2-P4 容器同步、联合 smoke、任务创建和长训监控的实际问题。
> 用途：下次训练优先按本文的最短路径执行，再查 Bug 台账中的完整证据。

## 1. 先固定任务身份

每次开始时先记录：

```text
权威本地 worktree
当前分支和 commit
父模型名称、平台 ID、checkpoint SHA256
任务名、task ID、UUID、监控 URL
有效训练时长和平台墙钟时长
```

- 不从旧绝对路径导入同步或上传工具。先用 `rg --files` 和
  `git log --all -- <path>` 确认工具实际所在分支。
- 模型 ID 只用于选择和 lineage；文件、模块、spec、shape 和有限值兼容才是硬条件。
- 平台运行的是创建任务时冻结的代码。后续 Git 提交不会热更新已运行任务。

## 2. 容器同步和模型上传

- 非模型文件统一用 RPC 同步和执行。
- 模型 ZIP、checkpoint 和权重优先用 WebIDE VSCode Remote 文件通道；RPC
  分片只是明确的 fallback。
- 模型临时文件限制在 `agent_ppo/test_artifacts/`，禁止扩大到项目根目录、
  `conf/`、`.env` 或源码目录。
- 上传后同时校验 ZIP 和内部 checkpoint SHA256，再解压和移动。
- 同步服务 `/health` 需要鉴权。HTTP 401 只说明未授权，不等于端口未监听。
  PTY 回显中的 marker 也不能当作执行结果；只解析独立的结果行。

标准同步顺序：

```bash
cd server
python3 local_sync_client.py --check-local
python3 local_sync_client.py --dry-run --skip-unchanged
python3 local_sync_client.py --skip-unchanged
python3 container_rpc_client.py --cwd . "pwd"
```

## 3. 开发容器最小验证

默认不再运行 128-env 重型 smoke。除非网络、storage、观测 shape、相机数量
或环境数发生变化，否则最小验证为：

1. 定向 pytest、Python 编译、TOML 解析和 `git diff --check`。
2. 1-env Isaac reset/step，仅在环境或传感器装配变化时运行。
3. 8-env 真实父包联合 smoke：32-tick 高层 rollout、PPO update、Adapter
   update、save 和 fresh-process resume。
4. 核对低层 digest、optimizer step、非有限值、reward conservation、峰值显存和
   pinned storage。

容器测试必须使用：

```bash
PYTHONDONTWRITEBYTECODE=1 pytest -p no:cacheprovider ...
```

避免在快照工作区生成 `__pycache__` 和 `.pytest_cache`。容器测试时，约每 5 分钟
在 Chrome 中滚动或切换 WebIDE 页面一次防止开发容器被回收。正式平台训练不依赖
该页面保活。

## 4. 创建训练任务前清理

先 dry-run：

```bash
python3 conf/container_training_cleanup.py
```

确认清单仅包含可再生文件后：

```bash
python3 conf/container_training_cleanup.py --apply
```

已完成全部容器测试且确实需要压缩快照时，才可使用：

```bash
python3 conf/container_training_cleanup.py --apply --remove-dev-files
```

可清理：

```text
__pycache__ / pytest、mypy、ruff cache
agent_ppo/test_artifacts
.ide-sync-*.tar.gz / *.sync-tmp
/tmp/IsaacLab 和 smoke 日志
测试完成后的容器副本 .git、.vscode、tests、tools
```

不可清理：

```text
conf/.env、Token、Cookie 和同步启动配置
平台 kaiwudrl/tools/isaac_env
测试尚需使用的父模型
正式训练源码和已发布模型
```

`CreateTrainTask` 返回通用 500 时的最短路径：

```text
CreateTrainTask 响应正文
-> CheckTrainTask / GetResourceBalance
-> 父模型状态
-> local/remote manifest 差集
-> cache 和 test_artifacts 数量
-> TOML 生成错误
```

不要在 learner/aisrv 尚未启动时就归因为 checkpoint loader 或模型 ID 门禁。

## 5. 任务创建和启动验证

- 首先创建 1-5 分钟的有界 smoke，验证表单、父模型和停止链路。
- 正式任务启动后立即核对 stage、环境数、terrain、课程、父模型和 worker wire。
- 检查 5 分钟首存、10 分钟周期保存、模型列表登记和最终保存。
- 墙钟 `save_model()` 不能代替平台 lifecycle heartbeat。每个成功的环境 step 必须走平台
  所需的 learn callback，否则可能在约 15 分钟被外部 SIGTERM。
- 运行代码的 logger 不假定平台支持 printf 参数转发；调用前生成完整字符串。

## 6. 有效时间和阶段切换

- 诊断、baseline 或 shadow 阶段如果不计入 `session_effective_seconds`，平台墙钟必须另加
  该时间以及 rollout/checkpoint/exit 余量。
- 不根据页面墙钟猜阶段。同时查看 `session_effective_seconds`、阶段 one-hot 和实际
  optimizer LR。
- 阶段仅在干净 rollout 边界切换。切换后至少观察 5-6 个独立 rollout，不用
  单个点判断漂移。

## 7. 监控接口和漂移判断

- 使用 Chrome 已登录会话读取平台指标 API，不仅依赖截图。
- 平台请求签名会过期。出现 `HOST_TIMESTAMP_OUT_OF_RANGE` 时重新加载页面并捕获
  新请求；不复用旧请求头，不打印 Cookie、Token 或签名。
- 每个 line 面板不超过 20 个指标。高频分桶和 quantile 在 GPU/窗口聚合后只上报
  最终标量。

只有以下信号成组出现才考虑中断或热修复：

```text
KL 持续上升且超过约 0.03
clip fraction 持续显著超过 0.20-0.25
actor/critic loss 同步恶化
路线效率、进度、碰撞和卡滞同时恶化
低层 digest 漂移或冻结 optimizer 意外 step
reward conservation 非零
显存持续增长、非有限值或 lifecycle 失败
```

单轮行为指标变差不是重启依据。训练链稳定也不等于导航能力、评估或真机已验证。

## 8. 任务结束与证据落档

- 停止或结束前确认没有遗留的同步、上传、smoke 和 `sleep` 会话。
- 按层级记录：本地、容器、平台 smoke、平台长训、评估、真机。
- 在 Bug 台账中记录任务身份、commit、父模型、SHA256、关键指标、未验证项和回滚方法。
- Chrome 监控页作为 handoff 保留；中间搜索、重复或无关页面关闭。

## 9. 本轮问题与最快解法

| 症状 | 实际原因 | 最快解法 |
|---|---|---|
| 本地判断 WebIDE 上传模块不存在 | 查了旧 worktree 绝对路径 | `rg` 全 worktree，再用 `git log --all -- <path>` |
| 同步服务被误判为未启动 | `/health` 未带 Token 返回 401 | 区分 TCP 可达和业务鉴权；用已鉴权 RPC 执行 `pwd` |
| 自举脚本同时显示 started/already-running | PTY 回显命中 marker 被子串命中 | 只解析独立结果行 |
| 任务创建通用 500 | 容器快照包含历史源码、测试模型、分片或 cache | 先运行安全清理脚本，再查 manifest 差集 |
| 清理后仍创建失败 | TOML 生成缺值或平台短暂故障 | 先捕获 `CreateTrainTask` 正文，不继续删平台框架 |
| 任务约 15 分钟被 SIGTERM | 有 checkpoint，但没有平台 learn/lifecycle heartbeat | 每个有效 `env.step()` 完成后调用 lifecycle callback |
| 阶段迟迟不切换 | 把平台墙钟当成有效训练时间 | 读 `session_effective_seconds` 和阶段 one-hot |
| 监控 API 突然 403 | 请求时间戳/签名过期 | Chrome 重载后捕获新请求，不复用旧 header |
| 日志保留 `%s/%d` | 平台 logger 不支持预期的 printf 参数转发 | 调用 logger 前格式化完整字符串 |
| 切阶段后 KL 瞬时上升 | Actor LR 按合同提升 | 观察至少 5-6 个 rollout；只在 KL/clip/行为成组恶化时修复 |
