## 0. 相对 v1 的三处路线级修订

1. **训练路线**：MVP 不直接实现 5Hz categorical semi-MDP recurrent PPO。当前为 **路线 A：特权 Oracle 行为克隆 → DAgger**；DAgger 验收后的少量 PPO 微调是已排定的固定后续阶段，但不在本 MVP 分支实现。理由见 §3——本仓库有两次 DAgger 蒸馏成功先例（lbc_loco、behavior_distill），零次"从零写新 PPO 头"先例；MVP 阶段 PPO 代码量归零。
2. **部署形态**：默认方案从"独立 nav 线程"改为 **单控制线程、双 ONNX session**（§7 方案 A）。锁、原子变量、数据竞争、watchdog 线程全部消失；双线程降级为影子实测不达标时的后备。
3. **训练次序（用户决策）**：高层架构验证先行，低层步态修复居后——契约冻结 → S0 smoke → **DAgger 架构验证轮**（父=command-34728，standard+Camera+虚拟目标）→ B1 楼梯修复 → **DAgger 正式轮**（父=B1 新 ID，track 模式）。成立前提有二：`vision_encoder` 永久冻结**自即日起生效**（提前于 B1，锚定 cnn_feat 语义，B1 只准训 Actor77）；接口契约先于高层工作冻结（B1 不改指令域，词表锚点跨低层换代保持有效）。架构验证轮的策略权重是半消耗品（B1 后重训 DAgger，机件全复用），其验收标准是管线/包/eval/探针，不是导航分数。

## 2. 训练进程与状态归属

**原则：全部 nav 运行时状态归 aisrv 侧 workflow 进程内的单例 `NavScheduler`（per-env 张量）。worker 持有零 nav 状态（其 command sampler 是死值）；learner 不持有活状态，只消费 storage 里显式落库的序列。**

| 状态 | 持有者 | 说明 |
|---|---|---|
| nav LSTM hidden (h,c) | NavScheduler（rollout 副本） | 每 tick 前向后就地更新；TBPTT 序列首快照进 storage |
| categorical token（当前词表项） | NavScheduler.held_token [num_envs] int | 每 K 步更新一次 |
| held_cmd3（token 查表值） | NavScheduler | token 的确定性函数，随 token 更新 |
| exec_cmd3（slew 后执行值） | NavScheduler.exec [num_envs,3] | 每 50Hz 步演化；同帧写 obs[:,6:9] 与 critic_obs[:,9:12]——**policy 与 critic 看到同一个 exec_cmd3** |
| 驻留计时器 | NavScheduler.dwell [num_envs] int | 以 nav tick 计；实现为 logits 掩码（驻留未满时屏蔽切换动作） |

- **learner 重建 recurrent PPO 所需内容**（PPO 阶段才启用；DAgger MVP 无此需求）：storage 按 nav tick 存 `{obs48, seq 首 hidden(h,c), token(int), logits(或 log_prob), dwell 掩码, value, 聚合奖励, 有效折扣 γ^k, done 类型, mask}`。掩码必须入库——驻留约束以 masked categorical 实现，重算 log_prob 时不带掩码会算错重要性比。
- **环境 reset 同步清零**：done 信号经 `prepare_rollout_step(..., reset_mask)`（agent.py:624 签名已有此参数）到达；NavScheduler.reset(env_ids) 一次完成：nav hidden=0、held_token=zero、exec=0、dwell=0；低层 LSTM hidden 复用现行 per-env reset 机制。与部署侧 episode 起始清零（State_VisionLoco enter()）语义对齐。
- **K=10 窗口第 3 步摔倒**：该 nav 步 reward = r0+γr1+γ²r2；bootstrap 按终止类型三分——**hard termination（摔倒）**：不 bootstrap，return=聚合奖励；**goal success**：终止奖励计入聚合，不 bootstrap；**timeout（截断）**：bootstrap γ³·V(s3)。sequence mask 在该步截断，reset 后新窗口从头计。timeout≠摔倒在奖励与优势估计两处都显式区分。
- **resume**：**不恢复** per-env hidden/held token/exec/dwell，全环境强制 reset 开新 episode。理由：活状态与权重版本耦合、且跨 resume 的时钟/计数一致性历史上已出过多次问题——训练侧丢弃半截 episode 的成本趋近零，不值得为它引入状态迁移代码。训练计数（累计 env 步、nav 步）持久化在 `training_state` 单调恢复；墙钟保存节拍在 resume 时**重新起表**，不从持久化时刻续算。
- **如何避免三套 nav scheduler**：结构上只允许一个实现存在——`feature/nav_scheduler.py` 是唯一的 hold/slew/dwell 逻辑；worker 侧无 nav 代码可运行（cmd 死值 + curriculum=false + 无 cmd 奖励项）；learner 只见落库张量；部署 C++ 是契约镜像而非第二实现，用 golden-vector parity 测试钉住（Python 侧生成标准输入输出序列存 `shared/interfaces/`，C++ 测试逐帧回放比对）。

## 3. 三条训练路线比较（当前最大开发风险的处置）

| 维度 | A：Oracle BC → DAgger（PPO 为固定后续阶段） | B：直接 5Hz categorical semi-MDP recurrent PPO | C：复用 Gaussian PPO 出 cmd3 + 训练域投影 |
|---|---|---|---|
| 需改既有模块数 | **0 个 PPO 内部模块**（新增文件仿 lbc 系；predict/storage/update 全不动） | ≥4 处重写：predict 高斯读数（agent.py:671-672）、storage mu/sigma→logits+mask、update 半 MDP return/TBPTT、anchor 分支禁用（algorithm_visual_ppo.py:56-58,700-728） | 2 处：动作后处理投影 + anchor 禁用；PPO 内核不动 |
| 平台 smoke 风险 | **低**——workflow 形态与已过平台的 lbc_workflow 同构（envs+agents 单进程循环、无新采样协议） | 中高——新 workflow + 新 storage 布局 + rollout 长度整除性重配（feature/definition.py:357-360） | 低中 |
| 收敛风险 | **低**——监督学习，损失单调可见；Oracle 在手，失败可归因（Oracle 不好 vs 学不到） | 高——半 MDP recurrent PPO 全血缘无先例，错误以"不收敛"呈现，与奖励设计纠缠不可归因 | 中——连续头逐 tick 漂移，抖动/贴边风险靠奖励压 |
| command OOD 风险 | **构造性低**（token 词表） | 构造性低（token 词表） | 行为性中——clamp 边界骑行是学出来的行为，不是结构保证 |
| 复用现有 DAgger/checkpoint codec | **高**——algorithm_lbc 三路损失改成 token 交叉熵 + DAgger ramp 机制原样；vision bundle 编解码先例直接扩展 | 部分 | 高（PPO 侧） |
| 适配"版本管理困难、希望一次训练成功"的平台 | **最适配**——每阶段产物可独立验收，失败回滚半径小 | 最不适配——最大不确定性押在一次训练里 | 中 |

**结论：A 为 MVP 主路线。** 关键机制：Oracle 是用户侧规则策略 `feature/nav_oracle.py`，只消费 **critic_obs**（特权通道：真值 lin_vel[0:3]、height_scan[60:316]、goal3[316:319]、nav wall privilege[319:323]），输出词表 token；worker 侧 observation process 负责从 `nav_scanner` 导出前/左/右墙分数，前墙阻塞时 Oracle 朝更开阔侧确定性转向。学生 HighLevelPolicy 只看 48 维真实输入契约（§5），用交叉熵 + DAgger 线性 ramp（学生驱动 0→100%）。DAgger 完成后固定进入少量 PPO 微调（从 DAgger 热启动）；categorical storage/logits/TBPTT/K-step return 的实现风险仍被承认，因此在独立后续阶段实现，不与 MVP 耦合。

## 4. Phase B 拆分（低层强化，禁止一次做完）

**CNN 冻结决定（已定，即日生效）：`vision_encoder`（CNN+LSTM）自即日起永久冻结——在架构验证轮之前生效，而非"自 B1 起"。** 高层先行的次序把探针结论、cnn_feat 分接、高层全部验证成果锚定在当前 CNN 语义上；B1-B3 的 optimizer 只准含 Actor77（+critic），CNN 逐位不动则回头修步态不会使高层视觉输入漂移。理由补充：视觉能力来自 LBC 蒸馏且已真机验证，步态修复主要在动作侧。若 B1 证明 actor-only 修不动楼梯，解冻 encoder 是一个显式升级决定（须知代价：探针重跑、高层验证成果作废、此后每次低层迭代都改变 cnn_feat 语义）。

**执行次序（v2 修订 3）：B1/B2 在 DAgger 架构验证轮之后执行；B1 完成后跑 DAgger 正式轮。**

| 阶段 | 内容 | 奖励改动 | 冻结 | 时长 | 验收 |
|---|---|---|---|---|---|
| **B1 楼梯步态与失稳修复** | 保持 command-34728 指令域**不变**，只修楼梯：后腿外展、支撑不对称、偶发失稳 | 全部经 TOML 权重调整（feet_stumble/接触/姿态项加权，现行 visual_policy_optimization TOML 奖励清单内），**不写新奖励代码** | vision_encoder 永冻；只训 Actor77+critic | 一个 4h 档（平台先例节奏），最多两轮 | 固定 eval seed 集（TOML seed，≥3 seeds）；楼梯段成功率/姿态分/终止分布相对 34728 基线不降、楼梯项显著改善；平台视频抽查清单：后腿外展角、双支撑对称性、失稳恢复步数 |

## 6. UWB 训练-部署等价性（"公式相同"之外）

训练侧不得直接用真值 local goal 喂 Actor；必须经过**模拟测量链**（新增于 `feature/` 内，复用已存在的 `goal_noise.py` 作噪声层）：

```
真值 delta（仿真位置差，仅此一步用特权）
 → 换算 (beta, pitch, distance)：模拟 UWB 原始测量三元组
 → 安装外参：天线相对机体原点的杆臂偏移 + 安装朝向偏差（常值 per-episode 采样 + 小噪声）
 → 逐通道噪声：bearing σ（度级）、distance σ（分米级）、pitch σ —— 常数向真机标定对齐，标定前用保守上界
 → planar 投影：镜像 planar_distance_from_uwb（含 stop/slow 距离逻辑如适用）
 → body frame 变换：用带噪声的 heading（模拟 IMU yaw 漂移），不是真值 heading
 → 低通滤波：镜像 time_filter_alpha(dt, tau)，tau 取部署配置同值 → 引入与真机相同的滤波延迟
 → 5Hz sample-and-hold + 到达抖动（±jitter）
 → freshness 计算与丢帧模拟（§5 分布）
 → encode_track_goal 编码（/10, /20, clamp）→ goal4
```

- **invalid 与 reached 的区分**：环境终止判定用真值距离（0.6m，平台机制）；Actor 视角的"到达"=dist_norm 小且 freshness 高；"失效"=freshness 衰减（goal 值冻结在上次有效值，不清零——与部署 hold 行为一致，hold_timeout 后系统级降级接管）。两种状态在输入空间结构上分离，策略无需猜。
- Oracle/critic 继续用真值位置（合法、且应该用——这正是特权训练的价值）；只有 Actor 输入过测量链。
- 测量链常数（外参、噪声 σ、tau、stale/hold 时限）全部进接口契约作为**成对常数**（训练配置与 deploy config 同源），列入 parity 测试。

### 6.1 目标点供给与多样性（训练主场由 smoke 决定）

**track 链的顺序与并行难度轨道可配**：`[terrain.track]` 真正支持 `track_length`、`sub_terrains`顺序与 `num_parallel_tracks`。历史 TOML 中的 `[terrain.level_mix]` 没有任何运行时消费者，已删除，不得再声称其能加权难度谱。首轮使用 10 条原生并行 track 列，以 `terrain_types` 实测 histogram 验证 128 环境长期分布。首轮 256 环境平台 smoke 虽能训练，但 checkpoint/lifecycle 空窗过长；后续固定 128。因此**训练主场首选 track**（短迷宫链做课程 → 全链做正式轮），standard 为保底——由 S0 第一问裁决：

## 7. 最简真机运行方式

**推荐 A：一个控制线程、两个 ONNX session。** 结论先行：方案 A 若 p95 达标，B（双线程）的全部锁/原子/快照/竞争复杂度都是负资产；C（融合 ONNX）维持 v1 否决（频率纪律埋进图内 latch，静默失效不可检）。

- **推理时序**（现有 50Hz policy 线程内，1kHz FSM 不动）：每帧 `采样传感器 → loco session 推理 → 按时发布关节动作 → [若 frame%10==0] 在本帧剩余时隙跑 nav session → slew 步进 exec_cmd`。nav 结果从**下一帧**起生效（一帧确定性延迟，训练侧镜像同语义；本帧动作永不被 nav 阻塞）。
- **两套 LSTM state**：`loco_h/c`（现有）与 `nav_h/c[2,1,64]`（新增成员变量）同线程持有，**无锁**。
- **depth/UWB/proprio 快照**：单线程内即本地变量，v1 报告识别的两处数据竞争（robot 快照、last_exec_cmd_ 原子化）**整体消失**。
- **nav 超时**：帧内预算检查——若上一 nav 帧超出时隙（挤压了下一帧起点），本周期跳过 nav、held/exec 保持（瞬时降到 2.5Hz 无害）；连续 N 次超时或输出非有限 → command_source 内部切 uwb 巡航（同线程状态机一个枚举，无 watchdog 线程）。
- **command hold**：held/exec/dwell 就是该线程的三个变量，与训练 NavScheduler 逐帧同语义（golden-vector parity）。
- **低层帧是否被 nav 阻塞**：结构上不会——nav 在动作发布之后运行；唯一风险是 nav 超时挤压下一帧起点，由跳帧规则兜住。
- **影子模式**：同一代码路径加 `apply=false`——nav 照常推理，输出只写 CSV 不进 command_for_frame。单线程下约 **100 行**（对 v1 的 ~350 行是大幅简化），且影子期间实测的就是接管期间的真实时序。
- **Jetson 必测指标**（影子模式产出，接管前置门）：loco 推理 ms、nav 推理 ms（仅 nav 帧）、整帧 ms 的 p50/p95/max **分 nav 帧与非 nav 帧两组统计**、实际达成 Hz、nav 跳帧率、（接管后）cmd 切换率。阈值沿用 analyzer 现行标准（p95 20ms STOP / 15ms WARN、45/48Hz）。**nav 帧占 10%，恰好整段落进 p95——这是 A 方案唯一的硬未知数，也是影子模式必须先行的原因。** 不达标的缓解序：nav CNN 半分辨率（90×160，需训练侧同配）→ nav tick 降 2.5Hz → 最后才是方案 B。

## 8. 一个 checkpoint 与一个发布包

### 8.1 顶层结构（v2 冻结）

```
model.ckpt-nav<stage>-<平台注入ID>.pkl      # 标签纯小写；ID 完全来自 lifecycle callback，禁止由 iteration 推算
{
  "format": "kaiwu_train_v1",
  "platform_model_id": <ID>,
  "model_spec": { ..., "goal_dim": 0 },
  "modules": {
    "vision_encoder": {...},               # 与低层父逐位相同
    "low_level":      {...},               # 同上
    "high_level":     { "nav_lstm": ..., "nav_head": ..., "nav_critic": ...,
                        "vocab": [...10项固定顺序...], "input_layout_version": 2,
                        "nav_period_frames": 10, "dwell_ticks": ..., "slew_rates": [...],
                        "freshness_train_dist": {...} }
  },
  "optimizers": { "high_level_ppo": ... }, # DAgger 阶段为 high_level_dagger；键名按阶段，位置固定在 optimizers.*
  "training_state": { "cumulative_env_steps": ..., "cumulative_nav_steps": ..., "schedule_mode": ... },
  "lineage": { "source_parent_model_id": ..., "low_level_state_digest": "<sha256(state_dict级)>" },
  "capabilities": { "deployable": <bool>, "freshness_randomized": <bool>, ... }
}
```

**不入包**：live LSTM hidden（任何一层）、per-env 运行时状态、词表以外的派生缓存。保存按墙钟节拍（resume 后重新起表）。

### 8.2 四条加载分支（load_model 内显式判别，agent.py:862 扩展）

1. **首载低层父**（nav 任务引导）：`preload_model_id=<低层ID>`，包内无 `modules.high_level` → 内存构造 high_level 随机初始化 + 新建 optimizers.high_level_*；写 lineage.source_parent_model_id；当场计算并缓存 low_level_state_digest。
2. **首次保存**：单一 `nav<stage>` 文件；保存前重算 digest 比对缓存值，不符**硬失败**（低层被污染=事故，不是警告）。
3. **同 schedule resume**：包内有 high_level + 对应 optimizer → 全量恢复权重与优化器；活 hidden 不在包内 → 全环境 reset；training_state 计数单调续接，墙钟重起。
4. **换低层重训**：`preload_model_id=<新低层ID>` → 走分支 1（高层**从头重训**，不做跨包权重嫁接——平台单 preload 机制不支持双源，且 cnn_feat 语义已变，嫁接无意义）。

**门禁分级**：eval 身份不符 / 缺 high_level / 反序列化失败 → **硬停止**（第一次 inference 之前）；训练侧 lineage 差异（如父 ID 与预期不同）→ **只 warning**（训练允许换父，不设不必要硬门）。**任何情况下不生成 locomotion/localmotion/lbc-loco 同 ID 别名文件；每次保存有且只有一个 nav\* 文件。**

### 8.3 真机发布包

```
release/
  loco.onnx          # 从组合包 modules.{vision_encoder,low_level} 导出，与低层父逐位一致
  nav.onnx           # 从同一组合包 modules.high_level + 冻结 CNN 副本导出
  manifest.json      # { source_checkpoint_sha256, platform_model_id, lineage,
                     #   loco_onnx_sha256, nav_onnx_sha256, vocab, slew_rates, dwell,
                     #   input_layout_version, freshness_params, export_tool_version }
  deploy.yaml        # 运行时配置（command_source、超时阈值、降级参数）
  sha256sums.txt
```

加载器启动时校验 manifest：两个 ONNX 的 sha256 必须与 manifest 一致、且 manifest 声明二者出自同一 `source_checkpoint_sha256`——**用户物理上无法误配不同版本的 loco/nav**。`capabilities.deployable=false` 或 `freshness_randomized=false` 的 checkpoint，导出工具直接拒绝生成 release。

## 结语：五项明确回答

**1. 推荐的最小训练路线（按用户确定的高层先行次序）**：契约冻结（词表 10 项、48 维输入、freshness 分布、**encoder 永冻即日生效**）→ S0 smoke（**第一问：track+Camera 存在性**，另含 TOML 校验 + num_envs + eval 入口 + nav_scanner 盘点）→ **DAgger 架构验证轮**（父=command-34728；场地按 §6.1 裁决：track+Camera 过 smoke 则短链 track（真 goal），否则 standard+Camera+虚拟目标（迷宫 proportion 开启）；序列 = Oracle 空转轮 → BC → DAgger 爬坡 + 在线探针；验收=管线/包/eval/探针，**Oracle-only 迷宫完成率是必须门禁**）→ B1 楼梯修复（只训 Actor77，指令域不变）+ B2 驻留压测 → **DAgger 正式轮**（父=B1 新 ID；track 全链 + 10 条原生并行难度轨道 + 计分对齐，**此轮成绩才算数**；若 track+Camera 不存在则 standard 续训、成绩验证整体转真机侧）→ **PPO 微调（计划内固定阶段，用户决策 2026-07-26：不再条件触发）**——半 MDP categorical PPO，以 DAgger 产物热启动，奖励复用既有导航项 + 特权 critic + 对 DAgger 初始策略的 KL 约束防遗忘；验收基线 = Oracle 天花板与复赛 track 血缘的完成率，两者都必须超过。B3（wz 扩域）挂起待时间瓶颈证据。

**2. 推荐的最简部署路线**：单控制线程 + 双 ONNX session；nav 在动作发布后的时隙内每 10 帧一跑，超时跳帧；影子模式（~100 行，apply=false）先行实测 nav 帧 p95；达标后接管 = 同路径翻 apply 开关 + release bundle（manifest 绑定同源 checkpoint）。无新线程、无锁、无 watchdog 线程、无跨线程状态。

**3. 明确不做的复杂设计**：融合 ONNX（静默失效不可检）；独立 nav 线程与全套并发设施（除非影子实测否决方案 A）；MVP 阶段的半 MDP categorical PPO（**用户决策 2026-07-26：已从"条件触发"升格为 DAgger 之后的计划内固定阶段，但仍不在 MVP 分支内实现**）；连续/混合动作头；局部占据记忆（N2 失败才升级）；横移 token（B2/N0 验收后放行）；wz 扩域先行（B3 条件触发）；同 ID 别名文件；跨包高层权重嫁接；per-env 状态入 checkpoint。

**4. 仍需平台 smoke 才能确认**：nav TOML 过校验器；Camera 任务 num_envs/显存上限；weight=0 奖励项是否仍执行、goal 阈值可否 TOML 覆盖；nav eval 入口加载同 ID 组合包全链路；在线探针的指标导出通道（监控指标 vs ckpt 内嵌）。

**5. 只能先解决三个问题时**：① **S0 平台 smoke**（硬门 #6/#9/#10）——它不过，一切排期悬空，且它最便宜；② **B1 楼梯修复**——低层步态是全系统性能地板，且其验收产物（固定 seed 基线）是之后所有回归测试的参照系；③ **接口契约冻结 + NavScheduler/parity golden vectors**——高低层解耦、训练部署一致、C++ 镜像正确性全部悬挂在这一份契约上，它冻结得越早，并行开发（训练侧与部署侧）越早解锁。选这三件的共同理由：都在关键路径上、都不依赖任何未验证假设、且都为后续每一步降低不确定性。
