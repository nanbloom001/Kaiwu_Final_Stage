# 固定前方 1m 但未自动停车问题追踪

日期：2026-07-12  
前置结果：`378413` 已能使用 D435i 和固定 `0.15m/s` 命令在真机正常行走。  
问题：配置 goal 为正前方 1m 后，机器狗行走超过 10m 仍未自动停止。

## 1. 预期与实际

预期：机器狗向前行走约 1m 后停止。  
实际：只要保持 VisionLoco，机器狗会持续按照 `0.15m/s` 命令前进。

活动配置：

```yaml
command_source: fixed
fixed_cmd: [0.15, 0.0, 0.0]
goal: [0.1, 0.0, 0.05, 0.0]
```

## 2. 根因一：这是移动的虚拟目标

训练时 goal 会根据目标世界坐标和机器人当前位姿逐帧重算：

```text
delta_world = goal_world - robot_world
goal3 = [local_x/10, local_y/10, distance/20]
```

机器人接近目标时，训练观测中的距离会逐渐减小到 0。

当前 fixed 部署没有世界定位，也没有累计位移。每帧都重新传入同一个：

```text
goal=[0.1,0,0.05]
```

它的真实语义是：

> 无论已经走了多远，目标仍位于机器狗当前正前方 1m。

因此它是随机器狗一起移动的虚拟目标，不是出发时固定在地面前方 1m 的终点。

## 3. 根因二：fixed 分支没有停车逻辑

fixed 模式每帧直接使用：

```cpp
theory_cmd = fixed_cmd_;
```

并把 `vx` 限制在允许范围内。当前没有：

```text
累计行走距离
目标距离递减
到达阈值判断
定时清零速度
自动切换Passive
```

所以 `fixed_cmd=[0.15,0,0]` 会一直进入 `proprio[6:9]`。

## 4. goal 有作用，但不是停车开关

`378413` 的 Actor80 输入是：

```text
proprio45 + depth latent32 + goal3
```

goal 会影响关节动作，但部署控制器没有规定“goal 为 1m时只走 1m”。外部 fixed 速度持续要求前进，Actor 不负责计算真实剩余距离，也不会替部署控制器强制清零速度。

因此该现象不是 goal 未生效，而是缺少距离控制器。

## 5. 可选修复路线

### A. 定时停车，仅用于近似测试

理论时间：

```text
1m / 0.15m/s = 6.67s
```

考虑速度爬升，可先测试约 `7～7.5s` 后自动令速度为零。

建议配置：

```yaml
fixed_stop_after_s: 7.0
```

优点：实现简单，不依赖 UWB。  
缺点：受打滑、加速和步态跟踪误差影响，只能得到约 1m。

### B. 根据实测位移停车

记录进入 VisionLoco 时的起点，使用可靠定位累计平面位移，达到 1m 后清零速度。

优点：比定时准确。  
缺点：必须有可靠的 UWB、里程计或规则允许的定位来源。

### C. UWB闭环目标跟踪

UWB 模式已有接近目标减速、到达阈值停车和数据失效零速框架，适合正式 Track。

但切换前必须把 UWB 原始：

```text
[orientation, pitch, distance_m, yaw]
```

转换成 Actor 训练格式：

```text
[local_x/10, local_y/10, planar_distance/20]
```

当前不能直接把原始 UWB 四元组传入 Actor80。

## 6. 建议

- 仅验证“走约 1m 后停”：实现路线 A。
- 需要准确 1m：实现路线 B。
- 正式比赛目标跟踪：实现路线 C。
- 到达后应由部署控制器明确把速度清零，不能依赖固定 goal 自行产生停车行为。

## 7. 结论

> `[0.1,0,0.05]` 只表示模型每帧看到一个位于当前机体前方 1m 的目标；fixed 模式持续输入 `0.15m/s`，没有真实剩余距离和到达判定，所以走过 10m 仍不停符合当前代码逻辑。
