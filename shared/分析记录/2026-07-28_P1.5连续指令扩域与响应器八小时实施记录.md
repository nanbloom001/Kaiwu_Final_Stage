## 1. 训练边界

P1.5 使用 Standard + Camera、128 环境。CNN 始终冻结；0-7 小时联合训练低层
LSTM/Actor/Critic/action distribution 与 ResponseAdapter，7-8 小时冻结全部低层参数，
只更新 Adapter。阶段按 monotonic wall clock 推进，不使用完成率、摔倒率或 loss 门禁，
业务代码不主动提前结束八小时任务。

## 2. Command 课程

worker 每 10 个 50 Hz frame 更新一次 `active_target_cmd3`，每帧按
`vx/vy=0.30 m/s^2`、`wz=1.00 rad/s^2` 生成 `exec_cmd3`。课程边界为
0.5/1.25/2/7 小时；2-7 小时主能力是 `vx=[0,1.0]`、`wz=[-0.8,0.8]`，
`vy` 只占 5% 专项，并持续保留 25% 父域回放及少量 `vx=1.0-1.3` 防遗忘样本。

family 目标比例为 joint/straight/pure-yaw/transition/lateral = 65/12/12/6/5；
trajectory 比例为 smooth/step/hold = 50/30/20。joint 事件在 vx-only、wz-only、both
三类之间均衡，并分别对 vx bin、|wz| bin 和左右方向分层。smooth target 每次实际改变
都会推进 epoch，因此 0.2/0.6/1.0 秒 future label 不会跨 target 变化误训练。

## 3. 数据与梯度隔离

```text
worker policy obs     = 57901
worker privileged wire = critic316 | response_aux30 = 346
aisrv PPO critic/storage = 316
Adapter buffer          = response_aux30 only
```

`train_workflow` 在 reset 与每个成功 step 后立即拆 wire；30 维 aux 不进入 Critic、
PPO transition 或 minibatch。低层 PPO 与 Adapter 使用独立 optimizer、scheduler、RNG、
backward 和 gradient counters；optimizer 参数集合只在启动 preflight 验证。

## 4. ResponseAdapter

网络固定为 `response_observation32 -> MLP64 -> GRU64 -> response_profile16`。
输入使用 `active_target_cmd3`，输出包含三个未来速度、1 秒位姿、stuck logit 和
1 秒速度 XYZ log sigma。loss 权重为 velocity 1.0、pose 0.5、stuck 0.25、NLL 0.1；
velocity horizon 权重为 1.0/0.75/0.5，log sigma clamp 到 `[-4,1]`。目标或 episode
在 horizon 内改变即 mask；rollout 为 80 帧，每个低层版本独立形成最长 50 帧标签，版本
切换时清空未完成 history。GRU 使用 8 帧 burn-in，并按 episode reset mask 对单个环境清零
hidden。每条记录保存 low-level digest、iteration、command phase 和 terrain 元数据。验收
同时报告各 horizon MAE、1 秒 NLL、zero baseline 与 copy-exec baseline。

## 5. 随机化与步态保持

FeedbackEmulator 的短时 `measured_velocity3` 固定为 SportMode `vx/vy` 与 IMU gyro `wz`，
模拟更新频率、延迟、噪声、bias、dropout、连续失效和 freshness。UWB 不进入 tracking
error 或 0.2/0.6/1.0 秒 Adapter 输入，只保留为未来独立 3-5 秒卡滞证据。实际 TOML
profile、配置 digest 与 `FeedbackEmulator` 源文件 SHA256 写入 checkpoint。

环境数在首次平台启动后由 256 调整为 128：P1.5 必须保留 80 帧 rollout，才能在同一
低层版本内容纳 50 帧 future label、8 帧 burn-in 和训练序列。原配置的批量帧预算为
`256x80=20480`，高于父阶段已验证的 `256x48=12288`，环境 reset 时 CUDA 异步错误最终
暴露在 ray-caster 初始化。`128x80=10240` 低于父阶段预算，并且不改变命令、反馈、地形、
相机或模型合同。

模型发布采用单一 10 分钟墙钟节奏：fresh start 与 resume 的首存均为第 10 分钟，之后
每 10 分钟保存一次。课程边界不再另行触发 checkpoint，避免 30/75/120/420/470 分钟
里程碑把实际间隔压缩到 5-8 分钟；边界状态由下一个周期包记录。正常退出和 SIGTERM
最终保存仍保留，不计入常规周期。
前 2 小时保留原生 physics-material event，但将其固定为 `[1.0,1.0]`，因此没有实际物理
随机化；2 小时后只应用 friction `[0.6,1.2]`。base mass、push、COM、执行器和强深度
增强保持关闭。

父 tracking reward 与 S0 action/latent anchor `0.35/0.10` 保持。新增三个归一化轻量
penalty，权重均为 `-0.05`：max continuous air time、contact duty symmetry、contact
participation。逐腿 worker probe 分别记录 FL/FR/RL/RR 的 contact count、duty factor、
mean/max air time、step frequency、slip distance 与 swing height。

## 6. Checkpoint 与保存

schema 1 父包在内存中迁移到 `kaiwu_train_v1/schema_version=2`。schema 2 同时保存低层、
adapter-only 高层组件、双 optimizer/scheduler/RNG、独立 iteration/env/gradient counters、
已完成 response records、command/feedback contract digest 和 low-level state digest。未完成
future history 不跨进程恢复，防止新任务 reset 与旧任务尾部拼接。缺 scheduler/RNG 等训练
状态时明确记录 `warm_start`；完整包标记为
`weights_optim_rng_resume_with_history_reset`，不宣称环境状态 bit-exact resume。

首存约 2 分钟，之后每 10 分钟调用无参数 `agent.save_model()`；30/75/120/420/470 分钟
额外保存。写盘使用同目录临时文件加 `os.replace`，失败不替换上一份有效包，60 秒后重试；
iteration-cap 最终保存也会等待 60 秒再试一次。
阶段标签仅使用 `responsebase/responseexpand/responsefull/responsecalib`，ID 和 path 只由
平台注入，不生成别名。

Terrain 原生距离 curriculum 保持关闭，reset 使用静态 0-9 难度覆盖，并记录
terrain family×level×command family histogram。Standard 从 response 包继续训练必须显式
启用 `low_level_only_preload`；默认 loader 不会静默选择 response 包。
