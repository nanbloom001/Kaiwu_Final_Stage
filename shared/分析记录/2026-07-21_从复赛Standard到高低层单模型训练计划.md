# 从复赛 Standard 到高低层单模型的训练计划

> 制定日期：2026-07-21
> 起点：[`archive/代码存档/复赛_standard/ckpt/model.ckpt-10288.pkl`](../../archive/代码存档/复赛_standard/ckpt/model.ckpt-10288.pkl)
> 目标：形成一个 checkpoint/ONNX 内的“高层导航 + 低层视觉运控”模型
> 配套评估：[`2026-07-21_Sim2Real分层方案综合分析评估.md`](./2026-07-21_Sim2Real分层方案综合分析评估.md)

## 1. 计划目标

最终模型应同时完成：

- 低层：平地稳定、准确跟踪速度、零速停车、转弯、上下坡、上下楼梯；
- 高层：根据深度图和 UWB Goal 输出有界速度指令，避障、绕障、通过迷宫并到达目标；
- 部署：Actor 只使用真机合法可获得的深度、proprio、Goal 和 recurrent state；
- 提交：仿真和真机使用相同网络权重、相同输入语义和相同动作语义；
- 工程：最终导出一个模型图，外围 C++ 不替代模型执行主要导航决策。

最终运行结构为：

```text
HighLevelNav(depth, goal3, nav_state, last_command)
    → bounded_command[vx, vy, wz]

VisualLocomotion(depth, inject(proprio45[6:9], bounded_command), loco_state)
    → joint_action12
```

高层建议 5～10 Hz 更新，低层保持 50 Hz。高层两次更新之间保持上一条 command，外围再执行安全限幅和 slew limit。

## 2. 计划中的模型角色

为避免“教师、学生、低层、高层”混淆，统一使用以下名称：

| 名称 | 输入 | 输出 | 是否部署 |
|---|---|---|---|
| `T_flat_10288` | `proprio45 + height_scan256` | `joint12` | 否 |
| `T_priv_loco` | `height_scan256 → latent32`，再与 `proprio45` 拼接 | `joint12` | 否 |
| `S_visual_loco` | `depth + proprio45 + loco_state`，其中 `proprio45[6:9]=command3` | `joint12` | 是，最终低层 |
| `P_nav` | `depth + goal3 + last_command + nav_state` | `command3` | 是，最终高层 |
| `M_hier` | `P_nav + S_visual_loco` | `joint12` | 是，最终提交模型 |

`T_flat_10288` 和 `T_priv_loco` 都只存在于训练期。最终部署不需要 height scan，也不需要教师网络。

## 3. 不可绕过的总体原则

### 3.1 每阶段都必须有独立准入和退出门槛

不能只看训练 reward 或蒸馏 loss。每一阶段均需保存：

- 代码 commit；
- 父 checkpoint 文件名和 SHA256；
- 配置文件和配置 SHA256；
- 随机种子；
- 训练步数和墙钟时间；
- 固定评测集指标；
- 结论：通过、失败或仅供诊断；
- 下一阶段唯一允许使用的 checkpoint SHA256。

未达到退出门槛的 checkpoint 不得作为下一阶段“默认父模型”。

### 3.2 先做短验证，再做长训练

任何新阶段必须依次通过：

1. 配置和 checkpoint 静态检查；
2. 单环境/少环境前向与 reset 测试；
3. 小批量 overfit 或几十次更新测试；
4. 短训练观察 loss、reward、显存和吞吐；
5. 固定评测集；
6. 通过后才启动长训练。

### 3.3 所有数值门槛先冻结再开训

本文给出的绝对阈值是首轮工程门槛，不是官方评分线。Phase 0 完成后，可以基于 10288 的真实基线调整一次；调整后的评测脚本和阈值必须提交并冻结，不能在看到新模型结果后反复移动门槛。

### 3.4 不允许语义不明的 partial loading

网络结构变化时，只允许：

- 严格匹配加载；
- 有单元测试和书面映射说明的显式转换；
- 以旧模型为冻结教师进行蒸馏。

禁止以“权重张量成功切片、补零或没有报错”作为迁移成功证据。

## 4. 固定评测协议

在 Phase 0 建立并贯穿全程，至少包含以下集合。

### 4.1 低层命令评测集

建议首版命令网格：

- `vx`：`0.0, 0.15, 0.30, 0.50, 0.70 m/s`；
- `vy`：`-0.20, 0.0, 0.20 m/s`；
- `wz`：`-0.80, 0.0, 0.80 rad/s`；
- 单轴命令、组合命令、阶跃命令和回零命令均需覆盖；
- 每类地形至少 3 个固定 seed，每个 seed 至少 100 个 episode，短调试可缩小但正式验收不可缩小。

若真机安全范围或平台能力表明 `0.70 m/s` 不适合，Phase 0 后可降低上限；最终高层绝不能输出低层未经过训练和验收的命令。

### 4.2 低层地形评测集

- 平地；
- 上坡、下坡及坡顶/坡底连接；
- 上楼梯、下楼梯；
- 楼梯入口不同偏航角；
- 不同台阶高度、深度、宽度和摩擦；
- 混合地形；
- 相机噪声、旧帧、空洞和安装位姿扰动。

### 4.3 高层导航评测集

- 空旷平地不同方位 Goal；
- 单障碍、双障碍、窄通道；
- 必须上楼或上坡才能到达的 Goal；
- 死胡同、T 字路口和完整迷宫；
- 低频、噪声、跳变、短时丢失和延迟 Goal；
- 目标附近减速、进入停止半径和重新离开停止半径。

### 4.4 必须统一记录的指标

低层：

- `MAE(vx)`、`MAE(vy)`、`MAE(wz)`；
- 零速命令后 1.5 s 的平面速度；
- 摔倒率、超时率、各地形通过率；
- 机体 roll/pitch、角速度峰值；
- action rate、关节极限、足端碰撞；
- 深度扰动前后的成功率变化。

高层：

- 到达率、到达时间和路径长度比；
- 碰撞率、摔倒率、超时率；
- command 超界次数和变化率；
- 高层反复左右切换次数；
- Goal 航向误差和 S 型振荡指标；
- 不同 Goal 更新频率/噪声下的性能下降。

## 6. Gate 0：规则与接口冻结

### 目的

避免训练完成后才发现双子网络、外围 UWB 处理或 ONNX 接口不被允许。

### 必须完成

1. 向主办方确认一个提交模型内部包含两个子网络是否合规；
2. 确认真机 C++ 可执行的 UWB 过滤、停车和安全逻辑边界；
3. 确认仿真和真机允许的输入、recurrent state、模型 I/O 数量；
4. 冻结 `goal3`、深度、proprio、command 和 action 的语义；
5. 冻结高层/低层频率以及单图执行规则；
6. 定义传感器故障时模型和外围的 fail-safe 行为。

### 推荐首版契约

```text
depth:
  float32 [1, 180, 320, 1], normalized to [0, 1]

proprio:
  float32 [1, 45]

goal3:
  float32 [1, 3]
  [clip(local_x/10), clip(local_y/10), clip(planar_distance/20)]

nav_state:
  versioned recurrent state

loco_state:
  versioned recurrent state

output:
  command3, joint_action12, next_nav_state, next_loco_state
```

外围 `valid/age` 暂不进入模型；外围对无效/过期 UWB 执行保持、减速和停车。仿真在语义 Goal 层模拟 5 Hz 左右更新、噪声、延迟和丢失，无需复刻完整 UWB 协议。

### 退出标准

- 规则问题获得书面答复，或形成明确的保守解释和备选方案；
- [`shared/interfaces/server-deploy-contract.md`](../interfaces/server-deploy-contract.md) 有待实现版本草案；
- 训练和部署对每个字段、单位、坐标系、频率和归一化没有歧义；
- 评测脚本和阈值版本冻结。

### 未通过时

若双子网络单模型不被允许，停止 Phase 7 以后工作，回退到单体视觉 Track；若外围深度导航被明确允许且仿真可运行同等逻辑，则方案 B 可成为备选。

## 7. Phase 0：复现并审计 10288

### 目的

确认 `model.ckpt-10288.pkl` 是真实可用的起点，并建立后续所有相对指标的父基线。

### 输入与可复用内容

- [`复赛_standard`](../../archive/代码存档/复赛_standard/) 全套归档；
- `model.ckpt-10288.pkl`；
- 原始 `ActorCritic`、301/316 维观测与 Standard 地形/命令配置。

### 实施任务

1. 计算 checkpoint SHA256，验证键名和权重形状；
2. 在归档代码对应环境中严格加载，禁止 partial loading；
3. 使用固定命令/地形评测集运行至少 3 个 seed；
4. 单独评测零速、低速、转向、侧移、上/下楼和上/下坡；
5. 保存回报、速度误差、摔倒率、视频和失败分类；
6. 验证教师在仿真中的上楼能力，而不是尝试把 height scan 教师部署到真机。

### 产物

- `T_flat_10288` 基线清单；
- checkpoint 和配置哈希；
- 固定评测报告；
- 是否进入 Phase 1 的决策。

### 退出标准

- checkpoint 严格加载且无缺失关键键；
- 无 NaN/Inf，动作和观测维度完全匹配；
- 混合地形总体成功率建议不低于 90%；
- 上楼、下楼、上坡、下坡均有独立成功证据；
- 零速命令后 1.5 s 平面速度建议不高于 `0.08 m/s`；
- 命令网格不存在整段完全不响应的速度或转向区间。

若教师地形能力合格但绝对阈值略有偏差，可以进入 Phase 2，并在 Phase 3 统一修复；若教师存在系统性不上楼、无法转向或不响应零速，则进入 Phase 1。

## 8. Phase 1：条件式扁平教师修复

### 目的

只修复会污染后续监督的根本缺陷，不为了追求更高仿真榜分数无限训练旧架构。

### 触发条件

满足任一项才执行：

- 10288 在仿真中不能稳定上下楼/坡；
- 零速、低速或转向指令基本不被执行；
- 命令训练分布缺失最终低层所需区域；
- 教师摔倒率过高，动作监督不安全。

### 实施任务

1. 从 10288 小学习率继续 PPO；
2. 增加零速和低速的显式采样比例；
3. 使用速度阶跃与回零命令；
4. 加强 `vx/vy/wz` 跟踪奖励，而不是只奖励快速前进；
5. 保留上下楼/坡能力，防止速度训练引发灾难性遗忘；
6. 参考 `archived/st7-opt4-angular-rate` 的角速度安全项和 `st7-opt2a-baseline-rewrite` 的倾角保护，但只移植经消融验证的部分。

### 退出标准

- 满足 Phase 0 教师准入门槛；
- 相对原 10288，关键地形成功率下降不超过 2 个百分点；
- 速度跟踪、停车或转向至少一项有统计显著改善；
- 不因为追求低误差而学成僵硬小步或拒绝高难地形。

### 停止条件

若两轮有边界的修复仍无法同时保留地形能力和命令跟踪，不再继续旧扁平网络；Phase 2 仍可用 10288 做初始化监督，Phase 3 从新的 `ActorCriticEncoder` 重新 PPO 学习。

## 9. Phase 2：10288 → 特权 latent32 行为蒸馏

### 目的

把扁平教师的关节行为迁移到当前 LBC 能消费的模块化结构：

```text
T_flat_10288(proprio45 + scan256) → teacher_action12

T_priv_loco:
  scan256 → encoder → latent32
  proprio45 + latent32 → actor → student_action12
```

本阶段的 `latent32` 没有独立标签。它通过最终动作 MSE 和闭环任务约束被间接学习，这就是“没有 latent 监督”的准确含义。

### 当前可复用实现

- [`algorithm_behavior_distill.py`](../../server/agent_ppo/algorithm/algorithm_behavior_distill.py)：已有 flat teacher → `ActorCriticEncoder` 的 action MSE；
- [`behavior_distill_workflow.py`](../../server/agent_ppo/workflow/behavior_distill_workflow.py)：已有教师/学生驱动框架；
- [`train_env_conf_standard_standard_ref_distill.toml`](../../server/agent_ppo/conf/train_env_conf_standard_standard_ref_distill.toml)：已有初始配置；
- [`决赛_track蒸馏_162404/agent_ppo/agent.py`](../../archive/代码存档/决赛_track蒸馏_162404/agent_ppo/agent.py)：历史上接通过的分发和加载蓝图。

### 必须先修复的代码 Gap

1. 新增明确的 `StandardBehaviorDistillConfig`；
2. Agent 增加 `is_behavior_distill` 与独立初始化分支；
3. 训练 workflow 能按 Stage 正确分发；
4. teacher loader 从当前 `strict=False` 改为严格 schema 检查：flat 301/316/12、预期键集合和每个权重 shape 必须同时匹配，不再静默忽略 unexpected keys；
5. behavior algorithm 和 Agent 的保存入口都改为统一 checkpoint schema，保存 `format`、网络维度、父 checkpoint SHA、迭代数、模型和 optimizer 状态；
6. 输出键必须能被现有 LBC 严格拆成 `encoder.*` 与 `actor.*`；
7. 把当前全局布尔 `student_drive` 改成显式的阶段比例调度，并支持逐环境 drive mask；
8. 增加 checkpoint round-trip、resume、旧裸 state_dict 兼容转换和错误结构拒绝测试。

以上 8 项全部通过短测试前，Phase 2 训练不得启动；当前仓库中的 behavior-distill 文件不能被视为已经可运行的完整路线。

### 训练步骤

1. **教师驱动预热**：环境完全由 10288 驱动，学生学习动作；
2. **混合驱动 DAgger**：学生驱动比例逐步增加，例如 0% → 25% → 50% → 75%；
3. **学生闭环阶段**：最终 100% 学生驱动，在学生访问状态上查询教师动作；
4. 对楼梯入口、登阶中段、下降中段、快速转向和回零状态提高采样权重；
5. 保持教师冻结，并在训练过程中检查其参数 hash 不变。

### 产物

- `model.ckpt-standard-bottleneck-bc-<id>.pkl`；
- 结构和血缘元数据；
- 教师/学生动作一致性报告；
- 闭环地形评测报告。

### 退出标准

建议首轮门槛：

- `action_cosine ≥ 0.98`；
- 在冻结的 held-out episode 集上，按动作维分别计算 `MSE_i / max(Var(teacher_action_i), 1e-6)`，再对 12 维取均值，结果 `≤ 0.10`；接近常量的动作维同时单独报告绝对 MSE；
- 最终阶段 100% 学生驱动；
- 闭环混合地形成功率达到父教师的 95% 以上；
- 摔倒率相对教师增加不超过 1 个百分点；
- checkpoint 可被当前 LBC loader 严格加载；
- 教师参数训练前后逐字节一致。

### 失败与回退

- 监督 loss 好但闭环差：增加 DAgger 和困难状态重采样，不直接进入 Phase 3；
- 结构瓶颈明显：允许重新训练 `ActorCriticEncoder`，但不要把 10288 权重机械切片进去；
- 两轮有界实验后仍无法达到父教师 90%：启动备选路线——从头 PPO 训练新的特权 `ActorCriticEncoder`，10288 仅用于早期 action regularization。

## 10. Phase 3：特权瓶颈教师 PPO 恢复与命令覆盖

### 目的

消除行为蒸馏误差，使 `T_priv_loco` 成为真正成熟的 Standard 教师，并建立最终高层可用的速度包络。

### 实施任务

1. 从 Phase 2 最佳 checkpoint 启动 Standard PPO；
2. Actor 使用 `proprio45 + height_scan256`，Critic 可使用训练期特权状态；
3. 命令采样必须覆盖零速、低速、常用前进、侧移、正反转向和组合命令；
4. 增加 command step、hold 和回零序列，而不是只随机恒速；
5. 地形 curriculum 从平地/坡地扩展到楼梯和混合地形；
6. 加入质量、质心、摩擦、执行器增益、动作延迟、控制周期抖动、外部推力等逐步随机化；
7. 监控 speed tracking 与地形通过率的 Pareto 关系，禁止只追求快速通过；
8. 对 timeout/truncated 语义复用 `archived/timeout-bootstrap-diag` 的诊断测试。

### 建议首轮退出标准

命令能力：

- 零速命令后 1.5 s 平面速度 `≤ 0.05～0.08 m/s`；
- `MAE(vx) ≤ 0.10 m/s`；
- `MAE(vy) ≤ 0.08 m/s`；
- `MAE(wz) ≤ 0.15 rad/s`；
- 命令阶跃后不持续大幅过冲或振荡。

地形能力：

- 平地和坡地成功率 `≥ 95%`；
- 上楼和下楼成功率分别 `≥ 90%`；
- 固定评测集摔倒率 `≤ 1%`；
- 综合能力不低于 10288 基线的 95%；
- 速度指令分布和成功率共同定义一个版本化的“低层允许命令包络”。

### 产物

- `model.ckpt-standard-privileged-teacher-<id>.pkl`；
- 命令包络表；
- domain randomization 参数表；
- Phase 4 唯一允许使用的教师 SHA256。

## 11. Phase 4：特权 Standard → 深度 Standard 的 D2 视觉蒸馏

### 目的

用合法深度相机输入替换教师的 `height_scan256`，保留低层地形与速度跟踪能力。

### 可复用内容

- 当前 `main` 的 D2：action-aware loss、逐环境 DAgger、TBPTT 16；
- `st9-opt3-d1-vision-distill`：D1 作为对照、深度 block dropout 和 Goal 噪声实现思路；
- [`VisionEncoder`](../../server/agent_ppo/model/vision_encoder.py)；
- D435i `180×320×1` 部署预处理契约。

### 必须调整

1. 新建 Standard D2 Stage，`goal_dim=0`；
2. 教师为 Phase 3 的 `T_priv_loco`；
3. 学生输入的 `proprio45[6:9]` 必须写入低层 command3，不额外拼接第二份 command；
4. 不允许 Goal 进入低层；
5. 相机外参必须使用最终标定值；
6. 训练和评估时的 depth augmentation 开关必须明确，不能评估时仍随机增强；
7. LSTM reset、mask、TBPTT 边界和 batch 维度必须有测试。

### 损失与驱动建议

```text
L = 0.5 * SmoothL1(student_latent, teacher_latent)
  + 0.1 * (1 - cosine_similarity)
  + 1.0 * SmoothL1(student_raw_action, teacher_raw_action)
```

以上沿用 D2 初值，正式长跑前必须用短实验验证梯度尺度。训练分为：

- 教师驱动预热；
- 50% 学生驱动；
- 75% 学生驱动；
- 100% 学生驱动。

只优化视觉学生，教师 encoder/Actor 必须冻结。

### 深度随机化

- 空洞和 block dropout；
- 深度量化、加性/乘性噪声；
- 少量旧帧和短时重复帧；
- 近远量程裁剪；
- 内参微扰和相机外参小范围扰动；
- 不同材质导致的局部失效；
- 训练后期加入真机深度日志离线回放。

### 退出标准

- 最终 100% 学生闭环驱动；
- `latent_cosine ≥ 0.95`；
- 在同一冻结 held-out 集上，按动作维计算 `MSE_i / max(Var(teacher_action_i), 1e-6)` 后取 12 维均值，结果 `≤ 0.10`，并单独报告接近常量动作维的绝对 MSE；
- 干净深度下综合成功率达到特权教师的 90%～95%；
- 单项楼梯/坡地成功率相对教师下降不超过 10 个百分点；
- 规定深度扰动集下成功率下降不超过 10 个百分点；
- 空白/常量深度消融应显著降低复杂地形能力，证明模型确实使用深度，而不是只凭 proprio 和固定步态；
- recurrent state reset 后结果可复现，长序列无 NaN/Inf。

### 失败与回退

- latent 好、动作差：检查 Actor 输入排列和 action scale；
- 动作 loss 好、楼梯闭环差：增加学生驱动、楼梯中段采样和时序训练；
- 干净仿真好、真机日志差：先修深度预处理/标定和随机化，不立即修改运控奖励。

## 12. Phase 5：视觉学生 PPO 后训练

### 目的

让学生在真实的视觉闭环状态分布中超过“只会模仿教师”的限制，并最终脱离教师独立训练。

### 必须新增的训练能力

1. recurrent visual Actor PPO；
2. Actor 只使用合法输入：depth、proprio、command、历史状态；
3. Critic 可使用 height scan、真实速度和其他训练期特权状态；
4. rollout 正确保存 LSTM 状态、done mask 和序列边界；
5. PPO minibatch 按序列采样，不得把 LSTM 当无状态 MLP 打乱；
6. 允许从 Phase 4 学生 checkpoint 严格恢复；
7. 导出时完全移除训练期 Critic 和教师依赖。

### 稳定训练顺序

1. 初期冻结视觉 CNN，只更新后部 LSTM/Actor 或使用极小学习率；
2. 保留冻结教师的动作正则：`L_total = L_PPO + λ L_teacher`；
3. `λ` 随训练逐步退火到 0；
4. 再小学习率解冻视觉 encoder；
5. 只有固定评测集不退化时才扩大 domain randomization。

### 退出标准

- 不加载教师也能完整训练、评估和导出；
- 合法 Actor 观测审计通过，height scan 只进入 Critic；
- 至少一项关键指标相对 Phase 4 有改善：命令跟踪、深度扰动鲁棒性或地形成功率；
- 任一核心地形成功率下降不超过 2 个百分点；
- 摔倒率不增加超过 0.5 个百分点；
- 教师正则最终可退火到 0，模型不发生能力崩塌；
- 训练中断和 resume 后 recurrent state/optimizer 行为一致。

### 产物

- `model.ckpt-standard-visual-ppo-<id>.pkl`；
- 合法观测审计表；
- Phase 4 与 Phase 5 的同集对比报告。

## 13. Phase 6：低层冻结与部署资格验收

### 目的

在训练高层之前，把低层当作稳定执行器验收并冻结。高层只能输出低层已证明能够执行的 command。

### 仿真验收

- 完整命令网格和混合地形通过 Phase 3/5 门槛；
- 深度噪声、动力学随机化和相机外参扰动通过；
- command 永不在模型内部被 Goal 或特权 terrain gate 改写；
- 固定 command 下能独立上下楼和坡；
- 零速、低速、转弯和停止可控。

### 真机分级验收

1. 离线真实深度回放；
2. 吊起/支架状态，command 为零；
3. 平地 `0.10～0.15 m/s`；
4. 平地低速转向和回零；
5. 逐步增加到训练覆盖速度；
6. 缓坡；
7. 低台阶；
8. 正式楼梯。

每级必须有独立人工急停、深度 stale watchdog、姿态/关节/动作限制。不得因低速表现不佳就直接提高真机速度；应回到训练覆盖低速分布。

### 退出标准

- 形成版本化低层 command 包络；
- 真机能稳定执行零速、前进、侧移和转向；
- 低风险地形测试无不可解释摔倒；
- ONNX 多帧结果与 Python 一致；
- 低层 checkpoint 和导出物 SHA256 固定；
- 后续 Phase 7/8 默认冻结全部低层参数。

## 14. Phase 7：实现并训练高层导航策略

### 目的

学习从深度和相对 Goal 生成低层可执行的 command3，而不再直接输出关节动作。

### 推荐网络

```text
depth → HighLevelCNN → visual_nav_feature
goal3 → GoalMLP → goal_feature
last_command + proprio_summary → state_feature

concat → GRU/LSTM → command_head → tanh → command envelope
```

首版使用独立高层视觉编码器，不与低层共享权重。输出通过连续可微映射限制在 Phase 6 包络内。

### 训练结构

- 冻结 `S_visual_loco`；
- 每 5～10 个仿真 Hz 更新高层，低层保持 50 Hz；
- 高层 Actor 使用 depth、goal3、历史 command 和记忆；
- 高层 Critic 可使用真实目标位置、地图/地形标签、碰撞和特权几何；
- Critic 特权信息不能进入 Actor 或导出模型输入；
- 初期不使用旧 Track 动作教师，直接 PPO 学习 command3。

### Goal 训练适配

仿真不重建 UWB 原始协议，而是在 `local_goal_xy` 层统一处理：

```text
Sim true goal → robot-frame local XY
             → sample/hold + noise + bias + delay + dropout
             → shared GoalEncoder
             → goal3
```

真机则是：

```text
UWB raw → calibration/filter/stale handling → robot-frame local XY
        → same GoalEncoder → goal3
```

### 初始课程

1. 空旷平地、目标在前方；
2. 空旷平地、目标覆盖 360°；
3. 单障碍绕行；
4. 双障碍和窄通道；
5. 必须经过坡地/楼梯；
6. 简单路口和短死胡同；
7. 完整迷宫。

### 奖励原则

- 目标距离进度；
- 到达奖励；
- 碰撞、摔倒和超时惩罚；
- command 平滑和超包络惩罚；
- 朝向目标奖励不应压倒必要绕障；
- 楼梯/坡地的通过奖励与高障碍绕行奖励分开统计；
- 不直接奖励“越快越好”，避免重现旧 Track 的高速过拟合。

### 初始退出标准

- 空旷平地任意方向 Goal 到达率 `≥ 95%`；
- 基础障碍课程到达率 `≥ 90%`；
- 所有 command 处于低层包络内，超界次数为 0；
- command 变化率满足部署 slew limit；
- 低层地形能力相对 Phase 6 不下降；
- Goal 5 Hz sample-and-hold 下性能相对理想连续 Goal 下降不超过 10 个百分点；
- 坐标旋转、左右 Goal、前后 Goal 的单元测试全部通过。

## 15. Phase 8：迷宫、楼梯语义与 hard-start 强化

### 目的

解决高层把台阶当障碍、只会标准入口、进入死胡同无法回退以及榜单地形过拟合。

### 可复用 Tag

- `st7-opt5-debug-hard-start-diagnostics`：先复用 reset 高度 raycast、入口速度索引和诊断测试；
- `st7-opt5b-conservative-hard-start-replay`：基础课程通过后复用保守 hard-start 分布；
- `st7-opt3-server-baseline`：Goal 噪声和 Track 成功指标；
- `archived/st7-opt4-angular-rate`：姿态/角速度安全项；
- 旧 J5/J6/J7 与 near-goal rejected 只用作失败记录，不重新合入活动配置。

### hard-start 使用顺序

1. 先证明普通 reset 下高层会完成对应地形；
2. 运行 debug-only reset 诊断，确认 spawn 高度、方向、速度和地形标签；
3. 低比例加入反向楼梯、反向坡地和迷宫中段；
4. 逐步提高困难状态比例，不从第一轮就让 hard-start 主导分布；
5. 始终保留从正常起点完整完成任务的 episode。

Opt5B 历史建议比例可作为起点：hard-start 占总采样约 25%，其中反向楼梯 55%、反向坡地 30%、迷宫 15%。该比例未经新架构验证，必须做消融，不得视为最终参数。

### 台阶语义专项实验

建立成对场景：

- 可通行楼梯 vs 同深度轮廓的高墙；
- 缓坡 vs 实体斜障碍；
- 台阶入口对准 vs 斜向接近；
- 目标在楼梯后方 vs 目标要求绕开障碍。

每次失败记录：深度帧、goal3、高层 hidden、command3、实际速度、低层 action、碰撞和终止原因。对楼梯接近/登阶样本增加采样权重，但不能把高层训练成见到任何竖直边缘都直冲。

### 退出标准

- 上下楼导航完成率分别 `≥ 90%`；
- 坡地导航完成率 `≥ 95%`；
- 固定迷宫集到达率首轮目标 `≥ 80%`；
- hard-start 评测通过率相对普通入口差距不超过 15 个百分点；
- 增加楼梯正样本后，墙体碰撞率不显著上升；
- 不出现持续左右摆动、原地高速转向或死胡同永久振荡；
- 至少 3 个未参与训练生成参数的地形 seed 保持通过。

## 16. Phase 9：单模型集成与有限联合微调

### 目的

把已验收的高层和低层组合为一个最终网络图，解决频率、状态和命令传递问题，而不破坏低层安全性。

### 集成顺序

1. 先只组合前向图，保持两层参数全部冻结；
2. 验证高层 command 与低层实际输入逐帧一致；
3. 验证 high-level tick、sample-and-hold 和 recurrent state reset；
4. 在完整 Track 环境评估组合模型；
5. 如有必要，只微调高层；
6. 只有高层无法适配且低层有明确余量时，才解冻低层最后少量层，并使用 Phase 6 策略锚定；
7. 任一低层核心指标退化即回滚到冻结低层版本。

### 频率实现方案

推荐在模型契约中显式提供 `nav_update_mask`，或对现有预留字段做版本化定义：

- mask=1：更新高层 recurrent state 和 command；
- mask=0：保持上一高层 command/state；
- 低层每 20 ms 都运行；
- 高层按 100～200 ms 运行一次。

若平台不允许条件更新，首版可让高层也以 50 Hz 运行，但训练和部署必须一致，并对输出做低通/限速。不能仿真用 10 Hz、真机未经说明改为 50 Hz。

### 退出标准

- 一个 checkpoint 包含两层权重和完整结构元数据；
- 不存在运行时 height scan 输入；
- 同一图在仿真和部署 wrapper 中输出一致；
- 组合后低层命令跟踪和地形成功率相对 Phase 6 下降不超过 2 个百分点；
- 高层到达率相对 Phase 8 下降不超过 2 个百分点；
- recurrent state 在 episode reset、急停复位和模型重启时全部清零；
- command 传递没有一帧错位、旧值污染或维度复用歧义。

## 17. Phase 10：导出与最终 Sim2Real 验收

### 目的

形成可复现、可回滚、可在 Jetson 安全运行的唯一发布制品。

### 导出要求

- 单个 ONNX 图；
- opset、输入输出名、shape 和 dtype 固定；
- 包含高层/低层 recurrent state；
- 不导出 Critic、教师 encoder 或特权输入；
- checkpoint、ONNX、部署配置和二进制均记录 SHA256；
- Python wrapper 与 ONNX Runtime 进行至少多帧 recurrent 对齐验证；
- 最大绝对误差建议 `≤ 1e-4`；
- Jetson 单低层周期满足 20 ms 实时预算并保留安全余量。

### 部署适配

当前默认部署路线 [`deploy/sim2real_test_loco`](../../deploy/sim2real_test_loco/) 已有 8 入/8 出和高低层状态端口外壳，但当前 `nav_h/nav_c` 主要透传、`cmd` 未形成真实高层闭环。需要：

1. 版本化新的高层 command 和 state 语义；
2. 实现高层调度与 command hold；
3. UWB raw → local XY → goal3 的统一 adapter；
4. 添加 UWB stale、深度 stale、NaN 和 inference timeout watchdog；
5. 禁止 RealSense 不可用时静默使用常量深度进入正式运行；
6. `ARTIFACTS.md` 记录 checkpoint、ONNX、运行库、二进制和验证状态。

### 最终验证阶梯

1. Python 离线固定输入；
2. Python vs ONNX 多帧对齐；
3. 仿真完整赛道固定 seed；
4. 仿真未见地形和传感器扰动；
5. 真机深度/UWB 日志离线回放；
6. Jetson `--check`/preflight；
7. 吊起状态零速；
8. 平地低速、转向、回零；
9. 平地 UWB Goal；
10. 坡地和低台阶；
11. 正式楼梯；
12. 障碍与迷宫；
13. 完整比赛路线。

### 最终发布标准

模型契约：

- 仿真和真机使用同一 checkpoint/ONNX SHA256；
- Actor 输入只来自合法传感器和模型状态；
- Goal、深度、proprio、command、action 的顺序/单位/归一化完全一致；
- 单模型内两层运行频率和状态更新有明确测试。

能力：

- 平地、坡地、上下楼和基础避障达到各阶段冻结门槛；
- 固定迷宫集到达率达到 Phase 8 门槛；
- UWB 低频、噪声、短丢失条件下仍能到达且不持续 S 型振荡；
- 到点进入停止半径后可靠停车，不因抖动反复启动；
- 全流程无 NaN、输出超界、state 污染和 watchdog 缺失。

工程：

- 所有制品有来源和 SHA256；
- 部署 preflight 通过；
- 有真机验证记录、失败案例和人工急停流程；
- 可从发布 Tag 和制品清单完整恢复；
- 回滚仅需切回上一组 checkpoint/ONNX/config，不依赖未记录的机载手改。

## 18. 消融实验优先级

以下实验应小规模并行比较，但不得同时改变多个变量：

1. Phase 2：纯教师驱动 BC vs DAgger；
2. Phase 4：D1 loss vs D2 loss；
3. Phase 4：无 TBPTT vs TBPTT 16；
4. Phase 5：纯 PPO vs 教师正则退火；
5. Phase 7：连续 Goal vs 5 Hz sample-and-hold Goal；
6. Phase 7：`goal3` vs 可选 `goal3 + valid/age`，只在外围处理失败后开展；
7. Phase 8：无 hard-start vs Opt5B 保守 hard-start；
8. Phase 9：独立视觉编码器 vs 共享 backbone，仅在部署算力成为瓶颈时开展。

每个消融只比较同一父 checkpoint、同一 seed、同一训练预算和同一评测集。

## 19. 明确不采用的捷径

- 不把 10288 权重切片后直接声称迁移到 Actor77；
- 不把训练期 height scan 或 terrain gate 间接写入部署 Actor 的 command；
- 不因为教师无法真机读取 height scan 就否定其训练价值；
- 不把旧 Track 关节动作教师强行当成新高层 command 教师；
- 不在 D2 loss 尚未闭环验收时直接进行昂贵长跑；
- 不在低层尚未能停、能转、能跟踪低速时训练高层；
- 不让高层输出超出低层训练包络的速度；
- 不用外围 C++ 的完整规划器掩盖模型没有导航能力，除非主办方明确允许且仿真端使用同等逻辑；
- 不把 Tag 存在等同于模型制品可用；
- 不跳过 Python→ONNX→Jetson 的多帧一致性验证。

## 20. 推荐实施顺序与停止闸门

### 第一里程碑：得到合格特权低层教师

完成 Phase 0～3。
若 `T_priv_loco` 无法达到 10288 的 95%，暂停视觉训练，先解决结构桥接或从头 PPO。

### 第二里程碑：得到可独立部署的视觉 Standard

完成 Phase 4～6。
若真实深度回放或低速真机平地失败，暂停高层训练，先修 observation contract、相机标定或视觉 PPO。

### 第三里程碑：得到仿真高层导航

完成 Phase 7～8。
若高层频繁要求低层包络外动作，不扩大真机速度，而是修奖励、课程或低层训练覆盖。
