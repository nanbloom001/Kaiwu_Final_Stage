# 智能体详述

> Source: https://tencentarena.com/docs/p-competition-legged_robot_competition_26/27.0.21/guidebook/dev-guide/agent/

我们在代码包中提供了智能体的简单实现，本文将对该部分内容进行讲解，包括两阶段训练流程、观测处理、算法与网络结构、LBC 视觉蒸馏等。

## 两阶段训练流程

为了让策略脱离仿真特权观测、能在真机上依赖机载深度相机运行，采用两阶段训练 + 教师-学生蒸馏：

| 阶段 | 名称 | 算法 | 输入 | 产物 | 说明 |
| --- | --- | --- | --- | --- | --- |
| Stage 1 | locomotion | PPO | height_scan 特权观测 | model.ckpt-locomotion-{id}.pkl | 训练运控教师：scan→encoder→latent(32)，actor 吃 proprio+latent |
| Stage 2 | lbc_loco | LBC（监督） | 深度相机图像 | model.ckpt-lbc-loco-{id}.pkl | 冻结教师，训练视觉学生（CNN+LSTM）从深度图回归教师 latent（MSE） |

- 部署 / 评估时，用视觉学生的 latent 替代 `height_scan` 的 latent，再送入教师 Actor 解码为关节动作——真机没有 `height_scan`，只有深度相机。
- 阶段通过 `agent_ppo/conf/conf.py` 的 `StageConfig` 子类选择；评估时框架会按 TOML 的 `env_conf.task_name` 自动推断阶段（含 `Camera` → `lbc_loco`，否则 → `locomotion`）。

## 观测处理

环境返回的 `observation` 信息包含了针对智能体的局部观测，可以在 `PolicyObservationProcess` 中进行处理。代码包默认直接透传 `self.default_observation()` 返回的 301 维张量，选手可在此基础上做特征工程（归一化、聚合、拼接额外特征等）：

```
class PolicyObservationProcess(ObservationProcess):
    target_group = "policy"

    def process(self):
        obs = self.default_observation()
        # TODO (track 地形)：可按需从 env.goal_positions / env.goal_yaw
        # 或 env.scene.sensors["nav_scanner"] 构造特征并拼接到 obs。
        return obs
```

观测数据布局：

| 区间 | 维度 | 含义 | 来源 |
| --- | --- | --- | --- |
| [0:3] | 3 | base_ang_vel，机体角速度，scale=0.25 | Isaac Lab mdp |
| [3:6] | 3 | projected_gravity，重力方向投影 | Isaac Lab mdp |
| [6:9] | 3 | velocity_commands，速度命令 (vx, vy, wz) | command manager |
| [9:21] | 12 | joint_pos_rel，关节相对默认位置 | robot data |
| [21:33] | 12 | joint_vel_rel，关节速度，scale=0.05 | robot data |
| [33:45] | 12 | last_action，上一帧动作 | action manager |
| [45:301] | 256 | height_scan，16×16 前方高度扫描 | height_scanner |

> Track 地形扩展：环境额外提供 env.goal_positions（出口位置）、env.goal_yaw（出口朝向）和 env.scene.sensors["nav_scanner"]（前瞻遮挡扫描）。

代码包提供三个观测处理器（均继承 `ObservationProcess`）：

| 处理器 | target_group | 阶段 | 输出布局 |
| --- | --- | --- | --- |
| PolicyObservationProcess | policy | locomotion | `[proprio(45) |
| CriticObservationProcess | critic | locomotion | `[critic_proprio(60) |
| LBCObservationProcess | policy | lbc_loco | `[proprio(45) |

`LBCObservationProcess` 在默认观测尾部拼接深度图，供蒸馏阶段切分：

```
class LBCObservationProcess(ObservationProcess):
    target_group = "policy"

    def process(self):
        # default_observation() = [proprio | height_scan]
        obs = self.default_observation()
        depth = nav_observation_utils.depth_camera_image(self.env)   # (N, 57600)
        return self.concatenate_terms(obs, depth)
```

> depth_camera_image 从 env.scene.sensors["depth_camera"] 读取深度图，归一化到 [0, 1] 并施加 sim2real 增强（像素 dropout / 高斯噪声 / roll·pitch 抖动，仅训练时启用）。切分逻辑由 AlgorithmLBC._split_obs 按 proprio_dim(45) / scan_dim(256) / depth 三段完成。

### 特征处理

当前代码包中 `PolicyObservationProcess` 直接使用 `default_observation()` 返回的原始观测，未做额外特征工程处理。

```
def process(self):
    obs = self.default_observation()
    return obs
```

选手可以在此基础上进行特征工程扩展。

### 奖励处理

代码包在 `reward_process.py` 中提供了一个示例奖励函数：

奖励说明：

| 奖励名称 | 作用 | 类型 |
| --- | --- | --- |
| _reward_termination | 惩罚真实失败（terminated ∧ ¬time_out），返回 1.0；在 TOML 中以 [rewards.termination] weight = -200.0 激活 | sparse |

其余通用 locomotion 奖励（`track_lin_vel_xy` / `joint_acc` / `action_rate` / `flat_orientation` 等）继承自 `RewardProcessBase`，在 TOML 配置中激活 `[rewards.<name>]` 即可，无需重复实现。选手若需训练导航策略，请在 `reward_process.py` 自行添加更多奖励函数。

## 算法介绍

决赛采用非对称 Actor-Critic + 地形编码器的 `ActorCriticEncoder`，为 LBC 视觉蒸馏做准备。

| 算法 | 文件路径 | 说明 |
| --- | --- | --- |
| PPO + ActorCriticEncoder | model/actor_critic_encoder.py | Actor 始终经 encoder；Critic 可选独立 encoder |
| LBC（监督蒸馏） | algorithm/algorithm_lbc.py | 教师-学生 latent 蒸馏（MSE） |

### ActorCriticEncoder 网络结构

与扁平 MLP 不同，决赛把 256 维 `height_scan` 先经 `encoder` 压缩为 32 维 latent，再与本体感知拼接后进入 Actor：

- Actor 路径：`scan(256) → encoder → latent(32)`，`actor` 输入 = `proprio(45) + latent(32)` = 77 维 → MLP `[512, 256, 128]` → 12 维动作。
- Critic 路径（`critic_use_encoder = True`，locomotion 阶段采用）：`critic` 用独立的 `critic_encoder`（与 actor encoder 参数分离），输入 = `critic_proprio(60) + critic_encoder(scan)(32)` = 92 维 → MLP `[512, 256, 128]` → 1 维价值。

| 组件 | 输入维度 | 隐藏层 | 输出维度 | 说明 |
| --- | --- | --- | --- | --- |
| encoder（scan→latent） | 256 | [512, 256] | 32 | 末尾 L2Norm，与蒸馏教师 encoder 结构一致 |
| Actor | 77（proprio+latent） | [512, 256, 128] | 12 | ELU 激活 |
| Critic | 92（critic_proprio+latent） | [512, 256, 128] | 1 | ELU 激活 |

> encoder 末尾的 L2 归一化使 latent 落在单位球上，是教师 Actor 的输入分布假设，也是学生视觉编码器需要对齐的目标。

### 训练超参数（locomotion）

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| lr | 3e-4 | 学习率 |
| num_learning_epochs | 5 | 每次更新的 epoch 数 |
| num_mini_batches | 4 | mini-batch 数量 |
| num_steps_per_env | 48 | 每个环境采集步数 |
| latent_dim | 32 | encoder 输出 latent 维度 |
| model_save_interval | 500 | 模型保存间隔（迭代次数） |

## LBC 视觉蒸馏（Stage 2）

`lbc_loco` 阶段是纯监督学习（非 RL）：冻结的运控教师驱动环境，视觉学生从深度图学习复现教师的 latent。

### 网络组成

| 角色 | 网络 | 输入 → 输出 | 状态 |
| --- | --- | --- | --- |
| 教师 encoder | DmEncoder（MLP [512,256]→32 + L2Norm） | height_scan(256) → latent(32) | 冻结（监督目标） |
| 教师 Actor | MLP [512,256,128] | proprio(45)+latent(32) → action(12) | 冻结（latent→关节解码器，真机仍需要） |
| 学生 | VisionEncoder（CNN + LSTM + L2Norm） | depth(180×320)+proprio(45) → latent(32) | 可训练 |

- CNN（`SimpleCNN`）：`180×320×1` 深度图 → 32 维特征，压缩比约 1800:1（也可切换 `ResNetEncoder`）。
- LSTM：输入 `cat(cnn_feat(32), proprio(45))`，2 层、hidden=64 → Linear(64→32) → L2Norm 得学生 latent。

### 损失与训练

```
teacher_latent = teacher_encoder(height_scan)      # 冻结
student_latent = vision_encoder(depth, proprio)    # 可训练
loss = MSE(student_latent, teacher_latent)         # 仅优化 vision_encoder
```

由于两侧 latent 均 L2 归一化，`mse ≡ 2(1-cos)`，真正可读的收敛指标是两 latent 的夹角 `angle_deg`（越小越贴合）。

教师权重来自 Stage 1 的 locomotion ckpt：`AlgorithmLBC.load_teacher_from_locomotion_ckpt` 按 key 前缀拆分——`encoder.*` → 教师 encoder，`actor.*` → 教师 Actor，`critic.*` / `log_std` 丢弃。

### StageConfig 阶段系统

阶段由 `agent_ppo/conf/conf.py` 中的 `StageConfig` 子类定义，通过 `Config.CURRENT` 选择：

| 子类 | task_type | algorithm | ckpt 前缀 |
| --- | --- | --- | --- |
| LocomotionConfig | standard | ppo | model.ckpt-locomotion |
| LBCLocoConfig | standard | lbc_loco | model.ckpt-lbc-loco |
| CustomConfig | —（模板） | — | 选手自定义 track 导航阶段 |

> 若要新增 track 地形导航训练阶段，可参考 CustomConfig 模板：明确 stage 名称、task_type、动作语义与维度、obs 维度（是否拼接 goal）、训练超参，并在同目录创建 train_env_conf_<task_type>_<stage.name>.toml。

| 面板名称 | 指标 Key | 类型 | 说明 |
| --- | --- | --- | --- |

> 说明：以上为代码包 monitor_builder.py 中定义的自定义指标。其余通用 reward 指标（如速度跟踪、姿态、步态等）由 tools/conf/monitor_default.yaml 和 tools/conf/monitor_default_track.yaml 负责展示。

### LBC 蒸馏指标组（lbc_loco 阶段）

蒸馏阶段不产生 PPO loss，`lbc_workflow` 上报以下监督学习指标：

| 指标 Key | 说明 |
| --- | --- |
| angle_deg | 学生 / 教师 latent 夹角（度），核心收敛指标，越小越贴合 |
| cos_sim | 学生 / 教师 latent 余弦相似度 |
| mse_loss | 逐样本平方距离均值（蒸馏损失） |

| student_std / teacher_std | 学生 / 教师 latent 的 batch 标准差 |

## 模型保存限制策略

为了避免用户保存模型的频率过于频繁，开悟平台对模型保存会有安全限制，不同的任务会有不同的限制，限制规则详情如下：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| model_save_interval | 500 | 每 500 次训练迭代保存一次模型（lbc_loco 阶段为 1000 步） |

> 注意：选手可在 conf.py 中修改 model_save_interval 的值调整保存频率，但平台侧可能有额外的最小间隔限制。

不同阶段 ckpt 命名与内容不同：

| 阶段 | ckpt 文件名 | 内容 |
| --- | --- | --- |
| locomotion | model.ckpt-locomotion-{id}.pkl | ActorCriticEncoder 完整 state_dict（encoder + actor + critic） |
| lbc_loco | model.ckpt-lbc-loco-{id}.pkl | vision_encoder + teacher_actor（真机必需）+ teacher_encoder / optimizer（续训用） |

## 模型评估模式

用户可以在腾讯开悟平台上创建模型评估任务。创建任务时，可以对该任务的环境进行配置，配置信息如下：

```
[env]

# Number of parallel environments. When num_envs ≤ 16, the MP4 saving feature is enabled by default; when num_envs > 16, the MP4 saving feature is disabled by default.
num_envs = 16

# Episode length in seconds | 单回合时长(秒)
episode_length_s = 20.0

[env_conf]

# locomotion/hier_nav training uses the base "Unitree-Go2-Velocity" to avoid render OOM.
# Isaac Lab 任务入口。LBC 蒸馏需要 TiledCamera 深度相机 → 走带相机的任务变体
# locomotion/hier_nav 训练用基础 "Unitree-Go2-Velocity"，避免渲染 OOM
task_name = "Unitree-Go2-Velocity-Camera"

[terrain]
# Terrain mode: standard / track | 地形模式

# Difficulty levels to evaluate (0=easiest, 9=hardest)

# List of sub-terrains for Standard mode: each terrain type occupies a column, and each difficulty level occupies a row. Env assignments are prioritized row-by-row.
```

> 
> 评估时部分训练配置（如域随机化、观测噪声）默认关闭，以确保评估结果的一致性和可复现性。

> num_envs 配置小于等于 16 时会产出 mp4 视频用于可视化观察模型表现，大于 16 时将不会产出 mp4 视频。

### 评估阶段自动推断

评估时框架按 TOML 的 `env_conf.task_name` + `terrain.mode` 自动推断阶段，覆盖 `Config.CURRENT`：

| task_name | terrain.mode | 推断阶段 | 加载内容 |
| --- | --- | --- | --- |
| Unitree-Go2-Velocity | standard | locomotion | ActorCriticEncoder 完整权重 |
| Unitree-Go2-Velocity-Camera | standard | lbc_loco | 仅 vision_encoder + teacher_actor（模拟真机视角，不加载 teacher_encoder） |

> lbc_loco 评估时故意不加载 teacher_encoder——真机没有 height_scan，推理路径为 depth → vision_encoder → latent → teacher_actor → 关节动作，与真机部署完全一致。

### 评估可视化：第一视角深度图

- 当 `num_envs ≤ 16` 时，评估会为每只机器狗产出第三人称跟随视频（RGB）。
- 此外，当 `task_name` 含 `Camera`（即 `lbc_loco` 视觉阶段）时，额外产出机器人第一视角深度图视频 `depth_view_*.mp4`（例如 `depth_view_env_001.mp4`），与第三人称视频同目录共存。
- 深度图以灰度渲染：越近越亮、越远越暗，超出量程（> 5 m，与 D435i 实用量程 `max_depth = 5.0` 一致）的像素渲染为全黑。借助该视频可以直观观察视觉学生"看到"的地形，判断蒸馏效果与相机安装位姿是否合理。
